# v0.6 지식그래프 수동 스모크 — 실행 안내

`docs/SMOKE.md` 의 **실행 H**가 쓰는 코퍼스와 절차다. 코퍼스는 `corpus/` 에 있다.

> ⚠️ **`--out` 은 반드시 리포지토리 밖 임시 폴더를 쓴다.** 산출물이 리포지토리 안에 남으면
> 다음 `pytest` 에서 픽스처의 입력 문서로 다시 잡혀 통합테스트가 깨진다(2026-08-22 실측).
> 입력 코퍼스는 리포지토리 안에 두어도 안전하다 — 테스트는 `tests/fixtures/` 와 `tmp_path`
> 만 쓰고 `docs/` 를 읽지 않는다.

이 안내문(`docs/smoke/README.md`)은 `corpus/` **바깥**에 있어 스캔 대상이 아니다. 안에 두면
7번째 문서로 잡혀 기대 그래프가 어긋난다.

---

## 1. 준비

```bash
ollama serve                      # 다른 터미널에서
ollama list                       # qwen2.5:7b-instruct · nomic-embed-text 확인
corpbrain doctor                  # 준비 상태 점검
```

## 2. 실행

```bash
CORPUS=docs/smoke/corpus          # 리포지토리 안
OUT=$(mktemp -d)                  # 산출물은 반드시 리포지토리 밖

corpbrain scan "$CORPUS" --out "$OUT" --force-gates
corpbrain graph --out "$OUT" --stats
corpbrain graph --out "$OUT" --central
corpbrain graph --out "$OUT" --neighbors 인사/채용계획.md.md
corpbrain graph --out "$OUT" --neighbors 개발/README.md.md
corpbrain graph --out "$OUT" --neighbors 기타/메모.md.md
```

`--force-gates` 는 GPU 미탐지 환경(Apple Silicon·AMD)에서 필요하다. NVIDIA GPU가 있으면
빼도 된다.

## 4. 체크리스트

`docs/SMOKE.md` 실행 H의 항목이다. 스텁이 원리적으로 증명할 수 없는 것만 본다.

- [x] **실제 모델이 `entities`를 채웠는가** — `graph --stats` 의 **엔티티 수가 0이 아니다.**
      0이면 로컬 모델이 이 필드를 늘 비워 보낸다는 뜻이고 프롬프트를 손봐야 한다.
      `entities` 는 선택 필드라 비어도 위키는 정상 생성되고 자동 테스트도 전부 통과한다 —
      **이 항목이 유일한 안전망이다.**
- [x] **뽑힌 엔티티가 쓸 만한가** — `--neighbors 인사/채용계획.md.md` 의 `CONTAINS_ENTITY`
      줄에 `인사팀` · `그리팅 ATS` 같은 **실재하는 개체**가 나오는가, 아니면 `문서` · `내용`
      같은 일반명사가 나오는가.
- [ ] **`인사팀`이 하나의 노드인가** — 두 문서가 모두 인사팀을 언급한다. `--stats` 의 엔티티
      수가 실제 등장한 고유명사 수와 얼추 맞는지 본다(표기 흔들림이 합쳐졌는지).
- [ ] **기본 임계치 `0.75`가 합리적인가** — `SEMANTICALLY_SIMILAR` 엣지 수를 본다.
      6문서에서 **0개면 너무 높고**, 15개(전 쌍)에 가까우면 너무 낮다.
      `인사/채용계획.md ↔ 인사/온보딩.md` 와 `개발/아키텍처.md ↔ 개발/벡터설계.md` 근처가
      나오는 것이 정상이다. 값을 바꿔 감을 잡아 본다:
      ```bash
      corpbrain scan "$CORPUS" --out "$OUT" --similarity-threshold 0.85 --force-gates
      corpbrain scan "$CORPUS" --out "$OUT" --similarity-threshold 0.65 --force-gates
      ```
      **재요약은 일어나지 않는다** — 전부 `최신 상태` 로 스킵되고 그래프만 다시 만들어진다.
      종료 요약의 `처리 0건 / 스킵 6건` 과 `관련 문서 갱신 N건` 으로 확인할 수 있다.
- [ ] **「관련 문서」가 사람이 보기에 납득되는가** — `$OUT/인사/채용계획.md.md` 를 열어
      목록 순서를 본다. 참조한 `온보딩` 이 맨 위에 있고 무관한 문서가 섞여 있지 않은가.
- [ ] **링크가 실제로 열리는가** — `$OUT/개발/아키텍처.md.md` 의 「관련 문서」 링크를
      에디터에서 눌러 대상 위키로 이동하는가(`벡터설계.md.md` · `README.md.md` 형태).
- [ ] **고립 문서** — `$OUT/기타/메모.md.md` 에 `관련 문서 없음` 이 찍혔는가.
- [ ] **자기참조가 없는가** — `graph --neighbors 개발/README.md.md` 결과에 `README.md`
      자기 자신이 없다.
- [ ] **참조 방향이 맞는가** — `--neighbors 인사/채용계획.md.md` 에 `REFERENCES →` 와
      `REFERENCES ←` 가 **둘 다** 나온다(온보딩과 양방향이므로).
- [ ] **종료 코드** — `--stats` · `--central` · `--neighbors` 가 모두 `0`. 없는 문서를
      지목하면 `1`:
      ```bash
      corpbrain graph --out "$OUT" --neighbors 없는문서.md ; echo "exit=$?"
      ```

## 6. v0.7 α 스윕 — `--graph-decay` 기본값 확정  `[v0.7 / issue #43]`

> **2026-08-26 확정됨** — `DEFAULT_GRAPH_DECAY = 0.5`. 실측 결과와 해석은 `docs/SMOKE.md`
> 실행 J, 채택 근거는 스펙 §0에 있다. 아래는 **코퍼스나 임베딩·요약 모델이 바뀌었을 때 같은
> 방법으로 다시 재는 절차**다.

스펙 §4.8은 값을 근거 없이 정하지 않기로 했다 — `--similarity-threshold 0.75` 를 근거 없이
릴리스했다가 별도 이슈(#42)로 되돌아온 전례를 반복하지 않기 위해서다.

| 단계 | 주체 |
|---|---|
| 스윕 스크립트·절차 문서·쿼리 세트 초안 | 구현 세션 |
| 쿼리 세트 검토·확정 (정답 라벨이 맞는가) | **사용자** |
| 코퍼스 `scan`(인덱스·그래프 DB 생성)과 스윕 실행 | 실행 환경을 쥔 쪽 |
| `docs/smoke/`·`docs/SMOKE.md`·스펙 §0 기록, 상수 확정 | 구현 세션 |

> 스펙 §4.8의 원래 분담표는 스캔·스윕 실행을 사용자 몫으로 두고 "실행 환경(모델 가중치·
> 하드웨어)이 사용자 쪽에 있다"를 근거로 들었다. **2026-08-26 실측에서는 그 전제가 성립하지
> 않았다** — 세션이 사용자와 같은 머신에서 돌고 있어 환경 분리가 없었고, 사용자 지시로 세션이
> 직접 스캔·스윕을 실행했다. 그 조항에서 여전히 유효한 것은 **정답 라벨을 사람이 확인하는
> 단계**(§4.8 2번)뿐이다.

### 6.1 쿼리 세트를 먼저 확정한다

`docs/smoke/graph_decay_queries.json` 은 한국어 쿼리와 그 쿼리의 **정답 문서 목록**(코퍼스 루트
기준 상대경로)이다. 정답을 하나로 제한하지 않는다 — 그래프 확산은 여러 관련 문서를 함께
끌어올리는 기능이므로, 정답이 하나면 이번 슬라이스가 개선하려는 효과 자체가 측정되지 않는다.

```json
[
  {"query": "신규 입사자 첫 주 일정은 어떻게 되나요",
   "relevant": ["인사/온보딩.md", "인사/복지제도.md"]}
]
```

**스윕을 돌리기 전에 이 파일을 한 번 읽고 고친다.** 초안은 세션이 코퍼스에서 만들었을 뿐이라
「이 쿼리의 정답이 정말 이 문서들인가」는 사람이 판단해야 한다. 스크립트는 파일의 문서 경로가
코퍼스에 실제로 있는지 먼저 확인하고, 없으면 스윕을 시작하지 않는다.

### 6.2 실행

```bash
CORPUS=docs/smoke/corpus
OUT=$(mktemp -d)                  # 산출물은 반드시 리포지토리 밖

# 1) 코퍼스를 인덱싱한다 — LLM 요약이 24회 돈다(시간이 걸린다).
corpbrain scan "$CORPUS" --out "$OUT" --force-gates

# 2) α 스윕 — 쿼리 임베딩만 돌고 LLM 요약은 0회다.
uv run python docs/smoke/graph_decay_sweep.py --out "$OUT"
```

스윕은 사용자가 쓰는 것과 **같은 경로**를 탄다 — `corpbrain.core.search_index()` 를
`--graph-decay` 값만 바꿔 가며 반복 호출한다(스펙 §4.8 6번). 별도 랭킹 구현을 두지 않으므로
측정한 값이 실제 CLI 동작과 어긋날 수 없다.

산출물은 `docs/smoke/graph_decay_results.json` · `.csv` 이고, 표준출력에 α별 지표 요약 표가
나온다. **원시 출력 전체(표준출력 + 두 파일)를 구현 세션에 전달한다.**

### 6.3 무엇을 보고 α를 정하나

스펙 §4.8 4번의 순서를 그대로 따른다 — 앞의 키에서 갈리면 뒤는 보지 않는다.

1. **top-1 적중률** 내림차순 (1순위 문서가 그 쿼리의 `relevant` 목록에 있는 비율)
2. **MRR** 내림차순
3. **Recall@3** 내림차순
4. 그래도 동률이면 **α가 작은 쪽** — 그래프 개입이 적어 v0.4 동작에 가깝고 되돌릴 일이 적다

스크립트는 비교 기준선으로 `--no-graph`(코사인 단독) 행도 함께 낸다. **그래프 확산이 코사인
단독보다 나쁘면 그것 자체가 결과다** — 그때는 값을 고르는 대신 왜 나쁜지를 먼저 본다.

### 6.4 결과 기록

확정되면 구현 세션이 세 곳을 함께 고친다.

- `corpbrain/core/config.py` 의 `DEFAULT_GRAPH_DECAY` 한 줄 (근거 주석도 함께 갱신한다)
- `static/docs/specs/features/corpbrain-v0.7-hybrid-search.md` §0 에 채택 α와 지표
- `docs/SMOKE.md` 에 실행 기록
- 사용자에게 영향이 있는 한계가 나오면 `docs/USAGE.md` 에도 적는다 (#42 §13.5 선례)

자동 테스트는 이 상수를 참조하지 않고 `graph_decay=` 를 명시적으로 넘기므로, 상수를 갈아끼워도
테스트는 깨지지 않는다. **잠정값인 채로 릴리스하지 않는다** — 스펙 §3 항목13이 그것을 완료
조건으로 요구한다.

### 6.5 2026-08-26 실측이 남긴 주의점

같은 절차를 다시 밟을 때 되풀이하지 않도록 적어 둔다. 자세한 수치는 `docs/SMOKE.md` 실행 J.

- **top-1 적중률로는 α를 고를 수 없다.** 확산 문서의 점수는 항상 코사인 1위 미만이라 1위는
  어떤 α에서도 바뀌지 않는다. §4.8 4번의 1순위 키는 늘 전 α 동률이 되고, 실질 결정은
  MRR → Recall@3 가 한다. 스윕 출력에서 top-1 열이 전부 같아도 버그가 아니다.
- **쿼리를 문서 본문을 바꿔 말해 만들면 측정이 죽는다.** 어휘가 겹쳐 임베딩이 정답을 그냥
  1위로 올리므로 그래프가 개입할 틈이 없다. 첫 쿼리 세트가 15개 전부 그랬다.
- **쿼리 세트에는 두 방향이 다 있어야 한다** — 정답이 top-k 밖이라 확산이 끌어올릴 여지가
  있는 쿼리(A형)와, 정답이 2~5위라 확산이 밀어낼 위험이 있는 쿼리(B형). A형만 모으면 스윕은
  "α가 클수록 좋다"밖에 낼 수 없다.
- **후보 선별은 `--no-graph` 순위만 보고 한다.** 「그래프가 잘 찾아내는 쿼리」로 고르면
  스윕이 자기가 증명하려는 것을 전제하게 된다. 그래프를 켠 결과는 선별이 끝난 뒤에 본다.
