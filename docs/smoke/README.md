# v0.6 지식그래프 수동 스모크 — 실행 안내

`docs/SMOKE.md` 의 **실행 H**가 쓰는 코퍼스와 절차다. 코퍼스는 `corpus/` 에 있다.

> ⚠️ **`--out` 은 반드시 리포지토리 밖 임시 폴더를 쓴다.** 산출물이 리포지토리 안에 남으면
> 다음 `pytest` 에서 픽스처의 입력 문서로 다시 잡혀 통합테스트가 깨진다(2026-08-22 실측).
> 입력 코퍼스는 리포지토리 안에 두어도 안전하다 — 테스트는 `tests/fixtures/` 와 `tmp_path`
> 만 쓰고 `docs/` 를 읽지 않는다.

이 안내문(`docs/smoke/README.md`)은 `corpus/` **바깥**에 있어 스캔 대상이 아니다. 안에 두면
7번째 문서로 잡혀 기대 그래프가 어긋난다.

---

## 1. 준비

```bash
ollama serve                      # 다른 터미널에서
ollama list                       # qwen2.5:7b-instruct · nomic-embed-text 확인
corpbrain doctor                  # 준비 상태 점검
```

## 2. 실행

```bash
CORPUS=docs/smoke/corpus          # 리포지토리 안
OUT=$(mktemp -d)                  # 산출물은 반드시 리포지토리 밖

corpbrain scan "$CORPUS" --out "$OUT" --force-gates
corpbrain graph --out "$OUT" --stats
corpbrain graph --out "$OUT" --central
corpbrain graph --out "$OUT" --neighbors 인사/채용계획.md.md
corpbrain graph --out "$OUT" --neighbors 개발/README.md.md
corpbrain graph --out "$OUT" --neighbors 기타/메모.md.md
```

`--force-gates` 는 GPU 미탐지 환경(Apple Silicon·AMD)에서 필요하다. NVIDIA GPU가 있으면
빼도 된다.

## 4. 체크리스트

`docs/SMOKE.md` 실행 H의 항목이다. 스텁이 원리적으로 증명할 수 없는 것만 본다.

- [x] **실제 모델이 `entities`를 채웠는가** — `graph --stats` 의 **엔티티 수가 0이 아니다.**
      0이면 로컬 모델이 이 필드를 늘 비워 보낸다는 뜻이고 프롬프트를 손봐야 한다.
      `entities` 는 선택 필드라 비어도 위키는 정상 생성되고 자동 테스트도 전부 통과한다 —
      **이 항목이 유일한 안전망이다.**
- [x] **뽑힌 엔티티가 쓸 만한가** — `--neighbors 인사/채용계획.md.md` 의 `CONTAINS_ENTITY`
      줄에 `인사팀` · `그리팅 ATS` 같은 **실재하는 개체**가 나오는가, 아니면 `문서` · `내용`
      같은 일반명사가 나오는가.
- [ ] **`인사팀`이 하나의 노드인가** — 두 문서가 모두 인사팀을 언급한다. `--stats` 의 엔티티
      수가 실제 등장한 고유명사 수와 얼추 맞는지 본다(표기 흔들림이 합쳐졌는지).
- [ ] **기본 임계치 `0.75`가 합리적인가** — `SEMANTICALLY_SIMILAR` 엣지 수를 본다.
      6문서에서 **0개면 너무 높고**, 15개(전 쌍)에 가까우면 너무 낮다.
      `인사/채용계획.md ↔ 인사/온보딩.md` 와 `개발/아키텍처.md ↔ 개발/벡터설계.md` 근처가
      나오는 것이 정상이다. 값을 바꿔 감을 잡아 본다:
      ```bash
      corpbrain scan "$CORPUS" --out "$OUT" --similarity-threshold 0.85 --force-gates
      corpbrain scan "$CORPUS" --out "$OUT" --similarity-threshold 0.65 --force-gates
      ```
      **재요약은 일어나지 않는다** — 전부 `최신 상태` 로 스킵되고 그래프만 다시 만들어진다.
      종료 요약의 `처리 0건 / 스킵 6건` 과 `관련 문서 갱신 N건` 으로 확인할 수 있다.
- [ ] **「관련 문서」가 사람이 보기에 납득되는가** — `$OUT/인사/채용계획.md.md` 를 열어
      목록 순서를 본다. 참조한 `온보딩` 이 맨 위에 있고 무관한 문서가 섞여 있지 않은가.
- [ ] **링크가 실제로 열리는가** — `$OUT/개발/아키텍처.md.md` 의 「관련 문서」 링크를
      에디터에서 눌러 대상 위키로 이동하는가(`벡터설계.md.md` · `README.md.md` 형태).
- [ ] **고립 문서** — `$OUT/기타/메모.md.md` 에 `관련 문서 없음` 이 찍혔는가.
- [ ] **자기참조가 없는가** — `graph --neighbors 개발/README.md.md` 결과에 `README.md`
      자기 자신이 없다.
- [ ] **참조 방향이 맞는가** — `--neighbors 인사/채용계획.md.md` 에 `REFERENCES →` 와
      `REFERENCES ←` 가 **둘 다** 나온다(온보딩과 양방향이므로).
- [ ] **종료 코드** — `--stats` · `--central` · `--neighbors` 가 모두 `0`. 없는 문서를
      지목하면 `1`:
      ```bash
      corpbrain graph --out "$OUT" --neighbors 없는문서.md ; echo "exit=$?"
      ```

를 함께 고친다 — 값이 두 곳에 있다.
