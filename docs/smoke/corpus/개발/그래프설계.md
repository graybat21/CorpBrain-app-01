# 지식그래프 저장소 설계

## 배경

아키텍처.md 가 정한 "저장 계층은 어댑터 인터페이스 뒤에 둔다"는 원칙에 따라, 벡터와는
별도의 그래프 저장소를 둔다. 그래프는 임계치 같은 파생 조건이 바뀌면 통째로 다시 만들어야
하고, 벡터설계.md 가 다루는 임베딩 저장소와는 재생성 주기가 다르기 때문이다.

## 노드·엣지 모델

노드는 문서·엔티티·태그 세 종류를 둔다. 엣지는 참조(REFERENCES), 엔티티 포함
(CONTAINS_ENTITY), 태그 부여(TAGGED_WITH), 의미 유사(SEMANTICALLY_SIMILAR) 네 종류다.
의미 유사 엣지만 임베딩 벡터의 코사인 유사도에 의존하고 나머지 세 종류는 요약 결과의
구조화 필드에서 결정적으로 나온다.

## 재빌드 정책

문서에서 추출한 사실(fact)만 증분으로 저장하고, 노드·엣지 자체는 매 실행마다 전체를
다시 만든다. 연구개발팀은 이렇게 해야 임계치를 바꿔 재실행했을 때 옛 엣지가 남는 문제를
피할 수 있다고 판단했다.

## 스키마 버전

저장소 파일이 손상되거나 이전 버전 스키마면 자동으로 복구하지 않는다. 사용자에게 파일을
지우고 다시 실행하라고 안내한다. README.md 가 정리한 모듈 규약과 마찬가지로, 이 결정도
연구개발팀 내부 리뷰를 거쳐 확정됐다.
