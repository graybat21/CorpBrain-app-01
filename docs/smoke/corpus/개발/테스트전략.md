# 테스트 전략

## 계층 구분

README.md 가 정리한 모듈 구조를 따라 테스트도 세 계층으로 나눈다. 단위 테스트는 추출기·
렌더러·저장소 계약처럼 순수 로직을 다루고, 통합 테스트는 Ollama HTTP를 mock으로 스텁해
파이프라인 전체를 검증하며, 보안 테스트는 localhost 외 연결이 없는지를 확인한다.

## 실제 모델 스모크

자동 테스트가 원리적으로 증명할 수 없는 것 — 실제 모델의 응답 충실도, 실제 임베딩
분포에서의 임계치 타당성 — 은 자동화하지 않고 수동 스모크로 따로 확인한다. 아키텍처.md
가 밝힌 로컬 우선 원칙 때문에 이 스모크도 로컬 Ollama로 진행하는 것이 원칙이다.

## 픽스처 관리

통합테스트는 `tests/fixtures/`와 `tmp_path`만 쓰고 `docs/`를 읽지 않는다. 산출물이
리포지토리 안에 남으면 다음 테스트 실행에서 픽스처의 입력 문서로 잘못 잡히는 사고가
있었기 때문에, 스모크용 산출물은 항상 리포지토리 밖 임시 폴더에 쓴다.

## 커버리지 원칙

새 기능은 실패 시나리오를 포함한 통합 테스트를 최소 1개 갖춰야 병합할 수 있다. 연구개발팀
리뷰어가 이 기준으로 PR을 확인한다.
