# CorpBrain 코어 아키텍처

## 설계 원칙

연구개발팀이 CorpBrain을 만들며 지키는 원칙은 셋이다.

1. **코어와 어댑터 분리** — 비즈니스 로직은 재사용 가능한 코어 라이브러리에 두고, CLI는
   인자 파싱과 종료 코드 매핑만 하는 얇은 어댑터다. 이후 붙을 UI도 같은 코어를 호출하는
   또 다른 어댑터가 된다.
2. **단일 외부호출 관문** — 프로세스의 모든 네트워크 호출은 게이트웨이 함수 하나를 지난다.
   코어의 다른 부분은 네트워크 라이브러리를 직접 부르지 않는다.
3. **코어 no-I/O** — 코어는 로그를 찍지 않고 파일 경로를 해석하지 않는다. 진행 상태는
   콜백으로 흘리고, 입출력은 어댑터가 맡는다.

## 처리 흐름

```
폴더 재귀 스캔 → 텍스트 추출 → 요약 → 마크다운 렌더 → 벡터 인덱싱 → 지식그래프
```

요약은 기본적으로 로컬 Ollama에 붙는다. 사용자가 명시적으로 켤 때만 외부 엔진을 쓰고,
그때도 동의 확인과 마스킹을 거쳐 같은 관문으로 나간다. 임베딩은 엔진과 무관하게 항상
로컬이다.

## 저장 계층

벡터와 그래프는 서로 다른 파일에 둔다. 수명과 재생성 주기가 다르기 때문이다 — 그래프는
임계치만 바꿔도 다시 만들지만 벡터는 그대로 쓸 수 있다. 두 저장소 모두 어댑터 인터페이스
뒤에 있어 구현을 교체할 수 있다. 자세한 스키마는 벡터설계.md 에서 다룬다.
