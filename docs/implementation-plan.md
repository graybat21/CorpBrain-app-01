## 원칙
- 구현은 확정 스펙에 **엄격히** 맞춘다. 스펙에 없는 기능 추가 금지. 완료 후 `/spec-check`.
- 구조 이음새 유지 (스펙 §4.5): ① 로직=코어 라이브러리, CLI=얇은 어댑터 ② 모든 외부 호출=단일 관문.
- 각 웨이브 착수 시 `/goal-setting`으로 해당 태스크의 `/goal` 프롬프트를 설계해 실행한다.
- **병렬 웨이브는 서브에이전트로 팬아웃**한다(같은 워크트리, 서로 다른 파일/모듈이면 충돌 없음).

## 임계 경로 (Critical Path)
FR-001 → 002 → 003 → 009 → 010 → 011 → 012 → 015 → 016 → 018 → (019·020)

깊이 ~11로 길다. 서브에이전트 병렬화의 실익은 **W3(5-way)** 와 W4/W7/W8/W11에 집중된다.
직렬 임계 경로(특히 W5→W6→W7→…)는 순차 진행이 불가피하다.

## 서브에이전트 운용 메모
- 오케스트레이션(orca)으로 웨이브별 Task 생성 → 병렬 태스크는 워커 동시 시작 → `worker_done` 대기.
- 각 워커에는 담당 이슈(`docs/issues/FR-0NN.md`)와 스펙 섹션을 지정하고, 코어 라이브러리·단일 관문
  이음새를 지키도록 명시한다.
- 같은 워크트리에서 병렬 실행 시, 워커별로 건드리는 모듈/파일 경계를 분리해 충돌을 피한다.
