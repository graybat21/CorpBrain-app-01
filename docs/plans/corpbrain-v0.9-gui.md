## 착수 전제

현재 브랜치 `feat/v0.9-gui-spec`에 커밋 3개가 있다 — 스펙, grill 원장 3종, 스펙 검토 14건
반영(`881cdb6`). **코드는 아직 한 줄도 없다.**

구현은 **이 브랜치가 `main`에 머지된 뒤** 시작한다. 스펙이 구현의 근거이므로 `main`에 없는
스펙을 보고 구현하면 두 PR이 같은 문서를 서로 다른 상태로 참조하게 된다. v0.7이 「선행 PR
머지 후 착수」로 세운 규율과 같으며, 이번에는 대기 비용이 0이다(리뷰 대기도 CI 실패도 없다).

## 브랜치·PR 전략 [사용자 결정 · grill-it T1]

**2 PR · 수직 절단.** 층으로 자르지 않는다.

```
main
 ├─ feat/v0.9-gui-server    PR ①  코어 6종 → handle() → 인증 → SSE → `gui` 명령
 │                                 → 정적 자산 골격 + 대시보드 1화면
 │                                 머지 시점: `corpbrain gui` 가 뜨고 대시보드가 보인다

 └─ feat/v0.9-gui-screens   PR ②  스캔 · 그래프 · 위키 · 검색 · 설정 5화면

                                   머지 시점: 스펙 §3 DoD 12항목 전부 충족
```

### 왜 층이 아니라 세로로 자르는가

이 저장소는 v0.6·v0.7·v0.8에서 **「`main`에 아무도 호출하지 않는 코드를 남기지 않는다」**를
세 번 근거로 삼았다. 코어만, 서버만 먼저 머지하는 계층 절단(3 PR)은 그 상태를 정확히 만든다 —
PR ①은 호출자 없는 함수 6개를, PR ②는 아무도 열지 않는 서버를 `main`에 남긴다.

세로로 자르면 그 근거를 **지키면서** 자를 수 있다. PR ①이 머지되는 시점에 `corpbrain gui`는
실제로 뜨고, 대시보드가 실제 `diagnose()`·`stats()` 값을 보여 주며, 나머지 탭은 §5가 정한
빈 상태를 그린다. 코어 6종은 전부 그 화면 하나가 실제로 호출한다.

### 왜 단일 PR이 아닌가

v0.7·v0.8이 단일 PR을 택한 근거는 **「쪼갤 자리가 없다」**였다 — 구현이 `extract.py` 한 파일,
`search` 한 명령에 몰려 있었다. v0.9는 그 전제가 성립하지 않는다. 코어 6종 · 서버 계층 전체 ·
프론트 6화면 · 패키징 · CI 신규 단계 · 문서 4종을 동시에 건드리므로, 한 PR에 담으면 리뷰
단위가 스펙 600줄어치가 된다. **전례를 기계적으로 따르지 않고 그 전례의 근거를 따른다.**

### PR ①이 머지 가능한 상태의 정의

「반쯤 된 GUI」를 머지하지 않는다. PR ①은 다음을 모두 만족할 때 ready가 된다.

- `corpbrain gui`가 임의 포트로 뜨고, stdout의 URL을 열면 대시보드가 실제 값으로 그려진다.
- 인증(토큰 → 쿠키 교환 · `Origin`/`Host`)이 스펙 §4.2대로 동작한다.
- 스캔을 아직 시작할 수 없어도 **SSE 엔드포인트는 붙고** 접속 즉시 스냅샷 1건을 보낸다.
- 미구현 화면 5개는 빈 화면이 아니라 §5의 「먼저 스캔하세요」 빈 상태를 그린다.
- `uv run ruff check .` · `uv run pytest` · 작업 트리 청결 검사 통과.

### 근거

v0.8 플랜이 `SUPPORTED_EXTENSIONS` 추가를 U1이 아니라 **추출기와 같은 커밋**으로 미룬 것과
같은 판단이다. 그때 근거는 「상수를 먼저 늘리면 매핑 정합성 단언이 여러 커밋 동안 빨간불이
된다」였고, 여기서는 **「호출자 없는 코드가 여러 커밋 동안 `main` 후보로 남는다」**이다.
T1이 PR을 세로로 자른 것과 같은 규율을 커밋 층위에도 적용한다.

⑥을 따로 떼는 이유는 반대다 — **동작이 한 글자도 바뀌지 않는 리팩터링**이라, 신규 기능
커밋에 섞이면 diff에서 「무엇이 옮겨졌고 무엇이 새로 생겼는지」가 사라진다. ③은 CLI가 이미
`_progress`를 소비하고 있어 호출자가 처음부터 있다.

## PR ①의 범위 — 인프라 전체 + 화면 1개 [사용자 결정 · grill-it T3]

**엔드포인트는 대시보드가 실제로 부르는 것만 만든다.** 스펙 §4.3의 코어 호출 7종 중 PR ①에
들어오는 것은 `diagnose()` · `SqliteGraphStore.stats()` 둘과 SSE뿐이다.

「화면이 하나뿐이라 PR ①이 얇다」는 오해를 남기지 않는다 — **인프라 전체가 PR ①이다.**

### 서버 계층을 통째로 넣지 않는 이유

엔드포인트 7종을 PR ①에 다 만들면 `main`에 **아무 화면도 부르지 않는 엔드포인트 6개**가
남는다. T1이 3 PR을 거부한 그 상태가 층만 바꿔 재현되는 것이다. 「조회 엔드포인트까지」라는
절충안도 택하지 않는다 — 경계가 「호출자가 있는가」에서 「메서드가 상태를 바꾸는가」로 옮겨가
T1·T2와 다른 잣대가 하나 더 생긴다. **규율은 셋 다 하나다: 호출자와 함께 들어온다.**

### PR ②가 반복 작업이 되는 것이 이 절단의 이득이다

PR ①이 인증·라우팅·SSE·토큰·패키징을 전부 닫아 두므로, PR ②의 화면 5개는 각각
**「엔드포인트 + (필요하면) 코어 변경 + 화면」 한 덩어리**로 들어와 바로 동작한다. 새로 정할
구조가 없어 화면마다 같은 모양의 커밋이 반복된다.

## `bind` 감시장치 확장 시점 [사용자 결정 · grill-it T6]

**`corpbrain gui`가 서버를 실제로 띄우는 커밋에서** `SocketWatcher`에 `bind` 기록
(pass-through)을 더하고 DoD 3 케이스를 같은 커밋에 넣는다. 감시장치와 측정 대상이 같은
커밋에서 처음 만난다 — T2의 「호출자와 함께」와 동형이다.

- **먼저 세우지 않는 이유**: 그 시점엔 `bind`하는 코드가 하나도 없어 새 케이스가 「아무도
  bind하지 않는다」만 단언하고, 실제로 지키는지는 한 커밋 동안 공허하게 통과한다.
- **v0.8이 보안 케이스를 U6으로 미룬 전례를 그대로 따르지 않는 이유**: 그때 늦춘 근거는 규율이
  아니라 **측정 대상(전체 스캔 파이프라인)이 그제야 존재했기 때문**이다. 이번에는 그 순간이
  PR ① 중반이므로 같은 근거가 이른 시점을 가리킨다. 서버가 뜬 채로 감시장치 없이 커밋이
  여러 개 지나가면 그 사이 `bind` 주소가 잘못 들어가도 아무도 잡지 못한다.

## CI wheel 단계 추가 시점 [사용자 결정 · grill-it T7]

**서버 기동 커밋 직후, 별도 커밋으로** `.github/workflows/ci.yml`에 `uv build` → wheel 설치 →
`corpbrain gui --no-browser` 기동 → stdout의 URL 확인 → 프로세스 종료 단계를 더한다.

- **이 저장소의 CI는 지금까지 휠을 빌드해 본 적이 없다.** hatchling의 `packages = ["corpbrain"]`이
  정적 자산까지 실제로 거두는지는 wheel을 만들어 봐야만 드러나고, 로컬은 `-e` 설치라 배치가
  틀어져 있어도 조용히 동작한다 — 스펙 §4.10.1이 경계한 그 분기다. **늦출수록 「로컬에선 됐는데」
  구간이 길어진다.**
- **별도 커밋인 이유**: 서버 기동 커밋은 이미 CLI 명령 · 서버 · `bind` 감시장치 세 덩어리를
  담는다. 워크플로 YAML은 성격이 달라 떼어 놓아야 diff가 읽힌다.
- `--no-browser`가 없으면 CI 러너에서 브라우저를 여는 명령이 되고, 서버는 포그라운드로 떠
  `Ctrl+C`까지 살아 있으므로(스펙 §4.1) 종료 절차가 없으면 CI가 타임아웃까지 매달린다.
  `dist/`는 이미 `.gitignore`에 있어 작업 트리 청결 검사와 부딪치지 않는다.

## 문서 갱신 시점 [사용자 결정 · grill-it T8]

**각 PR의 마지막 단위에서 그 PR 몫의 문서를 갱신한다.**

| PR | 문서 | 내용 |
|---|---|---|
| ① | `README.md` | 명령 5종(`plan`·`doctor`·`search`·`graph`·`gui`) · 필수 사전준비 2종(요약 모델·**임베딩 모델 pull**) · GPU 게이트 · 클라우드 옵트인 → **DoD 11 완결** |
| ① | `docs/USAGE.md` | `corpbrain gui` 절 신설 (기동 · 토큰 URL · `--no-browser`) |
| ② | `docs/USAGE.md` | 화면 6개 설명 · 「고급」 파라미터 · 알려진 한계(그래프 렌더 규모) |
| ② | `docs/SMOKE.md` | 실행 K 절차 |
| ② | `docs/ROADMAP.md` | §7이 GUI를 이월해 둔 자리 |

### 전례를 그대로 따르지 않는 이유

v0.6~v0.8은 문서를 **마지막 단위에 몰아서** 처리했다. 그 방식이 성립했던 것은 그 슬라이스들이
**단일 PR이라 「머지 시점」이 하나뿐**이었기 때문이다. PR이 둘이 된 이상, PR ① 머지 후
`corpbrain gui`가 `main`에 있는데 README·USAGE에는 없는 구간이 PR 하나만큼 생긴다 — T1이
절단 기준으로 삼은 「각 PR은 머지 시점에 실제로 쓸 수 있다」가 문서에서 깨지는 것이다.

**DoD 11이 PR ①로 옮겨간다.** 요구가 「다섯 명령과 사전준비 2종이 README에 나타난다」인데
`plan`·`doctor`·`search`·`graph`는 이미 있고 `gui`가 PR ①에서 생기므로, PR ① 안에서 완결된다.

## 수동 스모크 K와 릴리스 [사용자 결정 · grill-it T9]

**스모크는 PR ②의 ready 조건이고, 릴리스는 머지 후 별도 PR이다.** v0.7(#50)·v0.8(#52)이
버전 범프를 기능 PR과 분리한 전례를 그대로 잇는다 — 「기능이 맞는가」와 「낼 때가 됐는가」를
같은 리뷰에서 판단하지 않는다.

### 실행 주체를 미리 갈라 둔다

v0.7 스펙 §4.8은 「측정은 사용자가 실행한다」로 역할을 나눴지만 **실측에서는 그 조항을 따르지
않았다** — 세션이 사용자와 같은 머신에서 돌고 있어 조항이 근거로 든 「환경 분리」가 실제로는
없었기 때문이다. 그 어긋남이 스펙에 남아 나중에 정정되었으므로, 이번에는 처음부터 갈라 적는다.

| 실행 K 항목 | 주체 |
|---|---|
| 실제 코퍼스 스캔 중 진행 표시가 그래프 단계까지 이어지는가 | 세션 |
| 취소 버튼이 실제로 듣는가 · 얼마나 기다리게 되는가 | 세션 |
| 그래프 화면이 실제 노드·엣지 규모에서 버티는가 (§5 알려진 한계) | 세션 |
| **진행 표시가 사람이 보기에 멈춘 것처럼 보이는가** | **사용자** |
| **6개 화면이 minimalist 토큰대로 보이는가** | **사용자** |
| **클릭 가능한 요소가 키보드로 닿고 포커스 링이 보이는가** | **사용자** |

앞의 셋은 기계로 관측되고, 뒤의 셋은 **눈으로만 판정된다.** 스모크에서 결함이 나오면 PR ②
안에서 고친다 — 머지 후로 미루면 이미 `main`에 들어간 코드를 고치게 된다.

## 커밋 규율

- **기능 + 그 기능의 테스트 + DoD 번호가 한 커밋.** 코어 변경은 첫 호출자와 같은 커밋(T2).
- 매 커밋이 `uv run ruff check .` · `uv run pytest` · `git status --porcelain` 청결을 통과한다.
- 커밋 프리픽스는 `v0.9(gui):` — v0.6~v0.8이 쓴 `v0.N(주제):` 관용구를 잇는다.
- 스펙과 어긋나는 것을 발견하면 코드가 아니라 **스펙을 먼저 고친다.** 이번 슬라이스는 착수 전에
  이미 그 경로를 한 번 썼다(스펙 검토 14건 · 커밋 `881cdb6`).

## 이 슬라이스가 남기는 것

- `corpbrain gui` — 신규 런타임 의존성 0으로 도는 로컬 서버와 화면 6개.
- 코어에 가산된 것 4종(`should_cancel` · `ScanResult.cancelled` · 그래프 이벤트 3종 ·
  `iter_edges()`)과 공개 승격 **3종**(`build_expansion_evidence()` · `parse_wiki_document()` ·
  `collect_wiki_documents()`/`WikiInventory`). 마지막 하나는 착수 시점에 세지 못했고 V2 에서
  드러났다 — 위키 상세가 `doc_id` 로 위키 파일을 찾아야 하는데 트리는 라벨만 주기 때문이다
  [2026-08-27 정정 · issue #62 · D-7].
- **CI가 처음으로 wheel을 빌드하고 그것으로 기동을 확인한다** — 이후 슬라이스가 그대로 물려받는다.
- `bind`까지 보는 네트워크 감시장치 — 「듣는 소켓」이라는 축이 이번에 처음 생긴다.
