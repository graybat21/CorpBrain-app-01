## 0. Design Read

> 단일 운영자를 위한 **고밀도 로컬 도구**. Swiss/minimal 언어, 네이티브 CSS 변수 + 시스템 폰트 스택,
> 모션은 상태 피드백에만.

**Dials — VARIANCE 3 / MOTION 2 / DENSITY 8.**

`ui-ux-pro-max` 가 매칭한 스타일은 `Minimalism & Swiss Style`(Best For: 엔터프라이즈 앱,
대시보드, 문서 사이트, 전문 도구)이며 이 브리프에 정확히 맞는다. 그대로 채택한다.

### 두 스킬에서 기각한 것

| 기각 | 출처 | 사유 |
|---|---|---|
| 팔레트 인디고 `#6366F1` | `ui-ux-pro-max --design-system` | `taste-skill` §4.2 가 「AI 퍼플」 계열을 기본 선택으로 금지한다 |
| 타이포 Cormorant Garamond + Crimson Pro | 같음 | Google Fonts CDN 세리프. 스펙 §4.8.1 의 웹폰트·CDN 금지와 충돌 |
| 패턴 `Real-Time / Operations Landing` | 같음 | 조회가 이 브리프를 랜딩 페이지로 잡았다. 도구형 UI가 아니다 |
| GSAP `ScrollTrigger` 모션 프리셋 | 같음 | 라이브러리를 로드하지 않는다(스펙 §4.8.1) |
| 랜딩·포트폴리오 규칙 일체 | `taste-skill` §13 | 스킬이 스스로 「dashboards / dense product UI / admin panels 에는 맞지 않는다」고 명시한다 |

점, 섹션 번호 eyebrow, 가짜 정밀 수치) · `prefers-reduced-motion` · 다크모드 필수.

## 1. 색 토큰

**액센트는 하나(desaturated cobalt)이고 의미색 셋(ok·warn·stop)과 겹치지 않는다.** 액센트를
초록이나 빨강으로 두면 「성공/차단」 표시와 눈으로 구분되지 않는다.

```css
:root {
  --bg:#F4F6F8;  --surface:#FFFFFF;  --surface-2:#EAEEF2;
  --ink:#10151B; --ink-2:#4A5561;    --ink-3:#78848F;
  --line:#D8DFE6; --line-2:#C2CCD6;
  --accent:#2E5EAA; --accent-ink:#FFFFFF; --accent-soft:#E4EBF6;
  --ok:#166534;   --ok-soft:#DEF0E4;
  --warn:#9A5B12; --warn-soft:#F7EBDA;
  --stop:#A32620; --stop-soft:#F7E1DF;
}
```

다크는 같은 토큰 이름을 재정의만 한다. **어떤 색도 미디어 쿼리 안에만 정의하지 않는다** —
`prefers-color-scheme` 을 지정하지 않은 뷰어가 기본값이기 때문이다.

```css
--bg:#0E1319; --surface:#151B23; --surface-2:#1D242D;
--ink:#E4E9EE; --ink-2:#A6B1BC; --ink-3:#76828F;
--line:#28313B; --line-2:#39434F;
--accent:#7FA9E8; --accent-ink:#0E1319; --accent-soft:#1B2635;
--ok:#5FB584; --warn:#D2984B; --stop:#DE8B84;
```

- 중립색은 **살짝 차가운 쪽으로 기울인다**(순회색이 아니라 blue-grey). 액센트가 코발트라
  같은 방향의 편향이 「고른 색」으로 읽힌다.
- 순수 `#000000` · `#FFFFFF` 를 배경/본문에 쓰지 않는다.
- 액센트는 전 화면에서 하나다. 7번째 화면에서만 다른 색을 쓰지 않는다.

## 2. 타이포

**웹폰트를 로드하지 않는다.** 시스템 폰트 스택만 쓴다.

```css
--font-ui: -apple-system, BlinkMacSystemFont, "Segoe UI", "Malgun Gothic",
           "Apple SD Gothic Neo", system-ui, sans-serif;
--font-mono: ui-monospace, SFMono-Regular, Consolas, "D2Coding", monospace;
```

| 역할 | 크기 | 자간·행간 |
|---|---|---|
| 화면 제목 | 19px / 600 | `-0.01em` |
| 섹션 제목 | 14px / 600 | 기본 |
| 본문·목록 | 13.5px / 400 | 1.55 |
| 보조·메타 | 12px / 400 | `--ink-3` |
| 수치·경로·플래그 | 12px mono | `font-variant-numeric: tabular-nums` |

- **경로·점수·개수·엣지 종류는 전부 mono.** 자리가 흔들리면 표가 읽히지 않는다.
- 위키 본문만 `max-width: 68ch` 로 묶는다. 나머지는 도구 화면이라 폭을 다 쓴다.

## 3. 레이아웃

**1축.** 좌측 사이드바 하나, 상단 탭 없음.

```
┌ 사이드바 236px ┬ 메인 ─────────────────────────────┐
│ CorpBrain      │ 화면 제목            [화면별 액션]  │
│ [인사자료   v] │ ─────────────────────────────────│
│                │                                   │
│ ● 탐색         │  콘텐츠                            │
│   스캔         │                                   │
│   대시보드      │                                   │
│ ─────────      │                                   │
│ ⚙ 설정         │                                   │
└────────────────┴───────────────────────────────────┘
```

- 사이드바 폭 고정 236px. 접기 기능을 두지 않는다(항목이 4개뿐이라 접을 이유가 없다).
- 메인 상단 바 높이 52px. 화면 제목과 그 화면의 주 액션만 놓는다.
- 간격 스케일: `4 / 8 / 12 / 16 / 24 / 32`. 밀도 8이므로 32 위로 올라가지 않는다.
- **모서리 반경은 4px 하나로 통일한다.** 버튼·카드·입력·칩이 전부 같은 값을 쓴다.
- 카드는 위계가 실제로 있을 때만 쓴다. 그 외에는 `border-top` 과 여백으로 가른다.

### 3.1 탐색 화면 — 3분할

```
┌ 검색 입력 (메인 폭 전체) ──────────────────────────┐
├ 결과 목록 320px ┬ 본문 / 그래프 ───────────────────┤
│ 1. 복지제도 *   │ [본문] [그래프]                   │
│ 2. 온보딩       │                                   │
│ 3. 평가제도     │ 연차는 입사일자 기준으로...        │
└─────────────────┴───────────────────────────────────┘
```

- 결과를 클릭해도 **목록이 사라지지 않는다.** 검색어와 결과가 계속 보이는 것이 이 화면을
  통합한 이유다.
- 본문/그래프 전환은 오른쪽 창 안의 세그먼트 컨트롤이다. 화면을 바꾸지 않는다.
- 확산으로 올라온 문서는 결과 줄 아래에 근거 한 줄을 붙인다(스펙 §4.6 형식 그대로).
- 1100px 미만에서는 결과 목록과 본문을 위아래로 쌓는다.

### 3.2 스캔 화면

- 폼은 **3단**이다(스펙 §4.7.1) — 항상 보임(폴더·엔진·모델) / `<details>` 「고급」 / 미노출.
- 실행 중에는 폼이 잠기고 그 자리에 진행 카드가 온다.
- 진행 카드: 단계 표시(`3 / 24`) · 현재 파일 · 경과와 예상 · **중지 버튼** · 파일별 로그.
  `ui-ux-pro-max` 의 Feedback 가이드라인(「다단계 작업은 진행 단계를 보여라」)을 따른다.
- **그래프 단계에는 코어가 이벤트를 내지 않는다**(스펙 §5). 파일 루프가 끝나면 진행바를
  불확정 상태로 두고 「그래프 만드는 중」을 따로 표시한다. 멈춘 것처럼 보이면 안 된다.
- 완료 후에는 결과 요약이 남는다 — 처리·스킵 개수와 **스킵 사유별 목록**. 스킵을 접어
  숨기지 않는다.

### 3.3 대시보드

- 타일 4개(위키 · 엣지 · 엔티티 · 마지막 스캔). 각 타일은 수치 하나와 라벨 하나.
- 그 아래 최근 스킵과 그래프 종류별 엣지 수.
- 타일에 스파크라인이나 추세를 넣지 않는다. **이력을 보관하지 않으므로**(스펙 §4.3.1)
  추세를 그릴 데이터가 없다. 없는 데이터를 그리지 않는다.

### 3.4 설정

- 환경 점검(doctor) 체크리스트 · 클라우드 엔진 · 워크스페이스 관리 세 블록.
- doctor 항목은 상태 칩(`OK` / `경고` / `실패`)과 조치 한 줄을 함께 낸다.
- 클라우드 동의 다이얼로그에 **고지 3줄이 반드시 들어간다**(스펙 §4.10).

## 4. 상태와 피드백

- **네 가지 상태를 모두 만든다** — 기본 · 로딩 · 비어 있음 · 오류.
  - 로딩은 최종 레이아웃 모양의 스켈레톤. 원형 스피너를 쓰지 않는다.
  - 비어 있음은 다음에 할 일을 알려 준다(「아직 스캔한 문서가 없습니다. 스캔을 실행하세요」).
  - 오류는 무엇이 잘못됐고 무엇을 하면 되는지 함께 적는다.
- 클릭 가능한 요소에 `cursor: pointer`, 눌림에 `transform: translateY(1px)`.
- **포커스 링을 지우지 않는다.** `:focus-visible` 에 2px 액센트 아웃라인.
- 상태를 색으로만 알리지 않는다. 칩에는 글자가 함께 있다.

## 5. 모션

`MOTION 2` — 상태 피드백에만 쓴다.

- 허용: hover/focus 색 전환 120ms, 패널 전환 페이드 140ms, 진행바 폭 변화.
- 금지: 스크롤 하이재킹, 시차 효과, 무한 루프 애니메이션, 마퀴, 장식용 등장 효과.
- `transform` 과 `opacity` 만 애니메이트한다.
- `prefers-reduced-motion: reduce` 에서는 전부 즉시 상태로 떨어뜨린다. 진행바는 애니메이션
  없이 값만 갱신한다.

## 6. 아이콘

`taste-skill` §3.C 는 아이콘을 직접 그리지 말고 라이브러리를 쓰라고 한다. 그런데 스펙
§4.8.1 이 외부 CDN과 신규 의존성을 금지하므로 **라이브러리를 설치할 수 없다.** 두 규칙이
부딪히는 지점이며, 해소는 이렇게 한다.

> **새로 그리지 않는다.** `gui_preview/variants/minimalist` 의 `ICON_SVGS` 가 이미 인라인
> SVG 세트를 갖고 있고, 그 판본은 접근성 보정까지 마친 상태다. 그것을 그대로 가져다 쓴다.
> 모자란 글리프가 생기면 같은 획 굵기(1.5px)의 기하 도형으로 최소한만 보탠다.

- 이모지를 아이콘으로 쓰지 않는다.
- 아이콘만 있는 버튼에는 `aria-label` 을 단다.

## 7. 출하 전 점검

- [ ] em-dash(`—`)가 화면 문자열 어디에도 없다
- [ ] 액센트 색이 전 화면에서 하나다
- [ ] 모서리 반경이 4px 하나다
- [ ] 모든 버튼 글자가 배경 대비 4.5:1 이상이다
- [ ] 입력·플레이스홀더·헬퍼·오류 텍스트가 전부 4.5:1 이상이다
- [ ] 라이트/다크 두 모드에서 실제로 열어 봤다
- [ ] 색을 정의한 곳이 미디어 쿼리 안에만 있는 토큰이 없다
- [ ] `prefers-reduced-motion` 에서 모션이 사라진다
- [ ] 키보드만으로 4개 화면을 전부 이동할 수 있고 포커스가 보인다
- [ ] 외부 URL 참조가 0건이다
- [ ] 장식용 상태 점·섹션 번호 라벨·가짜 정밀 수치가 없다
