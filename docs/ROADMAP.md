# CorpBrain 로드맵

- 상태: 확정 (로드맵 수준)
- 최종 갱신: 2026-08-25
- 범위: MVP 첫 슬라이스(FR-001~020) + run-status 관측 계층 이후의 후속 버전 계획.

각 항목에는 출처 태그를 단다: `[사용자 결정]` / `[제안 후 승인]`. 심층 설계는 **다음 버전만**
확정하고, 이후 버전은 착수 시점에 각자 `/interview`→`/spec`으로 구체화한다. `[제안 후 승인]`

## 1. 제품 정체성
**로컬 우선 + 클라우드 옵트인.** 기본 동작은 100% 로컬(Ollama)이며, 외부로 나가는 통신은
0이다. 외부/클라우드 LLM은 **사용자가 명시적으로 켜는 옵션**으로만 동작하고, 반드시
`동의 → PII 마스킹 → NetworkGuard 목적지 allowlist`를 거쳐 단일 게이트웨이로만 나간다.
기본값에서는 절대 외부로 나가지 않는다. (게이트웨이의 예약된 확장 지점을 사용) [사용자 결정]

## 2. git·릴리스 전략
**트렁크 기반 + 태그 (기존 저장소 유지).** [사용자 결정]
- `main` = 트렁크(항상 통과 상태 유지).
- 기능마다 `feat/*` 단기 브랜치 → PR → `main` 머지.
- 버전 마일스톤 = **git tag `vX.Y`** + GitHub Release 노트.
- 기능 묶음 관리 = 버전당 `/spec` 문서 + **서브아이템(기능)당 GitHub Issue 1개**. v0.1의
  FR-×× 세분화(20개)는 v0.2부터 실제로 쓰이지 않았고, Milestone도 생성한 적이 없다 —
  이 문서 갱신 이전까지는 §2의 이 문구가 실제 관행과 어긋나 있었다. v0.7부터는 이 정정된
  방식(스펙당 이슈 1개, Milestone 미사용)을 그대로 따른다. [사용자 결정 · 2026-08-25 정정]
- `release/x.y` 브랜치는 "구버전 핫픽스를 하면서 main은 전진"이 필요해질 때만 도입. 현 단계 불필요.
- 신규 repo 분리·`main2` 병렬 메인라인은 **비채택**(공유 코어·이음새 분열/머지 충돌).

## 3. 버전 슬라이싱 (가치·저위험 우선) [사용자 결정]

| 버전 | 테마 | 포함 기능 |
|------|------|-----------|
| **v0.2** | 입력·계량 | (6) PDF 포맷 확장 · (2a) 중요도 점수화 · (1) 소요시간 추정 · (5) 추정부(GPU 감지·토큰 추산) |
| **v0.3** | 환경·게이팅 | (5) 전체 게이팅(GPU/파일크기/토큰 임계 → 기능 제한) · (4) 내부 LLM(ollama) 설치·연동 간편화 |
| **v0.4** | 벡터 RAG | (2b) 임베딩 → 벡터DB → RAG |
| **v0.5** | 클라우드 옵트인 | (3) 외부 LLM 인증·연동 + NetworkGuard + PII 마스킹 + 동의 게이트 |
| **v0.6** | 지식그래프 | (2c) 단순 wiki를 넘어 LLM wiki/지식그래프화 |
| **v0.7** | 검색 고도화 · 포맷 확장 | 임베딩 모델 재판단(#42, 선행) · 하이브리드 검색(그래프 가중치 결합) · `.xls`/`.ppt` 추출 |

의존성 근거: (2a)/(6)은 LLM 없이/추출단만 건드려 저위험·독립, (1)은 (5)의 토큰·처리율 추정에
의존, (2b)는 임베딩·벡터DB 신규 인프라, (3)은 보안(인증·NetworkGuard·PII) 부담이 크고,
(2c)는 추출·벡터 성숙에 의존해 가장 상위. [제안 후 승인]

v0.7 의존성: 하이브리드 검색은 `SEMANTICALLY_SIMILAR` 엣지 위에서 동작하므로, 그 엣지의
기반인 임베딩 모델·임계치가 실측으로 확정되기 전까지는 결과가 유효하지 않다 — 임베딩 모델
재판단(#42)을 먼저 닫고 그 결과(채택 모델·임계치)를 입력으로 하이브리드 검색에 착수한다.
`.xls`/`.ppt` 추출은 완전히 독립적이라 순서 제약 없이 언제든 병렬로 진행한다. 캘린더 날짜
타겟은 두지 않고 착수 순서만 고정한다. [사용자 결정 · 2026-08-25]

v0.7 비목표: GUI 착수(로컬 API 서버·SSE·화면)와 `RELATES_TO`(엔티티↔엔티티 관계·LLM 동의어
병합)는 v0.7에 넣지 않는다. GUI는 v0.6에서 스펙상 명시적 비목표였고 착수 시점·형태가 아직
정해지지 않았다. `RELATES_TO`는 결정적 판정이 불가능해 v0.6에서도 뺐던 항목으로, 비결정성을
어떻게 다룰지가 먼저 판단돼야 한다. 두 항목 모두 v0.8 이후 후보로 남기되 이번엔 상세를 정하지
않는다. issue #40(클라우드 스모크 재실행 — entities 효과 실측)은 v0.6.1 변경의 효과 검증이지
새 기능이 아니므로 v0.7과 무관하게 별도로 처리한다. [사용자 결정 · 2026-08-25]

## 4. v0.2 상세 (완료됨 — 과거 기록)

심층 스펙은 `static/docs/specs/features/corpbrain-v0.2-prescan-and-pdf.md`에 있다. 아래는
착수 당시의 로드맵 수준 개요를 그대로 보존한 기록이며, 정본은 스펙 문서다.

- **포맷 확장 (6)**: PDF 먼저 — `pypdf` 텍스트 레이어 추출만. xls(`openpyxl`)/ppt(`python-pptx`)는
  후속(v0.2.x 또는 v0.3). 기존 `extract.py`의 "확장자별 추출기" 패턴을 따른다. [사용자 결정]
  - 비목표: 스캔 이미지 PDF·OCR, 암호화 PDF. [사용자 결정]
- **pre-scan 계량 (2a·1·5)**: 본격 스캔 전에 도는 값싼 로컬 전용 패스.
  - 전용 명령 **`corpbrain plan <folder>`**(= `scan --dry-run`)이 상세 리포트를 출력하고,
    **`scan` 시작 시 요약 배너**도 함께 낸다. [사용자 결정]
  - 코어에 순수 함수 `plan_scan(config) -> ScanPlan` 추가 — LLM·네트워크 호출 0, 즉시 반환.
    파일 목록은 기존 `scanner.scan_folder` 재사용. [사용자 결정]
  - (2a) 중요도 점수: 트리 깊이·폴더명·파일명·확장자 휴리스틱(내용/LLM 없음). [사용자 결정]
  - (1)(5) 추정: 문자수→토큰 휴리스틱 + 감지 하드웨어(GPU/CPU) 기준 정적 처리율로 예상시간을
    내고, run-status가 측정하는 실제 rate로 보정. GPU 감지는 로컬 수단(추가 네트워크 0). [제안 후 승인]

## 5. v0.7 상세 (다음 버전 — 심층 확정)

심층 스펙은 각 서브아이템 착수 시 `/interview`→`/spec`으로
`static/docs/specs/features/corpbrain-v0.7-*.md` 각각 작성한다(슬러그는 착수 시 확정). 이
절은 착수 순서를 정하기 위한 로드맵 수준 개요이며, 기계 판정 가능한 완료의 정의·인터페이스
계약은 각 스펙에서 확정한다. [사용자 결정]

- **임베딩 모델 재판단 (issue #42, 선행)**: `nomic-embed-text` 기본값이 한국어 코퍼스에서
  유사도 순서 자체를 틀리는 문제(1/4 vs `bge-m3`의 4/4, 실측 근거 issue #42)를 더 큰 코퍼스
  (20~30문서)로 재검증하고, 채택 모델과 그 분포에서 산정한 임계치 기본값을 확정한다. 기본
  임베딩 모델 교체는 기존 벡터 인덱스를 무효화하는 파괴적 변경이므로, v0.4가 스키마 불일치에
  대해 정한 "자동 마이그레이션하지 않고 에러 + 재생성 안내" 방침과 정합적인 이행 경로를 함께
  정한다. [사용자 결정]
- **하이브리드 검색**: 코사인 유사도(`search`)와 그래프 연결 가중치(태그·엔티티 공유,
  `REFERENCES` 등)를 결합해 재순위화한다. 기존 `search` CLI·코어와 `graphstore.py` 조회
  이음새를 재사용하고 신규 저장 계층을 만들지 않는다. 임베딩 모델 재판단의 채택 모델·임계치
  결과를 입력으로 받은 뒤 착수한다(선행 의존). [사용자 결정]
- **`.xls`/`.ppt` 추출**: v0.2 스펙이 이미 후속 버전으로 예고해 둔 항목. `extract.py`의
  기존 "확장자별 추출기" 패턴을 그대로 따라 `openpyxl`(xls)·`python-pptx`(ppt)로 텍스트
  레이어만 추출한다. 다른 두 서브아이템과 독립적이라 순서 제약 없이 언제든 진행한다.
  [사용자 결정]

## 6. 품질 게이트 (매 버전 고정) [사용자 결정]
매 버전은 다음 파이프라인을 통과해야 tag 한다:

`/interview` → `/spec`(features/*) → `feat/*` 브랜치 → TDD(단위 + 통합 mock) →
`/spec-check` → 실제 모델 수동 스모크 → PR → merge → **tag `vX.Y`**

매 버전 유지할 불변식:
- 모든 외부 호출은 **단일 게이트웨이** 경유.
- **기본 로컬** — 외부는 옵트인·동의·PII·allowlist 경유일 때만.
- **코어 no-I/O** — 비즈니스 로직은 콜백/순수 값으로, 입출력은 어댑터가.
- **하위 호환** — 신규 파라미터는 선택·기본값 보존.
- **green** — `ruff check .` · `pytest` 모두 통과.

## 7. 로드맵 차원 비목표 [사용자 결정·파생]
- v0.8 이후의 세부 설계는 이번에 확정하지 않는다(v0.7 완료 후 재정리; 착수 시 각자 인터뷰).
- GUI 착수(로컬 API 서버·SSE·화면)는 v0.7 비목표 — v0.8+ 후보로만 남긴다.
- `RELATES_TO`(엔티티↔엔티티 관계)·LLM 동의어 병합은 v0.7 비목표 — 비결정성 처리 방안 미정.
- OCR·스캔 이미지 PDF.
- 클라우드/외부 LLM은 v0.5 전까지 도입하지 않는다.
- 전체 자원 게이팅 강제는 v0.2가 아니다 — v0.2는 **추정(표시)만** 하고, 강제 제한은 v0.3.
