# CorpBrain 프로젝트 개요 — 무엇을 하는 도구인가

> 이 문서는 CorpBrain 저장소를 처음 보는 사람이 **10분 안에 전체를 이해**할 수 있도록 쓴
> 안내서다. 스펙 문서(`static/docs/specs/`)가 「무엇을 만들기로 했는가」의 정본이라면,
> 이 문서는 「지금 무엇이 만들어져 있는가」의 지도다.
>
> 기준: **v0.8.0** · 2026-09-01 · 소스 코드 실측

---

## 1. 한마디로

**내 컴퓨터 안에 흩어진 문서를 읽어서, 검색 가능한 위키로 자동 정리해 주는 명령줄 도구.**

- 폴더 하나를 가리키면 → 문서마다 요약 위키 페이지 1개씩 만들어 준다.
- 문서끼리 어떻게 연결되는지(같은 태그·같은 인물·서로 참조)까지 계산해 붙여 준다.
- 그다음부터는 "휴가 정책" 같은 자연어로 검색할 수 있다.
- **모든 처리가 내 컴퓨터 안에서 끝난다.** 밖으로 나가는 통신은 로컬 Ollama 호출 하나뿐이다.

### 이 도구가 푸는 문제

| 흔한 상황 | CorpBrain이 하는 일 |
|---|---|
| 공유 폴더에 문서 수백 개, 뭐가 뭔지 모름 | 문서마다 한 줄 요약·핵심 포인트·태그를 붙인 위키 생성 |
| 파일명 검색만 되고 내용 검색은 안 됨 | 의미 기반(벡터) 검색 — 단어가 안 겹쳐도 찾음 |
| 관련 문서가 어디 있는지 모름 | 문서 사이 관계를 그래프로 계산해 「관련 문서」 링크 자동 삽입 |
| 기밀 문서라 외부 AI에 못 붙여넣음 | 100% 로컬 실행. 클라우드는 명시적으로 켤 때만 |

## 2. 전체 흐름 한눈에 보기

```
  ① 계량             ② 스캔·추출          ③ 요약              ④ 렌더
  plan               폴더 재귀 순회        로컬 LLM에게        고정 템플릿으로
  (LLM 0회)     →    7종 포맷 텍스트  →   JSON 6필드     →    마크다운 위키
  얼마나 걸릴까       앞 12,000자만        요청·수신           1문서 = 1파일
                                                                  │
                                                                  ▼
  ⑤ 인덱싱                    ⑥ 그래프 빌드                ⑦ 관련 문서 주입
  요약문을 벡터로             태그·엔티티·참조·유사도로     각 위키 파일에
  sqlite에 저장        →      노드·엣지 전체 재계산    →   「관련 문서」 블록 갱신
                                                                  │
                                                                  ▼
                                                 corpbrain search "질문"
                                                 corpbrain graph --stats
```

`scan` 명령 한 번이 ②~⑦을 전부 수행한다. "인덱싱 명령"이나 "그래프 빌드 명령"을 따로 두지
않은 것은 의도된 설계다 — **DB와 위키와 검색 결과가 언제나 같은 값을 가리키게** 하려는 것이다.

## 3. 주요 기능 리스트

### 🗂️ F1. 폴더 재귀 스캔 → 위키 생성 `[v0.1]`

폴더를 통째로 훑어 **입력 문서 1개당 위키 마크다운 1개**를 만든다. 입력 폴더의 하위 구조를
출력 폴더에 그대로 미러링한다.

- 파일명 규칙: `report.docx` → `report.docx.md` (확장자를 **떼지 않고 뒤에 붙인다**)
  - *왜?* 같은 폴더의 `a.txt`와 `a.md`가 둘 다 `a.md`가 되어 충돌하는 것을 원천 차단하려고.
- 출력 폴더가 입력 폴더 안에 있으면(`scan ./docs --out ./docs/wiki`) 그 하위 트리는 자동 제외.
  - *왜?* 안 그러면 지난 실행이 만든 위키를 새 입력 문서로 착각해 산출물이 무한히 중첩된다.

### 📄 F2. 7종 포맷 텍스트 추출 `[v0.1 → v0.2 → v0.8]`

| 확장자 | 어떻게 읽나 | 도입 |
|---|---|---|
| `.txt` `.md` | 평문 그대로 | v0.1 |
| `.docx` | 문단을 순서대로 이어 붙임 (python-docx) | v0.1 |
| `.pdf` | 텍스트 레이어만 (pypdf) — OCR은 하지 않음 | v0.2 |
| `.xlsx` `.xlsm` | 시트마다 `[시트: 이름]` 경계 줄 + 행을 탭으로 (openpyxl) | v0.8 |
| `.pptx` | 슬라이드마다 `[슬라이드 N]` + 도형·표·그룹·발표자 노트 (python-pptx) | v0.8 |

공통 규칙:

- 파일을 통째로 메모리에 올리지 않고 **앞부분 12,000자까지만** 읽는다.
- 내용이 없는 시트·슬라이드에는 경계 줄도 내지 않는다. (경계 줄만 남으면 "빈 문서" 검사를
  통과해 버려서, 시트 이름만 든 입력이 LLM까지 가 버린다.)
- 암호화된 파일은 앞 8바이트의 OLE 시그니처로 판별해 "암호화되었거나 구형 이진 포맷"이라
  안내한다. 예외 메시지 문자열로 판정하지 않는다 — 라이브러리 버전이 오르면 조용히 깨지므로.

### 🤖 F3. LLM 요약 — 구조가 깨질 수 없는 방식 `[v0.1]`

모델에게 **고정 필드 JSON**을 요청하고, 그 JSON을 **코드가** 마크다운 템플릿에 꽂아 넣는다.

```
모델이 채우는 것 : title / one_line_summary / key_points[] / summary / tags[] / entities[]
코드가 만드는 것 : front-matter · 섹션 헤더 · 원문 링크 · 「관련 문서」 마커
```

- 모델이 마크다운을 직접 쓰지 않으므로 **섹션 누락이 구조적으로 불가능**하다.
- 출력 언어는 항상 한국어.
- `entities`(인물·부서·시스템명)는 **선택 필드**다. 없어도 위키는 정상 생성되고 그래프의
  엔티티 엣지만 빠진다. 위키에 렌더되지 않는 그래프 전용 재료이기 때문이다.

### ⚡ F4. 증분 재처리 `[v0.1]`

원본 파일의 수정 시각(mtime)이 기존 위키보다 새로울 때만 다시 요약한다. 아니면 스킵.
`--force`로 강제 재생성. → **같은 폴더를 다시 돌려도 LLM 비용이 0**이다.

여기에 더해 **내용이 실제로 달라졌을 때만 디스크에 쓴다.** 같은 내용을 다시 써서 mtime만
갱신하면 동기화 도구가 매 실행마다 산출물 전체를 변경으로 인식하기 때문이다.

### 📊 F5. `plan` — 돌리기 전에 견적 내기 `[v0.2]`

**LLM도 네트워크도 전혀 쓰지 않고** 폴더를 값싸게 훑어 리포트를 낸다. 파일 내용은 열지도
않고 경로·확장자·크기(stat)만 본다.

- **중요도 점수 (0~100)** — 확장자 기본점(`.pdf`·`.docx`·오피스 40 / `.md` 30 / `.txt` 25)
  + 신호 키워드(`계약`·`보고서`·`최종`·`정책`…) 가산 − 잡음 키워드(`temp`·`사본`·`draft`…) 감산
- **예상 토큰** — 확장자별 바이트→글자 비율로 근사
- **예상 소요 시간** — GPU 감지 시 50 tok/s, CPU 10 tok/s로 나눠 계산
- **하드웨어 감지** — `nvidia-smi` 로컬 호출 (소켓 0건)

`scan --dry-run`을 쓰면 같은 리포트를 내고 위키는 만들지 않는다.

### 🚦 F6. 자원 게이팅 — 사고 나기 전에 막기 `[v0.3]`

| 게이트 | 기본 임계 | 걸리면 |
|---|---|---|
| GPU 미감지 | — | **scan 차단** (exit 1) · `--force-gates`로 강행 가능 |
| 개별 파일 크기 | 20 MB | 그 파일만 `file_too_large`로 스킵 |
| 전체 예상 토큰 | 200,000 | **scan 차단** (exit 3) |

> ⚠️ GPU 감지는 `nvidia-smi` 기반이라 Apple Silicon·AMD GPU는 CPU로 판정된다 →
> `--force-gates`가 필요하다.

### 🩺 F7. `doctor` — 환경 준비 점검 `[v0.3]`

Ollama가 깔려 있나 / 떠 있나 / 요약 모델은 받았나 / 임베딩 모델은 받았나 / GPU는 있나 /
클라우드 동의와 API 키는 있나 — 전부 점검해 체크리스트로 낸다. 하나 실패해도 멈추지 않고
전 항목을 본다(준비 완료면 exit 0, 아니면 1).

### 🔍 F8. 벡터 인덱싱 + 의미 검색 `[v0.4]`

`scan`이 위키를 만들면서 **요약문을 임베딩해 sqlite에 저장**한다. 그다음:

```bash
corpbrain search "신규 입사자 첫 주 일정" --out ./wiki
```

- 단어가 하나도 겹치지 않아도 의미가 비슷하면 찾는다.
- 저장소는 `VectorStore` 인터페이스 뒤에 있어 나중에 sqlite-vec·chromadb로 갈아 끼울 수 있다.
- ⚠️ **v0.4부터 파괴적 변경**: 임베딩 모델(`qwen3-embedding:4b`)이 없으면 `scan`이 아예
  차단된다. 끄는 플래그가 없다.

### 🕸️ F9. 지식그래프 `[v0.6]`

문서들을 서로 이어 주는 그래프를 `scan` 안에서 함께 만든다. **LLM 추가 호출 0회**이고 같은
입력이면 언제나 같은 그래프가 나온다(결정적).

**노드 3종** — `Document`(문서) · `Entity`(인물·부서·시스템) · `Tag`(태그)

**엣지 4종**

| 엣지 | 뜻 | 재료 |
|---|---|---|
| `TAGGED_WITH` | 이 문서는 이 태그를 가짐 | 요약의 `tags` |
| `CONTAINS_ENTITY` | 이 문서에 이 인물·부서가 나옴 | 요약의 `entities` |
| `SEMANTICALLY_SIMILAR` | 두 문서가 의미상 비슷함 | 벡터 코사인 (기본 0.5717 이상) |
| `REFERENCES` | 이 문서가 저 문서를 언급함 | 본문에 나온 정확한 파일명 |

결과는 두 곳으로 드러난다.

1. **각 위키의 「관련 문서」 섹션** — 근거까지 함께 표시한다.

   ```
   ## 관련 문서
   - [온보딩](../인사/온보딩.md.md) — 유사도 0.81 · 공유 태그 `인사` · 서로 참조함
   ```

2. **`corpbrain graph` 조회 명령** — `--stats`(개수) / `--neighbors <경로>`(이웃) /
   `--central`(연결 많은 순)

설계에서 눈여겨볼 점:

- 「관련 문서」는 `<!-- corpbrain:related:start/end -->` **주석 마커 사이만** 교체한다.
  헤딩 문자열을 찾아 자르면, 요약문 안에 "## 관련 문서"라는 글자가 든 문서에서 뒷부분이
  조용히 잘려 나간다.
- 자기 자신을 향하는 엣지는 종류를 불문하고 만들지 않는다 (README가 본문에 "README.md"라고
  쓰는 일은 흔하다).
- 재료(`doc_facts`)는 증분 저장, 노드·엣지는 **매 실행 전체 재빌드**. 임계치를 바꿔도 옛
  엣지가 남지 않는다.

### 🔗 F10. 하이브리드 검색 — 그래프 시드 확산 `[v0.7]`

검색이 코사인 유사도만 보지 않고, **상위 결과를 「시드」로 삼아 그래프로 이어진 문서를
후보에 끌어올린다.** 확산 문서의 점수는 `max(자기 코사인, 시드 점수 × α)`.

```
2. [0.568] 채용계획 — /docs/인사/채용계획.docx
     └ 코사인 0.380 · 시드 «온보딩» · 공유 태그 `인사` · 서로 참조함
```

> 🔬 **정직하게 기록된 실측 결과**
> 24문서 코퍼스에서 α를 0.5~0.95로 쓸어 본 결과, **그래프 확산이 코사인 단독보다 나은
> 결과를 내지 못했다.** 확산이 개입할수록 지표가 단조 하락했고, 채택된 기본값 α=0.5는
> "가장 좋은 개입 강도"가 아니라 **"개입이 일어나지 않는 지점"**이다. 원인은 요약 모델이
> 뽑는 엔티티가 대부분 부서명이라 선택성이 없다는 것이다 — `인사팀` 하나가 23문서 중
> 10개를 잇는다. 우회법은 `--expand-edges`로 엔티티 엣지를 빼는 것.
> (자세히: `docs/USAGE.md` §6.3)

### ☁️ F11. 클라우드 옵트인 + PII 마스킹 `[v0.5]`

기본은 로컬이지만 원하면 Anthropic API로 요약할 수 있다. 켜려면 **3단계를 모두** 밟아야 한다.

```bash
corpbrain consent cloud --grant        # ① 명시적 동의 (~/.corpbrain/config.json에 기록)
export ANTHROPIC_API_KEY=sk-...        # ② API 키는 환경변수로만 (파일에 저장하지 않음)
corpbrain scan ./docs --engine cloud   # ③ 실행할 때 엔진 명시
```

**나가기 전에 한국 특화 PII 7종을 자동 마스킹**한다 — 주민등록번호 · 전화번호 · 이메일 ·
사업자등록번호 · 신용카드번호 · 계좌번호 · IP 주소.

- 마스킹은 **전송본에만** 적용된다. 원본 문서와 생성된 위키는 그대로다.
- 과탐(정상 숫자를 가림)은 감수하고 누락(진짜 PII를 놓침)을 줄이는 쪽으로 설계했다 —
  과탐의 비용은 요약이 조금 흐려지는 것뿐이기 때문.
- **임베딩은 엔진과 무관하게 언제나 로컬**이다.

### 📢 F12. 진행 표시 · 스킵 리포트 · 종료 코드

- **진행 표시** — 코어가 이벤트를 방출하고 CLI가 stderr에 한 줄로 갱신한다. 터미널이면
  제자리 갱신(`\r`), 파이프로 넘기면 줄바꿈으로 폴백.
- **스킵 리포트** — 처리하지 못한 파일은 전부 사유와 함께 종료 요약에 나온다.

  | 사유 | 뜻 |
  |---|---|
  | `unsupported_extension` | 지원하지 않는 확장자 |
  | `empty_document` | 내용이 없음 |
  | `extraction_failed` | 텍스트 추출 실패 (손상·암호화) |
  | `permission_denied` | 권한 거부 |
  | `path_too_long` | 경로 260자 초과 |
  | `summary_failed` | LLM JSON 파싱 실패 |
  | `up_to_date` | 원본이 안 바뀜 (정상 스킵) |
  | `file_too_large` | 파일 크기 상한 초과 |
  | `cloud_rate_limited` · `cloud_api_error` | 클라우드 호출 실패 |

- **종료 코드** — `0` 정상(개별 파일 실패 포함) / `1` 선행 조건 실패 / `3` 자원 게이트 차단
  - 핵심 원칙: **개별 파일 실패를 전체 실패로 위장하지 않는다.**

### 🛡️ F13. 네트워크 단일 관문

프로세스의 **모든** 외부 호출은 `core/gateway.py`의 `request_json()` 하나만 통과한다.
다른 모듈은 `urllib`·서드파티 HTTP 라이브러리를 직접 부르지 않는다.

- 나가는 목적지는 두 곳뿐 — 로컬 Ollama, 그리고 (옵트인했을 때만) `api.anthropic.com`.
- 테스트(`tests/security/test_network_invariant.py`)가 소켓을 감시해 "localhost 외 연결
  없음"을 매 버전 단언한다.
- 나아가 **그 감시장치가 공허하게 통과하지 않음을 증명하는 테스트**
  (`test_watcher_flags_a_gateway_bypass`)까지 둔다.

## 요약
## 태그·키워드

<!-- corpbrain:related:start -->

<!-- corpbrain:related:end -->

두 sqlite 파일은 **별도 파일**이라 한쪽만 지워 재구축할 수 있다. 스키마가 맞지 않으면
**자동 복구하지 않고** 멈춘 뒤 삭제·재실행을 안내한다 — 조용히 폐기하면 데이터 손실이
한참 뒤에야 드러나기 때문이다.

## 7. 이 프로젝트를 관통하는 설계 원칙 5가지

원칙을 `CLAUDE.md`에 못박고 매 버전 지킨다. 코드를 고칠 때 반드시 알아야 할 것들이다.

1. **코어와 어댑터를 가른다** — 비즈니스 로직은 `core/`에, CLI는 인자 파싱과 출력만.
   나중에 GUI가 붙어도 같은 코어를 부르는 또 하나의 어댑터일 뿐이다.
2. **외부 호출은 단일 관문** — 네트워크 정책을 한 곳에만 얹으면 로컬·클라우드 경로가
   함께 보호된다.
3. **기본은 로컬** — 외부 전송은 옵트인 + 명시 동의 + PII 마스킹을 모두 통과할 때만.
4. **조회는 저장된 값을 읽기만** — 조회 시점에 파생값을 다시 계산하지 않는다. 그래야
   DB·위키·검색 결과가 서로 어긋나지 않는다.
5. **결정적으로** — 같은 입력이면 같은 출력. 임베딩 입력에 그래프 산출물(「관련 문서」)을
   절대 넣지 않는 것도 이 원칙 때문이다. 넣으면 유사도 → 관련 문서 → 임베딩 → 유사도의
   피드백 루프가 생겨 같은 입력이 같은 결과를 내지 못한다.

그리고 **스펙이 코드보다 먼저다.** `/interview` → `/spec` → 구현 → `/spec-check` 순서로
진행하고, 스펙에는 사용자가 결정하거나 승인한 것만 `[사용자 결정]` / `[제안 후 승인]`
태그를 달아 적는다.

## 9. 알려진 한계 (숨기지 않고 문서화되어 있는 것들)

| 한계 | 내용 |
|---|---|
| 그래프 확산의 실효 | 현 기본값에서는 검색 순위를 바꾸지 않는다 (F10 참고) |
| 엔티티 선택성 | 요약 모델이 부서명 위주로 뽑아 허브 노드가 생긴다 |
| `--max-chars` 절단 | 12,000자 이후에 나오는 참조는 `REFERENCES` 엣지로 잡히지 않는다 |
| 숨긴 엑셀 행 | `read_only` 모드에서 판별 불가 → 내용이 포함된다 (숨긴 **시트**는 제외됨) |
| 수식만 있는 엑셀 | 계산값 캐시가 없으면 빈 문서로 스킵된다 |
| OCR 없음 | 스캔 이미지 PDF·이미지 안 텍스트는 읽지 못한다 |
| `.xls` `.ppt` | 구형 이진 포맷 미지원 (외부 변환기 의존을 피하려 제외) |
| `CHARS_PER_BYTE` | 오피스 3종 값은 실측이 아닌 잠정값 (후속 이슈 #48) |

## 부록. 용어 빠른 참조

| 용어 | 쉬운 설명 |
|---|---|
| **임베딩(embedding)** | 글을 숫자 배열로 바꾼 것. 배열끼리 가까우면 뜻이 비슷하다. |
| **코사인 유사도** | 두 숫자 배열이 얼마나 같은 방향을 보는지. 1에 가까울수록 비슷하다. |
| **시드(seed)** | 검색에서 코사인만으로 먼저 뽑힌 상위 문서. 확산의 출발점. |
| **확산(expansion)** | 시드와 그래프로 이어진 문서를 후보로 끌어올리는 것. |
| **엣지(edge)** | 그래프에서 두 노드를 잇는 선. 여기서는 4종. |
| **doc_facts** | 문서에서 뽑아낸 그래프 재료(태그·엔티티·참조). 증분 저장된다. |
| **게이트(gate)** | 조건이 맞지 않으면 실행을 막는 검문소. GPU·파일 크기·토큰 3종. |
| **옵트인(opt-in)** | 사용자가 명시적으로 켤 때만 동작하는 것. 기본은 꺼짐. |
| **프리플라이트** | 본작업 전에 선행 조건을 미리 확인하는 것. |
| **결정적(deterministic)** | 같은 입력이면 몇 번을 돌려도 같은 결과가 나오는 성질. |
