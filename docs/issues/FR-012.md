## :dart: Summary
- 기능명: [FR-012] 위키 마크다운 출력 배치·경로 미러링
- 목적: 렌더된 마크다운을 `--out` 하위에 입력 폴더 구조를 미러링하여 `<원본이름.확장자>.md`로 기록한다.

## :white_check_mark: Task Breakdown (실행 계획)
- [ ] `corpbrain/core/output.py`에 `output_path_for(source_path, scan_root, out_dir) -> Path`와 `write_wiki(markdown: str, out_path: Path) -> None`를 구현한다.
- [ ] 입력 파일의 `scan_root` 기준 상대 경로를 계산해 `out_dir` 아래 동일한 하위 디렉토리 구조를 미러링한다.
- [ ] 출력 파일명은 `<원본이름.확장자>.md`로 생성한다 — 원본 파일명에 확장자를 유지한 채 `.md`를 덧붙이며, 원본 확장자를 `.md`로 대체하지 않는다 (스펙 §4.4 파일명 규칙, `report.docx` → `report.docx.md`). [사용자 결정 · 2026-08-12]
- [ ] 대상 하위 디렉토리가 없으면 생성한다(`mkdir -p` 상당). `--out` 기본값은 `./corpbrain_wiki`(기본값 처리는 CLI FR-014에서 주입).
- [ ] 렌더 결과 마크다운 문자열(FR-011 산출)을 UTF-8로 기록한다.
- [ ] 단위/통합테스트: 하위폴더를 포함한 픽스처에 대해 출력 트리가 입력 하위구조를 미러링하고 각 지원 파일마다 `<원본이름.확장자>.md`가 생성되는지 기대 트리와 비교 검증한다. 같은 폴더에 `a.txt`와 `a.md`가 함께 있어도 출력이 충돌하지 않음을 포함한다.

## :test_tube: Acceptance Criteria (BDD/GWT)
Scenario 1: 하위폴더 포함 입력구조 미러링
- Given: `sub/a.txt`, `b.md`를 포함한 스캔 루트와 렌더된 마크다운
- When: 각 파일에 대해 `output_path_for(...)`로 경로를 계산하고 `write_wiki(...)`로 기록한다
- Then: `<out>/sub/a.txt.md`, `<out>/b.md.md`가 입력 하위구조를 미러링하여 생성된다

Scenario 2: 존재하지 않는 대상 하위 디렉토리
- Given: `--out` 아래에 아직 없는 하위 경로에 파일을 써야 함
- When: `write_wiki(...)`를 호출한다
- Then: 필요한 하위 디렉토리를 생성한 뒤 `<원본이름.확장자>.md`를 기록하며 실패하지 않는다

## :gear: Technical & Non-Functional Constraints
- 보안: 출력은 로컬 파일시스템에만 기록한다. 네트워크 호출 없음.
- 성능/안정성: 지원 파일 1개당 위키 마크다운 1개(1:1)를 보장한다. 미지원·스킵 파일에 대해서는 산출물을 만들지 않는다(스킵 리포트는 상위 계층 소관).
