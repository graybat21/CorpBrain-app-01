## :dart: Summary
- 기능명: [FR-006] 텍스트 추출기 (.txt / .md)
- 목적: `.txt`와 `.md` 파일에서 요약 입력으로 쓸 평문 텍스트를 추출하되, 파일을 통째로 메모리에 올리지 않는다.

## :white_check_mark: Task Breakdown (실행 계획)
- [ ] `corpbrain/core/extract.py`에 텍스트 추출기 함수 `extract_text(path: Path, max_chars: int) -> str` 구현 — 확장자별 디스패치의 `.txt`/`.md` 경로.
- [ ] `.txt`/`.md`는 인코딩 지정하여 스트리밍으로 읽고, 앞부분 `max_chars`(기본 12,000, FR-008에서 상한 관장)까지만 읽어 반환 — 파일 전체를 메모리에 올리지 않는다.
- [ ] 인코딩은 UTF-8 우선으로 읽되 디코딩 오류에 안전하게 처리(예: `errors="replace"` 또는 폴백)하여 추출 실패로 크래시하지 않는다.
- [ ] `.md`는 마크다운을 특별 파싱 없이 원문 텍스트 그대로 추출(스펙에 마크다운 렌더/구조 파싱 요구 없음 — 상상 추가 금지).
- [ ] 추출 결과가 비었거나 읽기에 실패하는 경우의 신호(빈 문자열/예외)를 FR-008(빈문서·추출실패 스킵)이 소비할 수 있게 명확히 반환.
- [ ] 코어 API 단독 호출로 추출이 동작함을 확인하고 단위테스트 작성 대상으로 노출(§3, §4.5).

## :test_tube: Acceptance Criteria (BDD/GWT)
Scenario 1: 정상 .txt/.md 추출
- Given: 내용이 있는 `.txt` 파일과 `.md` 파일이 있고 `max_chars`가 충분히 크다.
- When: `extract_text(path, max_chars)`를 호출한다.
- Then: 파일 앞부분의 평문 텍스트가 반환되며, 파일 전체를 메모리에 로드하지 않는다(앞부분만 읽음).

Scenario 2: 디코딩/읽기 문제
- Given: 인코딩이 불완전하거나 읽기에 문제가 있는 텍스트 파일이 있다.
- When: 추출을 시도한다.
- Then: 프로세스가 크래시하지 않고, 안전 처리된 텍스트를 반환하거나 추출 실패 신호(빈 문자열/예외)를 남겨 FR-008이 스킵+로그로 처리할 수 있게 한다.

## :gear: Technical & Non-Functional Constraints
- 보안: 로컬 파일 읽기만 수행하며 외부 네트워크 호출 없음.
- 성능/안정성: 파일 통째 로드 금지 — 앞부분 `max_chars`까지만 읽는다. 개별 파일 추출 실패는 전체 실패로 위장하지 않고 스킵으로 흡수(FR-008 연계). 코어 모듈로 구현(§4.5).
