## :white_check_mark: Task Breakdown (실행 계획)
- [ ] `corpbrain/core/gateway.py`(FR-003의 단일 외부호출 관문)를 경유하는 Ollama 클라이언트를 `corpbrain/core/llm/ollama_client.py`에 구현한다. 코어의 다른 부분은 네트워크 라이브러리를 직접 호출하지 않는다.
- [ ] `detect(ollama_url: str = "http://127.0.0.1:11434") -> bool` (또는 예외 발생형): 관문을 통해 Ollama 구동 여부를 확인하는 헬스체크(예: `GET /api/tags` 또는 `GET /api/version`)를 수행한다.
- [ ] 탐지 실패(연결 거부·타임아웃·비정상 응답) 시 설치·프로비저닝을 **시도하지 않고** 명확한 예외/에러 신호(`OllamaNotAvailableError` 등)를 반환하여 상위 계층이 선행 조건 실패로 비-0 종료를 매핑할 수 있게 한다.
- [ ] `--ollama-url`(기본 `http://127.0.0.1:11434`)을 인자로 받아 관문 호출 대상에 그대로 전달한다. localhost 외 연결을 만들지 않는다.
- [ ] `OllamaNotAvailableError` 등 예외 타입을 코어 모듈에 정의하고 export한다.
- [ ] 단위테스트: 관문을 mock/stub하여 (a) 정상 응답 → 탐지 성공, (b) 연결 실패 → 예외, (c) 비정상 상태코드 → 예외를 검증한다.

## :test_tube: Acceptance Criteria (BDD/GWT)
Scenario 1: Ollama가 구동 중일 때 탐지 성공
- Given: `--ollama-url`에 해당하는 로컬 Ollama가 헬스체크에 정상 응답한다
- When: `detect(ollama_url)`를 호출한다
- Then: 탐지 성공을 반환하며, 호출은 단일 관문을 경유하고 대상은 지정한 localhost URL뿐이다

Scenario 2: Ollama 미탐지/미구동
- Given: `--ollama-url` 대상이 연결 거부되거나 응답하지 않는다
- When: `detect(ollama_url)`를 호출한다
- Then: 설치를 시도하지 않고 `OllamaNotAvailableError`를 발생시켜 상위 계층이 선행 조건 실패(비-0 종료)로 매핑하게 한다

## :gear: Technical & Non-Functional Constraints
- 보안: 모든 네트워크 호출은 FR-003의 단일 관문만 통과한다. 대상은 `--ollama-url`(기본 localhost)뿐이며 그 외 네트워크·텔레메트리 0.
- 성능/안정성: Ollama 설치·프로비저닝 금지(탐지만). 선행 조건 실패(미탐지)는 부분 실패가 아니라 전체 선행 조건 실패로 취급한다.
