- 기능명: [FR-010] 요약·구조화 프롬프트와 고정필드 JSON 응답 파싱

## :white_check_mark: Task Breakdown (실행 계획)
- [ ] `corpbrain/core/llm/summarize.py`에 `summarize(text: str, model: str, ollama_url: str) -> SummaryResult` 구현. LLM 호출은 FR-009 클라이언트(→ 단일 관문)만 사용한다.
- [ ] 프롬프트를 구성해 모델이 **고정 필드 JSON**을 반환하도록 요청한다. 필드: `title`, `one_line_summary`, `key_points`(배열), `summary`, `tags`(배열).
- [ ] 출력 언어는 항상 **한국어**가 되도록 프롬프트에 명시한다.
- [ ] 모델 이름은 인자로 받는다(기본 `qwen2.5:7b-instruct`, 환경변수 `CORPBRAIN_MODEL` 지원은 CLI 계층 FR-014에서 주입).
- [ ] 응답에서 JSON을 파싱하고 필수 필드/타입(`key_points`·`tags`는 배열)을 검증하는 `SummaryResult` 데이터클래스를 정의한다.
- [ ] JSON 파싱 실패 또는 필수 필드 누락 시 `LLMParseError`(또는 명확한 실패 신호)를 발생시켜, 파이프라인(FR-015)이 **해당 파일만 스킵+로그**하고 나머지는 계속 처리하도록 한다.
- [ ] 12,000자 초과 절단은 FR-008에서 처리되므로 이 모듈은 이미 절단된 텍스트를 입력으로 받는다(파일 통째 로드 금지 원칙 유지).
- [ ] 단위테스트: 관문/클라이언트를 mock하여 (a) 유효 JSON → `SummaryResult`, (b) 깨진 JSON → `LLMParseError`, (c) 필드 누락/타입 오류 → `LLMParseError`를 검증한다.

## :test_tube: Acceptance Criteria (BDD/GWT)
Scenario 1: 유효한 고정필드 JSON 응답
- Given: Ollama가 `title/one_line_summary/key_points/summary/tags` 필드를 갖춘 유효 JSON을 한국어로 반환하도록 stub됨
- When: `summarize(text, model, ollama_url)`를 호출한다
- Then: 다섯 필드가 채워진 `SummaryResult`를 반환하며 `key_points`·`tags`는 배열이다

Scenario 2: LLM JSON 파싱 실패
- Given: Ollama가 JSON이 아니거나 필수 필드가 누락된 응답을 반환하도록 stub됨
- When: `summarize(...)`를 호출한다
- Then: `LLMParseError`를 발생시키며, 상위 파이프라인이 해당 파일만 스킵+로그하고 나머지 파일 처리는 중단하지 않는다

## :gear: Technical & Non-Functional Constraints
- 보안: LLM 호출은 FR-009 클라이언트 경유(단일 관문)뿐, 대상은 `--ollama-url`(localhost). 그 외 네트워크·텔레메트리 0.
- 성능/안정성: 입력은 `--max-chars`까지 절단된 텍스트만 사용(파일 통째 로드 금지). LLM 레이턴시 SLA 없음. 개별 파일 파싱 실패를 전체 실패로 위장하지 않는다.
