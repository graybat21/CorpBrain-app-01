## :white_check_mark: Task Breakdown (실행 계획)
- [ ] `tests/security/test_network_invariant.py` 작성
- [ ] 소켓 감시 장치 구성: `socket.socket.connect`(및 `create_connection`)를 패치해 연결 대상 주소를 수집하고, `--ollama-url` 호스트(기본 `127.0.0.1:11434`) 외 목적지로의 연결 시도가 있으면 테스트를 실패시키는 헬퍼 구현
- [ ] 관문 경유 불변식 검증: 코어의 다른 모듈이 네트워크 라이브러리를 직접 호출하지 않고 오직 단일 외부호출 관문(FR-003)만 소켓을 연다는 것을 assert (§4.5)
- [ ] 완료정의 픽스처로 파이프라인 1회 실행(Ollama 응답은 관문 스텁으로 대체) 후 수집된 연결 대상이 localhost 집합의 부분집합임을 assert
- [ ] `--ollama-url`을 다른 localhost 포트로 바꿔 실행해도 오직 그 지정 주소로만 연결됨을 확인(하드코딩된 외부 호스트 부재 검증)

## :test_tube: Acceptance Criteria (BDD/GWT)
Scenario 1: 정상 실행 시 localhost 외 연결 없음
- Given: 소켓 `connect`를 감시하는 패치가 걸린 상태에서 완료정의 픽스처와 관문 스텁
- When: 코어 파이프라인을 end-to-end로 1회 실행한다
- Then: 수집된 모든 연결 목적지가 `--ollama-url`이 가리키는 localhost 주소이며, 그 외 호스트로의 소켓 연결 시도가 0건이다

Scenario 2: 코어가 관문을 우회해 직접 네트워크를 열면 실패
- Given: 소켓 감시 패치가 활성화된 상태
- When: 코어의 비-관문 모듈이 외부 네트워크 라이브러리를 직접 호출(관문 우회)한다
- Then: 감시 장치가 이를 감지해 테스트가 실패하여, 단일 외부호출 관문 불변식(§4.5)을 회귀 방지로 강제한다

## :gear: Technical & Non-Functional Constraints
- 보안: 이 테스트가 스펙의 핵심 보안 불변식(외부 통신은 로컬 Ollama 호출뿐, 텔레메트리 0)을 강제하는 관문이다. 실제 원격 네트워크로 나가지 않도록 소켓은 감시/스텁만 한다.
- 성능/안정성: 테스트는 Ollama 실기동 없이(관문 스텁) 결정적으로 통과해야 하며, 외부 호스트 하드코딩·백그라운드 텔레메트리 유입에 대한 회귀 방지 역할을 한다.
