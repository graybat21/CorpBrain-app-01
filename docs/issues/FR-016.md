## :white_check_mark: Task Breakdown (실행 계획)
- [ ] `corpbrain/cli.py`에서 진행 로그를 **stderr**로 출력하도록 로깅을 구성한다(§4.1).
- [ ] 코어 `run_scan`(FR-015) 반환값을 받아 종료 요약을 출력한다: 처리 N건 / 스킵 M건(+각 사유) / 출력 경로(§4.1).
- [ ] 스킵 리포트를 사유별로 렌더한다: 미지원 확장자 / 빈 문서 / 추출 실패 / 권한 거부 / 긴 경로(>260) / LLM JSON 파싱 실패(§5).
- [ ] 종료 코드 매핑 함수를 구현한다(§5):
  - [ ] 개별 파일의 부분 실패만 있고 파이프라인이 정상 완료 → 종료 코드 **0**(스킵 목록 보고).
  - [ ] 선행 조건 실패(Ollama 미탐지/미구동, 입력 폴더 없음/접근 불가) → **비-0**.
  - [ ] 스캔 대상 상한(기본 50) 초과로 중단 → 사용자 알림 후 종료(선행 조건 실패로 취급, 비-0).
- [ ] 코어에서 올라온 실패 신호를 종료 코드로 변환하는 것 외의 비즈니스 로직을 CLI에 넣지 않는다(§4.5).

## :test_tube: Acceptance Criteria (BDD/GWT)
Scenario 1: 부분 실패는 성공 종료
- Given: 일부 파일이 스킵(미지원·빈 파일·JSON 파싱 실패)되고 나머지는 정상 처리되어 파이프라인이 완료됐다.
- When: `corpbrain scan` 실행이 끝난다.
- Then: stderr에 처리 N건/스킵 M건(+사유)/출력 경로 요약이 나오고, 프로세스 종료 코드는 **0**이다.

Scenario 2: 선행 조건 실패는 비-0 종료
- Given: Ollama가 탐지되지 않거나 입력 폴더가 없거나, 스캔 대상이 상한(50)을 초과한다.
- When: 실행이 선행 조건 검사/상한 검사에서 중단된다.
- Then: 사용자에게 사유가 알림(stderr)되고, 프로세스 종료 코드는 **비-0**이다.

## :gear: Technical & Non-Functional Constraints
- 보안: 리포팅·종료 처리 과정에서 어떤 외부 네트워크 호출·텔레메트리도 발생시키지 않는다(§1). 로그는 로컬 stderr로만 출력한다.
- 성능/안정성: 진행 로그는 stderr, 산출물 경로는 명확히 보고한다. 개별 파일 부분 실패를 전체 실패(비-0)로 위장하지 않는다(§5).
