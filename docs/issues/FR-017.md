- [ ] 렌더 산출물 파싱으로 front-matter 키(`source_path`, `generated_at`, `model`, `source_bytes`) 및 섹션 헤더(`# 제목`/`## 한 줄 요약`/`## 핵심 포인트`/`## 요약`/`## 태그·키워드`/`## 원문`) 존재를 assert (§3-2, §4.4)

## :test_tube: Acceptance Criteria (BDD/GWT)
Scenario 1: 렌더러가 고정 템플릿을 결정적으로 생성
- Given: `title`/`one_line_summary`/`key_points`/`summary`/`tags` 필드가 채워진 JSON과 원문 메타(경로·bytes·모델)
- When: 렌더러 함수를 호출한다
- Then: 반환 마크다운에 front-matter 4개 키와 6개 필수 섹션 헤더가 모두 존재하고, 동일 입력에 대해 항상 동일한 출력이 나온다

Scenario 2: 긴 문서 절단과 빈 문서 스킵
- Given: 12,000자를 초과하는 텍스트 파일과, 내용이 빈 파일
- When: 추출기를 호출한다
- Then: 긴 문서는 앞부분 12,000자까지만 추출 입력으로 반환되고, 빈 문서는 산출물 없이 "빈 문서" 사유의 스킵 신호를 반환한다

## :gear: Technical & Non-Functional Constraints
- 보안: 단위테스트는 네트워크를 전혀 사용하지 않는다(추출기·렌더러는 외부호출 관문을 경유하지 않는 순수 로직). 테스트 중 소켓 연결 0.
- 성능/안정성: 파일을 통째로 메모리에 올리지 않고 `--max-chars`까지만 읽는 계약을 검증한다. 테스트는 결정적(고정 입력→고정 출력)이며 Ollama 미기동 상태에서도 통과해야 한다.
