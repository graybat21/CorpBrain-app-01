## :dart: Summary
- 기능명: [FR-002] 코어 라이브러리 골격 (비즈니스 로직=코어 모듈, CLI=얇은 어댑터 경계)
- 목적: 후속 슬라이스(UI 등)를 재설계 없이 얹기 위해, 비즈니스 로직을 재사용 가능한 코어 모듈에 두고 CLI를 얇은 어댑터로 분리하는 이음새를 확보한다.

## :white_check_mark: Task Breakdown (실행 계획)
- [ ] `corpbrain/core/` 패키지를 생성해 스캔·텍스트 추출·요약·마크다운 렌더 등 비즈니스 로직이 들어갈 코어 모듈 경계를 만든다 (개별 로직 구현은 후속 FR).
- [ ] 코어의 공개 진입점(예: `corpbrain/core/__init__.py`에 end-to-end 실행 함수 시그니처)을 정의해, CLI 없이 함수 호출만으로 파이프라인을 구동할 수 있는 API 표면을 확보한다.
- [ ] `corpbrain/cli.py`(FR-001 스텁)를 이 코어 API를 호출하는 얇은 어댑터로 정리한다 — 어댑터에는 인자 파싱·로그 출력·종료 코드 매핑 외의 비즈니스 로직을 두지 않는다.
- [ ] 코어 API가 CLI 타입(argparse Namespace 등)에 의존하지 않도록, 입력 파라미터를 순수 값/데이터 구조로 받는 경계를 명시한다.
- [ ] 통합테스트가 CLI가 아닌 코어 API를 직접 호출하는 진입 경로가 존재함을 확인하는 최소 스모크(코어 함수 import 및 호출 가능) 테스트를 둔다.

## :test_tube: Acceptance Criteria (BDD/GWT)
Scenario 1: 코어를 CLI 없이 직접 호출
- Given: 설치된 `corpbrain` 패키지
- When: 테스트 코드가 `corpbrain.cli`를 거치지 않고 `corpbrain.core`의 공개 함수를 직접 import·호출한다
- Then: 코어 API가 CLI 의존 없이 호출 가능하며(파이프라인 로직은 후속 FR에서 채워짐), 통합테스트가 이 경로로 접근할 수 있다.

Scenario 2: CLI 어댑터의 로직 침범 방지
- Given: `corpbrain/cli.py` 어댑터
- When: 어댑터 코드를 검토한다
- Then: 어댑터는 인자 파싱·로그 출력·종료 코드 매핑만 수행하고, 스캔/추출/요약/렌더 등 비즈니스 로직은 코어 모듈에만 존재한다.

## :gear: Technical & Non-Functional Constraints
- 보안: 이 골격은 외부 네트워크 호출을 직접 포함하지 않는다 — 외부 호출은 별도 단일 관문(FR-003)으로만 도입한다.
- 성능/안정성: 코어와 CLI의 경계를 명확히 유지해, 후속 UI(pywebview·React) 어댑터가 동일 코어를 재설계 없이 호출할 수 있어야 한다.
