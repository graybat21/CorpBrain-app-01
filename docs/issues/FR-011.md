## :dart: Summary
- 기능명: [FR-011] JSON→마크다운 결정적 렌더러
- 목적: 요약 JSON을 스펙의 고정 템플릿(front-matter + 필수 섹션)으로 결정적으로 렌더링해 섹션 누락이 발생하지 않게 한다.

## :white_check_mark: Task Breakdown (실행 계획)
- [ ] `corpbrain/core/render.py`에 `render_markdown(summary: SummaryResult, source_path: str, model: str, source_bytes: int, generated_at: str) -> str` 구현.
- [ ] front-matter에 `source_path`(원문 절대경로), `generated_at`(ISO8601), `model`(사용 모델), `source_bytes`(숫자) 4개 키를 모두 출력한다.
- [ ] 본문 섹션을 고정 순서로 렌더: `# <제목>`, `## 한 줄 요약`, `## 핵심 포인트`(불릿 3~7개), `## 요약`, `## 태그·키워드`, `## 원문`(`[원본 파일 열기](file://<원문 절대경로>)`).
- [ ] `key_points`·`tags` 배열을 각각 불릿/태그 목록으로 결정적으로 변환한다. 어떤 필드가 비어도 섹션 헤더 자체는 항상 존재하도록 렌더한다(섹션 누락 불가).
- [ ] `generated_at`은 ISO8601 문자열로 주입받는다(렌더러는 시각을 자체 생성하지 않아 결정적 테스트가 가능하게 한다).
- [ ] 단위테스트: 샘플 `SummaryResult`를 렌더한 뒤 파싱하여 front-matter 4개 키와 6개 섹션 헤더가 모두 존재하는지, `file://` 원문 링크가 절대경로로 생성되는지 검증한다.

## :test_tube: Acceptance Criteria (BDD/GWT)
Scenario 1: 완전한 요약 JSON 렌더
- Given: 다섯 필드가 채워진 `SummaryResult`와 원문 절대경로·model·source_bytes·generated_at
- When: `render_markdown(...)`를 호출한다
- Then: `source_path/generated_at/model/source_bytes` front-matter 키와 `제목/한 줄 요약/핵심 포인트/요약/태그·키워드/원문` 섹션이 스펙 순서대로 모두 포함되고 `## 원문`에 `file://` 절대경로 링크가 있다

Scenario 2: 배열 필드가 비어있는 경우
- Given: `key_points` 또는 `tags`가 빈 배열인 `SummaryResult`
- When: `render_markdown(...)`를 호출한다
- Then: 해당 섹션 헤더는 여전히 존재하며(섹션 누락 불가) 렌더 결과는 결정적이다

## :gear: Technical & Non-Functional Constraints
- 보안: 렌더러는 순수 함수로 네트워크 호출을 하지 않는다(외부 통신은 관문 경유 LLM만).
- 성능/안정성: 코드가 JSON을 **결정적으로** 렌더링하여 섹션 누락이 불가능해야 한다. 동일 입력은 동일 출력(시각은 인자로 주입).
