## :dart: Summary
- 기능명: [FR-008] 길이 제한(--max-chars 절단) + 빈문서·추출실패 스킵
- 목적: 추출 텍스트를 `--max-chars`(기본 12,000)까지만 요약 입력으로 절단하고, 빈 문서·추출 실패 파일은 중단 없이 스킵+로그로 처리한다.

## :white_check_mark: Task Breakdown (실행 계획)
- [ ] `corpbrain/core/extract.py`(또는 파이프라인 경계)에 길이 제한 적용 지점을 확정 — 추출 결과를 `max_chars`(기본 12,000)로 절단하는 단일 규칙으로 통합.
- [ ] 추출기(FR-006/FR-007)가 앞부분만 읽더라도, 최종 요약 입력이 `max_chars`를 초과하지 않도록 방어적 절단을 보장한다.
- [ ] 빈 문서 판정: 추출 결과가 공백만이거나 길이 0이면 사유 `empty_document`로 스킵 대상으로 분류.
- [ ] 추출 실패 판정: FR-006/FR-007이 남긴 실패 신호(예외/빈 반환+오류)를 사유 `extraction_failed`로 스킵 대상으로 분류.
- [ ] 스킵 항목을 (경로, 사유)로 스킵 리포트에 누적하고, 해당 파일은 위키 산출물을 만들지 않으며 나머지 파일 처리는 계속(부분 성공).
- [ ] 12,000자 초과 문서는 오류가 아니라 앞부분 12,000자만 사용해 정상 처리됨을 보장(스킵 아님).
- [ ] 코어 API로 절단·스킵 판정이 동작함을 확인하고 단위테스트 대상으로 노출(§3, §4.5).

## :test_tube: Acceptance Criteria (BDD/GWT)
Scenario 1: 12,000자 초과 문서 절단 후 정상 처리
- Given: 12,000자를 초과하는 지원 포맷 문서가 있고 `--max-chars`는 기본 12,000이다.
- When: 추출·길이 제한을 적용한다.
- Then: 요약 입력은 앞부분 12,000자로 절단되고, 해당 문서는 스킵이 아니라 정상 처리 대상으로 파이프라인에 전달된다.

Scenario 2: 빈 문서/추출 실패 스킵+로그
- Given: 빈 문서(공백/0바이트 텍스트)와 추출에 실패한 파일이 있다.
- When: 길이 제한/유효성 판정을 적용한다.
- Then: 각 파일은 사유(`empty_document`/`extraction_failed`)와 함께 스킵 리포트에 나타나고 해당 `.md`는 생성되지 않으며, 나머지 파일 처리는 중단 없이 계속된다.

## :gear: Technical & Non-Functional Constraints
- 보안: 로컬 텍스트 처리만 수행하며 외부 네트워크 호출 없음.
- 성능/안정성: 파일 통째 로드 금지 — 요약 입력은 `max_chars`까지만. 개별 파일 스킵(빈문서·추출실패)은 전체 실패로 위장하지 않는다(부분 성공 보고). 길이 제한은 단일 규칙으로 일관 적용. 코어 모듈로 구현(§4.5).
