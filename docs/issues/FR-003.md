## :white_check_mark: Task Breakdown (실행 계획)
- [ ] `corpbrain/core/gateway.py`(단일 관문 모듈)를 생성하고, 모든 외부 네트워크 호출이 통과하는 단일 함수 시그니처를 정의한다 (실제 Ollama 호출 로직은 FR-009에서 이 관문을 경유해 구현).
- [ ] 코어의 다른 모듈이 네트워크 라이브러리(`urllib`/`http.client`/`requests` 등)를 직접 import·호출하지 않고, 반드시 이 관문 함수를 통해서만 외부 호출하도록 경계를 확립한다.
- [ ] 관문 함수가 대상 URL을 파라미터로 받도록 설계해, 후속 단계에서 스텁·감시(monkeypatch)로 대체 가능한 단일 지점이 되도록 한다.
- [ ] 관문 모듈에 후속 확장(NetworkGuard·PII 마스킹 게이트)이 삽입될 지점을 주석/구조로 명시하되, 이번 슬라이스에서는 게이트 로직을 구현하지 않는다 (비목표).
- [ ] 완료의 정의 6번 검증을 위해, 관문을 스텁·감시해 localhost 외 소켓 연결이 없음을 확인할 수 있는 훅(테스트에서 관찰 가능한 단일 진입점)을 노출한다.

## :test_tube: Acceptance Criteria (BDD/GWT)
Scenario 1: 외부 호출이 관문 단일 지점을 통과
- Given: 코어 파이프라인이 외부 네트워크 호출을 필요로 하는 상황
- When: 코어 코드가 외부 호출을 수행한다
- Then: 호출은 `corpbrain/core/gateway.py`의 단일 관문 함수를 통해서만 이루어지고, 테스트가 이 한 지점을 스텁·감시할 수 있다.

Scenario 2: 코어의 관문 우회 방지
- Given: `corpbrain/core`의 코어 모듈들
- When: 코어 소스를 검토·정적 분석한다
- Then: 관문 모듈 외의 어떤 코어 모듈도 네트워크 라이브러리를 직접 호출하지 않으며, 모든 외부 연결은 관문을 경유한다.

## :gear: Technical & Non-Functional Constraints
- 보안: 관문은 프로세스의 유일한 외부 네트워크 출구다 — 이 지점 외에서 발생하는 외부 연결은 스펙 위반이며, 이후 NetworkGuard·PII 마스킹 게이트의 삽입 지점이 된다.
- 성능/안정성: 관문은 대상 URL을 주입 가능한 형태로 받아 스텁·감시가 용이해야 하며(완료의 정의 6번 검증 성립), 이번 슬라이스 범위 밖의 게이트 로직은 구현하지 않는다.
