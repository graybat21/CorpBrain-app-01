## :dart: Summary
- 기능명: [FR-007] 텍스트 추출기 (.docx)
- 목적: `.docx` 파일에서 요약 입력으로 쓸 평문 텍스트를 추출하되, 앞부분 `--max-chars`까지만 사용하고 추출 실패는 스킵 신호로 남긴다.

## :white_check_mark: Task Breakdown (실행 계획)
- [ ] `corpbrain/core/extract.py`의 확장자 디스패치에 `.docx` 경로 추가 — `extract_text` 내부에서 `.docx` 전용 추출 함수 호출.
- [ ] `.docx` 파싱 의존성(예: `python-docx`)을 `pyproject.toml`에 추가하고 문단 텍스트를 순서대로 연결해 평문 추출.
- [ ] 앞부분 `max_chars`(기본 12,000)까지만 축적하도록 하여 매우 큰 문서를 통째로 메모리에 올리지 않는다(문단 누적 중 상한 도달 시 중단).
- [ ] 손상·비정상 `.docx`(파싱 예외)는 크래시가 아니라 추출 실패 신호(빈 문자열/예외)로 반환하여 FR-008이 스킵+로그로 처리하게 한다.
- [ ] `.pdf`/`.doc` 등 스펙 비목표 포맷은 절대 다루지 않는다(상상 추가 금지 — §2).
- [ ] 코어 API 단독 호출로 추출이 동작함을 확인하고 단위테스트 대상으로 노출(§3, §4.5).

## :test_tube: Acceptance Criteria (BDD/GWT)
Scenario 1: 정상 .docx 추출
- Given: 여러 문단 텍스트를 가진 정상 `.docx` 파일이 있다.
- When: `extract_text(path, max_chars)`를 호출한다.
- Then: 문단 텍스트가 순서대로 연결된 평문이 반환되며, 반환 길이는 `max_chars`를 넘지 않고 문서 전체를 무한정 메모리에 올리지 않는다.

Scenario 2: 손상된 .docx 추출 실패
- Given: 열 수 없거나 파싱이 실패하는 손상된 `.docx` 파일이 있다.
- When: 추출을 시도한다.
- Then: 프로세스가 크래시하지 않고 추출 실패 신호를 남겨, 해당 파일만 스킵+로그로 처리되고 나머지 파일 처리는 계속된다(FR-008 연계).

## :gear: Technical & Non-Functional Constraints
- 보안: 로컬 파일 파싱만 수행하며 외부 네트워크 호출 없음.
- 성능/안정성: 파일 통째 로드 금지 — 앞부분 `max_chars`까지만 축적. 개별 `.docx` 추출 실패는 전체 실패로 위장하지 않고 스킵으로 흡수. 지원 포맷은 `.docx`뿐이며 비목표 포맷을 추가하지 않는다(§2). 코어 모듈로 구현(§4.5).
