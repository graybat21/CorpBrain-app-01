## :dart: Summary
- 기능명: [FR-005] 스캔 가드레일 (상한 50 중단+알림, 미지원·긴경로>260·권한거부 스킵+로그)
- 목적: 스캔 대상 상한(기본 50) 초과 시 처리를 중단·알림하고, 미지원·긴 경로(>260자)·권한 거부 파일은 중단 없이 스킵+로그로 처리한다.

## :white_check_mark: Task Breakdown (실행 계획)
- [ ] `corpbrain/core/scanner.py`(또는 인접 가드 모듈)에 상한 검사 로직 추가 — 파라미터 `max_files: int = 50`.
- [ ] 스캔 대상 수가 `max_files`를 초과하면 처리를 시작하지 않고(또는 처리 중단) 상한 초과를 알리는 예외/신호 반환 — 종료 요약에 사용자 알림으로 표출(FR-016과 연결).
- [ ] 스킵 사유를 표현하는 구조/열거형 정의: `unsupported_extension`, `path_too_long`(>260자), `permission_denied` (그리고 §5의 빈 문서·추출 실패는 FR-008 담당이므로 여기서는 스캔 단계 사유만).
- [ ] 경로 길이 검사 `len(str(path)) > 260` → 스킵 사유 `path_too_long`로 분류.
- [ ] 접근 시 `PermissionError`/`OSError`를 잡아 해당 파일만 `permission_denied`로 스킵+로그, 전체 스캔은 계속.
- [ ] 각 스킵 항목을 (경로, 사유) 형태로 스킵 리포트에 누적하여 반환(산출물 생성 없음).
- [ ] 상한 초과는 부분 실패가 아닌 "처리 중단+알림"임을 명확히 구분(개별 파일 스킵과 다름).

## :test_tube: Acceptance Criteria (BDD/GWT)
Scenario 1: 상한(50) 초과 시 중단+알림
- Given: 지원 파일이 51개 이상인 픽스처 폴더가 있고 `--max`는 기본 50이다.
- When: 스캔을 실행한다.
- Then: 처리가 중단되고 상한 초과 사실이 사용자에게 알려지며, 위키 산출물이 대량 생성되지 않는다.

Scenario 2: 긴 경로/권한 거부/미지원은 스킵+로그로 계속 처리
- Given: 경로 길이 >260자 파일, 권한 거부 파일, 미지원 확장자 파일이 섞여 있다.
- When: 스캔이 이 파일들을 만난다.
- Then: 각 파일은 사유(`path_too_long`/`permission_denied`/`unsupported_extension`)와 함께 스킵 리포트에 나타나고, 해당 `.md`는 생성되지 않으며, 나머지 파일 처리는 중단 없이 계속된다.

## :gear: Technical & Non-Functional Constraints
- 보안: 가드레일 동작 중 외부 네트워크 호출 없음. 파일시스템 접근 오류는 프로세스 크래시가 아니라 스킵으로 흡수한다.
- 성능/안정성: 개별 파일 실패(스킵)는 전체 실패로 위장하지 않는다(부분 성공 보고). 상한 초과만이 처리 중단 사유이며, 이는 선행조건 실패가 아니라 사용자 알림 후 중단이다. 코어 모듈로 구현(§4.5).
