## :test_tube: Acceptance Criteria (BDD/GWT)
Scenario 1: 완료정의 픽스처 end-to-end 정상 처리
- Given: 정상/하위폴더/빈/미지원/초과 파일이 섞인 픽스처 폴더와, 고정필드 JSON을 반환하는 Ollama HTTP mock
- When: 코어 파이프라인 API에 `scan(folder, out)`를 직접 호출한다
- Then: 지원 파일마다 입력 하위구조를 미러링한 `<원본이름>.md`가 생성되고, 각 파일은 front-matter 4키와 6섹션을 포함하며, 처리 N건/스킵 M건(+사유)이 요약에 보고되고 종료 코드는 0이다

Scenario 2: 선행 조건 실패와 부분 실패의 구분
- Given: (a) Ollama 미탐지 상황을 mock으로 만든 경우와 (b) 일부 파일만 JSON 파싱에 실패하는 경우
- When: 파이프라인을 실행한다
- Then: (a)는 선행 조건 실패로 비-0 종료, (b)는 실패 파일만 스킵 리포트에 사유와 함께 남고 나머지는 계속 처리되어 종료 코드 0이다

- 성능/안정성: 통합테스트는 CLI가 아닌 코어 API를 직접 호출해 §4.5 코어 라이브러리 이음새를 검증한다. 개별 파일 실패가 전체 실패로 위장되지 않음(부분 성공 보고)을 반드시 검증한다.
