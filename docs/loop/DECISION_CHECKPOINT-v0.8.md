# 의사결정 체크포인트 — v0.8 `.xlsx`/`.xlsm`/`.pptx` 텍스트 추출

세 정본(스펙 · 실행 플랜 · grill 원장)에 **확정돼 있지 않은** 추가 의사결정만 기록한다.
정본에 이미 있는 결정을 여기에 복창하지 않는다.

- CORE = 아키텍처 · 보안 · 외부의존 · 데이터 모델
- MINOR = 네이밍 · 디렉터리 · 로그 포맷 · 문구

CORE: 0
MINOR: 3

## 기록

### M1 (MINOR · 문구) — 열기 실패 detail 의 포맷 이름을 확장자에서 파생시킨다

- 맥락: 스펙 §4.3.1 은 OLE 시그니처일 때의 문구(「암호화되었거나 구형 이진 포맷입니다」)만
  못박고, 그 앞에 붙는 기본 문구는 기존 관용구(`"docx를 열지 못했습니다: {path}"`)에 맡긴다.
- 결정: `_open_failure_detail()` 이 포맷 이름을 하드코딩하지 않고 `path.suffix` 에서 파생시킨다.
- 근거: `.xlsx` 와 `.xlsm` 이 같은 추출기를 공유하므로 하드코딩하면 `.xlsm` 파일이
  「xlsx를 열지 못했습니다」로 보고된다. 기존 `.docx`·`.pdf` 문구도 결과적으로 확장자와 같은
  문자열이므로 관용구가 갈리지 않는다.

### M2 (MINOR · 출력 포맷) — PPTX 표의 행도 탭으로 잇는다

- 맥락: 스펙 §4.2 는 「표 셀 텍스트를 재귀로 훑는다」까지만 정하고 셀 구분자를 정하지 않는다.
  엑셀 쪽에는 탭 구분과 「행 끝 빈 셀은 탭을 남기지 않는다」 규칙(T2)이 명시돼 있다.
- 결정: 엑셀의 `_tab_joined_row()` 를 PPTX 표가 그대로 재사용한다.
- 근거: 둘 다 「행 × 셀」 구조이고, 표기가 갈리면 같은 표를 담은 `.xlsx` 와 `.pptx` 가 서로 다른
  요약 입력을 만든다. 규칙이 한 함수에만 있으면 나중에 바뀌어도 두 포맷이 함께 따라온다.

### M3 (MINOR · 출력 포맷) — 노트만 있는 슬라이드도 경계 줄을 받는다

- 맥락: 스펙 §4.2 T1 은 「내용이 있는 슬라이드에만 경계 줄」을, 별도 항목에서 「노트가 공백뿐이면
  `[노트]` 줄도 내지 않는다」를 정한다. 도형은 없고 노트만 있는 슬라이드는 두 문장 어디에도
  명시돼 있지 않다.
- 결정: 노트도 내용으로 세어 `[슬라이드 N]` 경계 줄을 낸 뒤 `[노트]` 블록을 잇는다.
- 근거: 경계 줄의 의미가 「뒤에 내용이 온다」이므로, 뒤에 노트가 오면 신호가 필요하다. 반대로
  하면 `[노트]` 블록이 어느 슬라이드 것인지 알 수 없는 채로 놓인다. 「도형이 없으면 무조건
  생략」은 이미지만 있는 슬라이드를 겨냥한 규칙이지 노트를 버리라는 규칙이 아니다.
