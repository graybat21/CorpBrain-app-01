# 의사결정 체크포인트 — v0.8 `.xlsx`/`.xlsm`/`.pptx` 텍스트 추출

세 정본(스펙 · 실행 플랜 · grill 원장)에 **확정돼 있지 않은** 추가 의사결정만 기록한다.
정본에 이미 있는 결정을 여기에 복창하지 않는다.

- CORE = 아키텍처 · 보안 · 외부의존 · 데이터 모델
- MINOR = 네이밍 · 디렉터리 · 로그 포맷 · 문구

CORE: 2
MINOR: 5

## 기록

### M1 (MINOR · 문구) — 열기 실패 detail 의 포맷 이름을 확장자에서 파생시킨다

- 맥락: 스펙 §4.3.1 은 OLE 시그니처일 때의 문구(「암호화되었거나 구형 이진 포맷입니다」)만
  못박고, 그 앞에 붙는 기본 문구는 기존 관용구(`"docx를 열지 못했습니다: {path}"`)에 맡긴다.
- 결정: `_open_failure_detail()` 이 포맷 이름을 하드코딩하지 않고 `path.suffix` 에서 파생시킨다.
- 근거: `.xlsx` 와 `.xlsm` 이 같은 추출기를 공유하므로 하드코딩하면 `.xlsm` 파일이
  「xlsx를 열지 못했습니다」로 보고된다. 기존 `.docx`·`.pdf` 문구도 결과적으로 확장자와 같은
  문자열이므로 관용구가 갈리지 않는다.

### M2 (MINOR · 출력 포맷) — PPTX 표의 행도 탭으로 잇는다 — **스펙에 흡수됨**

- 맥락: 스펙 §4.2 는 「표 셀 텍스트를 재귀로 훑는다」까지만 정하고 셀 구분자를 정하지 않는다.
  엑셀 쪽에는 탭 구분과 「행 끝 빈 셀은 탭을 남기지 않는다」 규칙(T2)이 명시돼 있다.
- 결정: 엑셀의 `_tab_joined_row()` 를 PPTX 표가 그대로 재사용한다.
- 근거: 둘 다 「행 × 셀」 구조이고, 표기가 갈리면 같은 표를 담은 `.xlsx` 와 `.pptx` 가 서로 다른
  요약 입력을 만든다. 규칙이 한 함수에만 있으면 나중에 바뀌어도 두 포맷이 함께 따라온다.

### M3 (MINOR · 출력 포맷) — 노트만 있는 슬라이드도 경계 줄을 받는다 — **스펙에 흡수됨**

- 맥락: 스펙 §4.2 T1 은 「내용이 있는 슬라이드에만 경계 줄」을, 별도 항목에서 「노트가 공백뿐이면
  `[노트]` 줄도 내지 않는다」를 정한다. 도형은 없고 노트만 있는 슬라이드는 두 문장 어디에도
  명시돼 있지 않다.
- 결정: 노트도 내용으로 세어 `[슬라이드 N]` 경계 줄을 낸 뒤 `[노트]` 블록을 잇는다.
- 근거: 경계 줄의 의미가 「뒤에 내용이 온다」이므로, 뒤에 노트가 오면 신호가 필요하다. 반대로
  하면 `[노트]` 블록이 어느 슬라이드 것인지 알 수 없는 채로 놓인다. 「도형이 없으면 무조건
  생략」은 이미지만 있는 슬라이드를 겨냥한 규칙이지 노트를 버리라는 규칙이 아니다.

### C1 (CORE · 아키텍처) — 오피스 추출기의 예외 흡수 범위를 열거하지 않고 `Exception` 전체로 둔다 — **스펙에 흡수됨**

- 맥락: 스펙 §4.3 은 「손상·파싱 실패 → `extraction_failed` + detail」만 정하고 어떤 예외를
  잡을지는 정하지 않는다. 최초 구현은 기존 `.docx`/`.pdf` 관용구를 따라
  `(InvalidFileException, BadZipFile, OSError, ValueError, KeyError)` 를 열거했다.
- 문제: 그 목록은 «zip 이 아닌 쓰레기 바이트» 만 덮었다. 컨테이너는 열리는데 안쪽 XML 이
  잘린 경우 — 실사용에서 훨씬 흔하다 — `openpyxl` 은 `xml.etree.ElementTree.ParseError`,
  `python-pptx` 는 `lxml.etree.XMLSyntaxError` 를 올리는데 **둘 다 `SyntaxError` 하위**라
  목록 어디에도 걸리지 않고 코어 밖으로 탈출했다. 실측에서 손상 파일 하나가 스캔 전체를
  중단시켜 같은 폴더의 정상 `.txt` 가 처리되지 못했다 — v0.1 §5 의 「개별 파일 실패는 전체
  실패로 위장하지 않는다」 위반이다. 게다가 손상되지도 않은 **차트시트 통합문서**가
  `openpyxl` 3.1.5 내부 `AttributeError` 로 죽는다.
- 결정: 열거를 늘리지 않고 `_OFFICE_ERRORS = Exception` 으로 범위를 넓힌다.
- 근거: 이 경계는 **제3자 파서에게 신뢰할 수 없는 이진 입력을 먹이는 자리**여서 무엇이
  올라올지 미리 셀 수 없다. 열거를 늘리는 것은 같은 사고를 다음 라이브러리 버전으로 미루는
  일이다. `BaseException` 이 아니라 `Exception` 이므로 `KeyboardInterrupt`·`SystemExit` 은
  그대로 통과해 사용자의 중단 요청이 「추출 실패」로 둔갑하지 않는다.
- 대가: 추출기 루프 안 우리 코드의 버그도 `extraction_failed` 로 흡수될 수 있다. 그 코드
  (`_cell_text`·`_tab_joined_row`)는 단위테스트가 따로 덮으므로 감당 가능하다고 본다.
- CORE 로 분류한 이유: 기존 추출기 3종의 관용구(열거)와 갈라지는 선택이라 아키텍처 결정이다.

### M4 (MINOR · 판정 기준) — 엑셀 행의 「내용 없음」 판정을 공백까지 포함하도록 넓힌다 — **스펙에 흡수됨**

- 맥락: 스펙 §4.2 T2 표는 「내용 없음」의 기준을 `None`(빈 셀)로 적는다. 구현은 그대로
  `if not line` 을 썼다.
- 문제: `_tab_joined_row()` 는 **빈** 셀만 뒤에서 떼어내므로 `" "` 같은 값은 살아남는다.
  공백만 든 통합문서의 추출 결과가 `'[시트: 서식만]\n \t  \n\t'` 가 되어 호출자의
  `text.strip()` 검사를 통과했다 — §4.2 T1 이 막으려던 실패가 `None` 이 아니라 공백을 통해
  그대로 재현된다. 같은 파일의 PPTX 표 경로는 이미 `if line.strip()` 을 쓰고 있었다.
- 결정: 엑셀 행 필터를 `if not line.strip()` 으로 바꿔 두 추출기를 통일한다.
- 근거: T1 이 지키려던 성질(경계 줄만 남아 빈 판정을 통과하지 않는다)을 문면(`None`)이 아니라
  의도대로 성립시킨다. 빈 판정 책임은 여전히 호출자에 있다 — 추출기는 「내용이 없다」를
  빈 문자열로 표현할 뿐이다.
- **후속 [2026-08-27]**: `/spec-check` 가 이 항목을 드리프트 **D3** 로 분리 보고했고(스펙 T2 표의
  문면은 `None`, 구현은 공백 포함), 사용자가 **스펙을 넓히는 쪽**으로 결정했다. 스펙 §4.2 의 행
  필터 문장과 T2 표에 반영됐으므로 이 항목은 더 이상 «정본에 없는 결정» 이 아니다. 카운터에는
  남겨 둔다 — 결정이 있었다는 사실 자체는 기록이다.

### 드리프트 해소 요약 [2026-08-27]

`/spec-check` 가 M2·M3·M4 를 각각 드리프트 **D1·D2·D3** 로 분리 보고했고, 사용자가 셋 다
**스펙을 구현 쪽으로 넓히는** 결정을 내렸다. 스펙 §4.2 에 반영됐으므로 셋 다 더 이상 «정본에
없는 결정» 이 아니다.

**C1 도 같은 이유로 스펙 §4.3 에 흡수했다** — 스펙 상태를 「완료」(= 구현이 스펙과 일치)로
옮기는 마당에, 스캔 전체가 죽는 것을 막는 계약이 체크포인트에만 있으면 나중에 누군가
「관용구대로 예외를 열거하자」고 되돌려 그 결함을 되살릴 수 있다. **코드 변경은 없었다** — 세 건 모두 구현이 이미 옳았고 문면이 따라온 것이다.
카운터에는 남겨 둔다 — 결정이 있었다는 사실 자체는 기록이다.

### C2 (CORE · 아키텍처) — 예외 흡수 범위 통일을 `.docx`·`.pdf` 까지 넓힌다

- 맥락: C1 은 오피스 2종만 `Exception` 범위로 넓혀 기존 3종의 「열거」 관용구와 갈라져 있었다.
  리뷰에서 이 갈라짐 자체를 논점으로 올렸고, 확인 결과 **손상된 `.docx` 가 같은 방식으로 새고
  있었다** — zip 은 열리는데 `word/document.xml` 이 깨진 파일에서 `lxml.etree.XMLSyntaxError`
  가 탈출한다(2026-08-27 실측). `main` 에 이미 있던 결함이며 이 슬라이스가 만든 것이 아니다.
- 결정: `_EXTRACTOR_ERRORS = Exception` 을 **네 추출기 전부**가 쓴다. [사용자 결정]
- 근거: 열거가 부족하다는 근거가 `.docx` 에도 그대로 적용된다. 갈라 두면 같은 저장소 안에서
  `.xlsx` 는 안전하고 `.docx` 는 안 안전한 상태가 굳고, 다음 사람이 「왜 오피스만 다르지」에서
  잘못된 쪽으로 통일할 위험이 있다. `.pdf` 는 실측에서 누수가 재현되지 않았으나 열거가 덮지
  못하는 예외(`zlib.error`·`RecursionError` 등)는 같으므로 관용구 통일에 포함한다.
- 함께 넣은 것: 순회 단계에 `except ExtractionError: raise` 를 앞세워 **이미 우리 계약인 예외를
  다시 감싸지 않게** 했다. 감싸면 원래 detail 이 일반 문구로 덮여 사라진다. 지금은 도달 불가한
  경로지만 추출기 내부 로직이 커지면 조용히 깨질 자리였다.
- CORE 로 분류한 이유: C1 과 같은 종류의 아키텍처 결정이며 적용 범위가 기존 포맷까지 넓어졌다.

### M5 (MINOR · 출력 포맷) — 표기 규칙의 빈틈 3건을 닫는다 — **스펙에 흡수됨**

리뷰 준비 중 실측으로 찾아 사용자 결정으로 고친 셋. 셋 다 스펙 §4.2 에 반영됐다.

- **`time`·`timedelta`**: T2 표가 다섯 타입만 정해 시각·기간 서식 셀이 `str()` 폴백에 걸렸다.
  `14:30:00`·`1 day, 2:00:00` 이 그대로 요약 입력에 들어갔다 — `120000.0` 을 없애려던 그 표의
  취지와 같은 잡음이다. 각각 `HH:MM`(초는 `datetime` 규칙에 맞춰 버림)·`H:MM`(엑셀 `[h]:mm` 과
  같은 총 시간:분)으로 적는다.
- **줄 경계 절단**: `[:max_chars]` 가 경계 줄을 반토막 냈다(`"[시트: 아주긴시트"`). 줄 경계로만
  자르고, 뒤에 내용이 남지 않은 경계 줄은 함께 뺀다. 경계 줄조차 안 들어가면 빈 문자열이다 —
  그냥 자르면 반토막 마커만 남고 내용은 한 글자도 못 실린다.
- **공백의 범위**: M4 로 넓힌 「공백」이 `str.strip()` 기준이라 전각 공백(U+3000)·NBSP 를
  포함한다는 사실이 문면에 없었다. 명시했다.
