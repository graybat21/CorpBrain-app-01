# 스펙: CorpBrain v0.9 — 로컬 웹 GUI (조회 + 스캔 실행 · 멀티 워크스페이스)

- 상태: 구현 완료 (실사용 피드백 반영 중)
- 최종 갱신: 2026-09-02 (실사용 피드백 — §4.7 `reveal` 추가 · §4.9 「원문」 표기 ·
  §4.8 탐색 목록을 폴더 트리로)

## 1. 목표
v0.1~v0.8로 완성된 코어 파이프라인을 CLI를 모르는 사용자도 쓸 수 있도록, `corpbrain gui`
실행 시 로컬 웹서버가 뜨고 브라우저가 열리는 **두 번째 어댑터**를 얹는다. v0.1 스펙 §4.5가
"이후 UI는 같은 코어를 호출하는 또 다른 어댑터로 붙는다"고 약속한 이음새를 실제로 쓰는
슬라이스다. 사용자는 브라우저에서 워크스페이스를 만들고, 폴더를 골라 스캔을 돌리고 진행
상황을 보며, 생성된 위키를 검색·열람·편집하고 지식그래프를 탐색한다. 코어는 한 줄도
고치지 않으며, 로컬 우선 원칙과 단일 게이트웨이 불변식은 그대로 유지된다. [사용자 결정]

## 2. 비목표
이번 슬라이스에서 다음은 하지 않는다.

- **pywebview 데스크톱 창.** 웹 브라우저만 쓴다. v0.1 스펙 §2가 "UI(pywebview·React)"로
  묶어 둔 것 중 pywebview 경로는 열지 않는다. [제안 후 승인]
- **원격 접속·다중 사용자·계정.** 서버는 `127.0.0.1`에만 바인딩한다. [제안 후 승인]
- **그래프 수동 편집**(노드·엣지 추가·삭제). 그래프는 스캔이 파생하는 것이지 사람이 짓는
  것이 아니다. v0.6이 세운 "재료와 파생물을 분리한다"와 같은 잣대다. [제안 후 승인]
- **RAG 답변 생성.** 검색 결과를 LLM이 요약해 답하는 기능은 코어에도 없다. [제안 후 승인]
- **프론트엔드 E2E 자동 테스트**(Playwright 등)와 JS 단위 테스트. 파이썬 단일 툴체인을
  유지한다(§3 검증 방식). [사용자 결정]
- **워크스페이스 개념의 코어·CLI 편입.** 이번엔 GUI만 안다. CLI에 `--workspace`를 만들지
  않고 `corpbrain/core/`에 워크스페이스 모듈을 두지 않는다. 필요해지면 후속 버전에서
  코어로 승격한다. [사용자 결정]
- **코어 수정.** `run_scan`을 비롯한 코어 공개 API의 시그니처·동작을 바꾸지 않는다.
  GUI 때문에 코어에 취소 이음새를 넣지 않는다. [사용자 결정]
- **`ProgressEvent`·`StatusSnapshot`의 공개 API 승격.** `corpbrain-run-status-observability.md`
  §2가 [사용자 결정]으로 금지한 것을 뒤집지 않는다. §4.5의 프로세스 분리로 승격 없이
  성립시킨다. [제안 후 승인]
- **React·번들러·Node 툴체인.** 프론트엔드는 빌드 없는 Vanilla JS다. [사용자 결정]
- **외부 CDN.** 폰트·아이콘·그래프 엔진을 포함해 모든 정적 자산을 로컬에 둔다.
  [제안 후 승인]

## 3. 완료의 정의
아래를 모두 만족한다. 프론트엔드 화면 동작을 제외한 전 항목이 `pytest`로 기계 판정된다.

1. `corpbrain gui --no-browser` 실행 시 서버가 **`127.0.0.1`에만 바인딩**되고 다른
   인터페이스로는 접속되지 않는다.
   - 검증: 바인딩 주소를 단언하고, `0.0.0.0`·LAN IP 바인딩이 발생하지 않음을 확인한다.
2. 토큰 없는 모든 `/api/*` 요청이 **401**, `Host` 헤더가 허용 목록 밖이면 **403**이다.
   - 검증: 엔드포인트 목록을 순회해 토큰 없이 401, 위조 `Host`로 403을 단언한다.
3. 워크스페이스 생성 → 스캔 실행 → 완료까지가 **HTTP 요청만으로** 통과한다.
   - 검증: 코어를 스텁한 상태에서 핸들러를 in-process로 호출하는 통합테스트.
4. 스캔이 도는 중 검색 요청이 **409**를 받고, 트레이스백이 응답에 노출되지 않는다.
   - 검증: 스캔 상태를 진행 중으로 만든 뒤 검색 요청의 상태코드와 본문을 단언한다.
5. 중지 요청 후 자식 프로세스가 **실제로 종료**된다.
   - 검증: 러너를 대신하는 더미 프로세스를 띄워 중지 후 `poll()`이 `None`이 아님을 단언.
6. 정적 자산(HTML·CSS·JS) 어디에도 **외부 URL 참조가 0건**이다.
   - 검증: 정적 파일 전체를 읽어 `http://`·`https://`·`//cdn` 패턴이 없음을 단언한다.
     `127.0.0.1`·`localhost` 문자열은 표시용 텍스트로만 허용한다.
7. 서버가 제공하는 정적 파일 목록이 **기대 집합과 정확히 일치**한다.
   - 검증: 정적 디렉터리 목록과 기대 집합을 동등 비교한다.
8. 마크다운 렌더러에 `<script>`가 든 입력을 넣으면 **이스케이프되어** 나온다.
   - 검증: 렌더러 단위테스트에서 `<script>`·`onerror=`·`javascript:` 입력의 출력을 단언.
9. 위키 편집 저장 시 `corpbrain:related` 마커 블록이 보존되지 않으면 **400**으로 거절한다.
   - 검증: 마커를 지운 본문을 PUT 해 상태코드를 단언하고, 파일이 바뀌지 않았음을 확인한다.
10. **네트워크 불변식 유지** — `corpbrain gui` 기동과 API 처리에서 나가는 소켓 목적지가
    localhost뿐이다.
    - 검증: `tests/security/test_network_invariant.py`에 케이스를 **추가**한다. 새 파일로
      분리하지 않는다 — 소켓 패치 관용구가 복제되고, 감시장치가 공허하게 통과하지 않음을
      증명하는 `test_watcher_flags_a_gateway_bypass`의 보호를 받지 못한다(v0.6·v0.7·v0.8
      결정 계승).
11. `uv run ruff check .`와 `uv run pytest`가 exit 0이다.
    - 검증: 두 명령의 종료 코드.
12. 화면 동작은 `docs/SMOKE.md`의 체크리스트로 수동 확인한다.
    - 검증: 자동 판정 대상이 아니다. 체크리스트 존재 자체를 완료 조건으로 삼는다.

**검증 방식(전반)** [사용자 결정]: 서버 핸들러는 **in-process로 직접 호출**해 테스트한다.
`tests/security/test_network_invariant.py`의 `watch_sockets` 픽스처는 `socket.connect`를
무조건 `ConnectionRefusedError`로 만들므로, 그 픽스처 안에서 HTTP 클라이언트로 자기 서버에
접속하는 테스트는 **원리적으로 불가능하다.** 어댑터 테스트는 `tests/test_cli.py`가 파싱과
실행을 분리해 검증하는 관용구를 계승한다.

**테스트 배치** [제안 후 승인]: 서버 어댑터 테스트는 `tests/test_gui_server.py`,
마크다운 렌더러·워크스페이스 저장소 같은 순수 로직은 `tests/unit/` 아래에 둔다. 기존
`tests/test_cli*.py`와 같은 층위다.

## 4. 인터페이스 계약

### 4.1 CLI [제안 후 승인]
```
corpbrain gui
  --port N          기본 8765 (사용 중이면 다음 빈 포트를 자동으로 잡는다)
  --no-browser      브라우저를 자동으로 열지 않는다
```
- 바인딩 주소는 **`127.0.0.1` 고정**이며 플래그로 바꿀 수 없다 [사용자 결정]. 보안
  불변식 테스트가 localhost 외 목적지를 offender로 잡으므로 사실상 강제되는 값이고,
  옵션으로 열어 두면 그 강제가 무의미해진다.
- 기동 시 stderr에 접속 URL(토큰 포함)을 한 줄 낸다. `--no-browser`여도 낸다.
- 종료 코드: 기동 실패(포트 전부 사용 중 등)는 1, 정상 종료는 0.

### 4.2 아키텍처와 프로세스 모델 [사용자 결정]
- 서버는 **표준 라이브러리 `http.server.ThreadingHTTPServer`** 로 구현한다. 신규 런타임
  의존성을 `pyproject.toml`에 추가하지 않는다 — 게이트웨이가 세운 "서드파티 HTTP 의존성을
  두지 않는다"를 유지하고 `uv.lock`·CI를 그대로 둔다.
- **코어를 수정하지 않는다.** GUI는 `corpbrain.core`의 공개 API만 호출하는 두 번째
  어댑터다.
- 스캔은 **별도 프로세스**로 실행한다. 코어에 협조적 취소 이음새가 없고
  (`run_scan`은 동기 블로킹이며 `on_event` 콜백의 예외를 삼킨다), `tests/test_core_api_smoke.py`가
  `run_scan`의 파라미터 목록을 정확히 일치로 단언해 인자를 더할 수 없기 때문이다.
  **중지는 자식 프로세스 종료로 구현한다.**
- GUI 모듈은 **`corpbrain/gui/`** 아래에 둔다. `corpbrain/core/` 안에 넣지 않는다 —
  `tests/test_core_api_smoke.py`가 "코어를 import 해도 CLI가 딸려 오지 않음"을 단언하며,
  같은 격리를 GUI에도 유지한다. [제안 후 승인]
- 서버 프로세스는 `cli.main()`을 재사용하지 않는다. `cli._force_utf8_output()`이 전역
  `sys.stdout`을 재구성하고 `_log()`가 stderr에 직접 쓰기 때문이다. 코어를 직접 호출한다.
  [제안 후 승인]

### 4.3 진행 상황 전달 [사용자 결정]
- **1초 폴링**이다. SSE를 쓰지 않는다. 문서 1개 요약에 수십 초가 걸리는 작업이라
  실시간성의 이득이 없는 반면, SSE는 연결마다 서버 스레드를 점유하고 broken pipe·재접속·
  놓친 이벤트 복구를 직접 다뤄야 한다.
- 자식 프로세스는 `ProgressEvent.to_dict()`를 **JSON 한 줄씩** stdout에 쓴다. 서버가 이를
  읽어 `corpbrain.core._progress.reduce()`로 접어 스냅샷 하나로 보관하고, 폴링 요청에 그
  스냅샷을 돌려준다.
- `render_status_line()`은 쓰지 않는다 — CLI 한 줄 텍스트 전용이며, GUI는 스냅샷 필드를
  화면에 직접 바인딩한다. [제안 후 승인]
- 이 구조 덕분에 **`ProgressEvent`를 공개 API로 승격할 필요가 없다.** `_progress`를 import
  하는 것은 자식 프로세스(러너)뿐이고, 러너는 `corpbrain` 패키지 내부 모듈이라
  `_progress.py`가 허용한 "패키지 내부는 직접 import 한다"에 해당한다. 서버는 JSON dict만
  다룬다. [제안 후 승인]

#### 4.3.1 스냅샷의 수명 [사용자 결정 · grill T3]
- 스캔이 도는 동안의 스냅샷은 **메모리**에 둔다(폴링 대상).
- 스캔이 끝나면 결과를 **`<out_dir>/.corpbrain_gui_lastrun.json`** 에 기록한다. 워크스페이스당
  **마지막 1회만** 보관하며 이력을 쌓지 않는다.
- 서버 기동 시 각 워크스페이스의 이 파일을 읽어 「마지막 스캔」 정보를 복원한다. 탭을 닫았다
  열어도, 서버를 껐다 켜도 직전 결과를 다시 볼 수 있다.
  - 근거: 스캔은 수십 분이 걸리고 그동안 탭을 닫아 두는 것이 자연스럽다. 결과를 메모리에만
    두면 §5의 "성공했지만 N건 스킵됨을 반드시 렌더한다"가 사실상 무력해진다 — 사용자가 그
    화면을 볼 기회를 놓친다.
- 파일 이름은 기존 두 저장소(`.corpbrain_index.sqlite`·`.corpbrain_graph.sqlite`)와 같은
  «`out_dir` 아래 숨김 파일» 관용구를 따른다. 지워도 다음 스캔이 다시 만들며, 없다고
  실패하지 않는다.
- 쓰기는 §4.5의 원자적 교체를 쓴다. 스캔 종료 직후 한 번만 쓰므로 비용이 없다.
- **이 파일은 스캔 결과의 표시용 사본이다.** 그래프·인덱스·위키의 정본이 아니며, 어떤 조회도
  이 파일을 근거로 답하지 않는다 — 「조회는 저장된 값을 읽기만 한다」 불변식은 그대로다.

### 4.4 러너 프로토콜 [제안 후 승인]
- 자식 프로세스는 `python -m corpbrain.gui.runner`로 띄운다.
- 입력: `ScanConfig`에 해당하는 값을 **JSON으로 stdin**에 넘긴다. 명령줄 인자로 넘기지
  않는다 — 경로에 공백·비ASCII가 흔하고 프로세스 목록에 노출된다.
- 출력: stdout에 **JSON 한 줄 = 이벤트 하나**. 이벤트는 `ProgressEvent.to_dict()`이며,
  마지막에 §4.4.1의 **종료 레코드** 한 줄을 낸다.
- stderr는 진단용으로 그대로 흘리고 서버가 마지막 N줄만 보관한다.
- 종료 코드는 CLI와 같은 매핑을 쓴다 — 0 정상, 1 선행 조건 실패, 3 자원 게이트 차단.

#### 4.4.1 종료 레코드 [사용자 결정 · grill T4]
`ScanResult`를 **손실 없이** 직렬화한다. 필드를 골라 버리지 않는다 — 무엇을 버릴지 지금
정하면 화면을 손볼 때마다 이 결정으로 되돌아오게 되고, `--max`(기본 50) 규모에서 크기 차이는
수십 KB에 불과하다.

`ScanResult`는 `Path`와 `StrEnum`을 품고 있어 `dataclasses.asdict()`만으로는 JSON이 되지
않는다. **변환 규칙을 못박는다:**

| 원래 타입 | JSON 표현 |
|---|---|
| `Path` | **절대경로 문자열** (§4.5의 절대경로 규칙과 같다) |
| `StrEnum` (`SkipReason`·`IndexingSkipReason`·`GraphSkipReason`) | 멤버의 값 문자열 |
| `None` | `null` |
| 중첩 dataclass (`GraphOutcome`·`GraphStats`·`SkippedFile` 등) | 중첩 객체 그대로 |

- `GraphStats.nodes`·`edges`는 **프로퍼티라 `asdict()`에 포함되지 않는다.** 화면이 총계를
  쓰므로 직렬화 시 명시적으로 더한다.
- 레코드는 위 필드에 더해 `schema`(레코드 형식 버전) · `finished_at`(ISO8601) ·
  `exit_code` · `workspace_id`를 담는다. 이 넷은 `ScanResult`에 없는 어댑터 정보다.
- 같은 레코드가 §4.3.1의 `.corpbrain_gui_lastrun.json`에 그대로 저장된다. **직렬화 형식이
  하나뿐이라** 러너 출력과 저장 파일이 갈리지 않는다.
- `schema`가 이번 버전과 다른 `lastrun.json`은 **읽지 않고 무시한다**(파일이 없는 것과 같이
  다룬다). 표시용 사본이므로 자동 복구도 오류도 필요 없다 — 다음 스캔이 덮어쓴다. 저장소
  스키마 불일치를 오류로 다루는 v0.4·v0.6 방침과 갈리는 지점이며, **정본이 아니기 때문에**
  갈라도 된다.

### 4.5 워크스페이스 저장소 [사용자 결정]
- 워크스페이스 목록은 **`~/.corpbrain/workspaces.json`** 에 둔다. 코어는 이 파일을 모른다.
- 항목 하나의 필드: `id`(불변 식별자) · `name`(표시 이름) · `source_dir`(스캔 대상) ·
  `out_dir`(위키·인덱스·그래프 위치) · `created_at` · `last_options`.
- **`last_options` — 워크스페이스별 스캔 설정** [사용자 결정 · grill T6]: 스캔을 실행할 때
  쓴 옵션을 여기 남기고, 다음에 그 워크스페이스를 열면 §4.7.1의 폼에 미리 채운다. 폴더마다
  성격이 다르면 실행 옵션도 달라지는 것이 자연스럽고, 매번 다시 입력하게 하면 「고급」이
  사실상 쓰이지 않게 된다.
  - **`force`와 `force_gates`는 저장하지 않는다.** 둘 다 「이번 한 번만」의 성격이라 조용히
    유지되면 놀란다 — 어제 켠 `force`가 오늘도 켜져 있으면 전체 재요약이 돌아 LLM 비용이
    예기치 않게 발생하고, `force_gates`는 막으라고 둔 게이트를 계속 무력화한다. 이 둘은
    **매번 꺼진 채로 시작**한다.
  - `last_options`가 없거나 필드가 빠져 있으면 코어 기본값을 쓴다. 서버가 값을 지어내지
    않는다(§4.7.1과 같은 규칙).
- **경로는 언제나 절대경로로 저장·전달한다.** 서버는 상대경로를 받지 않는다 [제안 후 승인]
  — 브라우저가 보낸 `./inbox`는 서버 프로세스의 cwd 기준으로 풀려 사용자가 의도하지 않은
  폴더를 가리킨다. 경로 해석은 어댑터의 책임이라는 코어 불변식을 GUI도 그대로 진다.
- 쓰기는 **원자적**이다 — 같은 디렉터리의 임시 파일에 쓰고 `fsync` 후 `os.replace`로
  교체한다. `corpbrain/core/consent.py`의 관용구를 그대로 계승한다. [제안 후 승인]
- 클라우드 동의는 워크스페이스별로 갈리지 않는다. `~/.corpbrain/config.json`의 **전역 단일
  파일**을 그대로 쓴다. [제안 후 승인]

### 4.6 보호 [사용자 결정]
- 기동할 때마다 **랜덤 토큰**을 생성한다. 브라우저는 토큰이 담긴 URL로 열리고, 이후 모든
  `/api/*` 요청은 토큰을 요구한다. 토큰이 없거나 틀리면 **401**.
- **`Host` 헤더를 검증한다.** `127.0.0.1:<port>` 및 `localhost:<port>` 외의 값이면 **403**.
  DNS rebinding을 막는다.
- 근거: `127.0.0.1` 바인딩은 다른 머신만 막을 뿐, 같은 컴퓨터의 다른 프로그램과 브라우저의
  다른 탭은 막지 못한다. 이 서버는 로컬 파일시스템을 탐색하고 문서 본문을 그대로 돌려주므로
  정보 유출 표면이 있다.
- 토큰은 파일에 저장하지 않는다. 프로세스가 살아 있는 동안만 유효하다. [제안 후 승인]

#### 4.6.1 토큰을 어디에 싣는가 [사용자 결정 · grill T5]
- **첫 진입(`GET /`)만 URL 쿼리스트링**으로 받는다. 브라우저가 최초 요청에 커스텀 헤더를
  붙일 방법이 없으므로 여기서는 URL 외의 수단이 없다.
- 페이지는 토큰을 읽어 **메모리(JS 변수)에** 두고, 이후 모든 `/api/*` 요청에 **커스텀
  헤더**로 싣는다.
- 토큰을 읽은 직후 `history.replaceState()`로 **주소창에서 토큰을 제거한다.** 브라우저
  히스토리·북마크·화면 공유에 남지 않게 한다.
- **토큰은 `sessionStorage`에 둔다** [사용자 결정 · 2026-09-01 정정]. 같은 탭 안에서만
  유지되며 탭을 닫으면 사라진다.
  - **초판은 «어디에도 저장하지 않는다 — 새로고침하면 첫 진입 URL을 다시 거치는 것이 의도된
    동작»이라고 적었으나, 실사용에서 그 마찰만 남고 얻는 것이 없었다.** CSRF를 막는 것은
    **커스텀 헤더**이지 토큰의 수명이 아니다 — 다른 사이트의 스크립트는 우리 헤더를 붙일 수
    없고, `sessionStorage`는 출처별로 격리돼 읽을 수도 없다. 쿠키였다면 브라우저가 다른 탭의
    요청에도 자동으로 붙여 보내 방어가 무너지지만 `sessionStorage`는 그렇지 않다.
  - **`localStorage`는 여전히 쓰지 않는다.** 탭을 닫으면 사라져야 서버가 꺼진 뒤 죽은 토큰이
    디스크에 남지 않는다.
  - 저장소 접근이 막힌 환경(사생활 보호 모드 등)에서는 저장을 포기하고 그 세션만 동작한다 —
    화면이 통째로 실패하지 않는다.
- **쿠키를 쓰지 않는 이유**: 브라우저는 쿠키를 **다른 탭에서 온 요청에도 자동으로 붙여
  보낸다.** 그러면 §4.6이 토큰을 도입한 목적(다른 탭의 스크립트가 이 API를 때리는 것을
  차단)이 정면으로 무효가 된다. 커스텀 헤더는 다른 출처가 붙일 수 없어 그 목적을 실제로
  달성한다.
- **쿼리스트링을 계속 쓰지 않는 이유**: CSRF는 막지만 토큰이 서버 접근 로그·브라우저
  히스토리·`Referer` 헤더에 그대로 남는다.

### 4.7 HTTP API [제안 후 승인]
모든 엔드포인트는 토큰과 `Host` 검증을 통과해야 하며, 요청·응답 본문은 JSON이다.
`{ws}`는 워크스페이스 `id`다.

| 메서드·경로 | 하는 일 |
|---|---|
| `GET /api/workspaces` | 워크스페이스 목록 |
| `POST /api/workspaces` | 등록 (`name`·`source_dir`·`out_dir`) |
| `DELETE /api/workspaces/{ws}` | 목록에서 제거 (파일은 지우지 않는다) |
| `GET /api/fs/list?path=` | 폴더 탐색 — 하위 디렉터리 목록 |
| `GET /api/workspaces/{ws}/dashboard` | 현황 — 위키 수·그래프 통계·마지막 스캔 시각 |
| `GET /api/workspaces/{ws}/plan` | 스캔 전 견적 (`plan_scan`) |
| `POST /api/scan` | 스캔 시작 (`ws` + 실행 옵션) |
| `GET /api/scan` | 진행 상태 스냅샷 (1초 폴링 대상) |
| `DELETE /api/scan` | 중지 |
| `GET /api/workspaces/{ws}/search?q=&top_k=` | 검색 (`search_index`) |
| `GET /api/workspaces/{ws}/wiki` | 위키 트리 |
| `GET /api/workspaces/{ws}/wiki/{경로}` | 위키 한 장 — 렌더된 HTML과 원문을 함께 |
| `PUT /api/workspaces/{ws}/wiki/{경로}` | 편집 저장 |
| `GET /api/workspaces/{ws}/graph` | 그래프 전체 노드·엣지 |
| `GET /api/workspaces/{ws}/graph/neighbors?doc=` | 한 문서의 이웃 |
| `PUT /api/workspaces/{ws}/options` | 실행 옵션 **부분 갱신** (보낸 키만 바꾼다) |
| `DELETE /api/workspaces/{ws}/index` | 검색 데이터(벡터 인덱스)만 삭제 |
| `POST /api/workspaces/{ws}/reveal` | 원본이 있는 폴더를 파일 탐색기로 열기 |
| `GET /api/models` | 설치된 Ollama 모델 목록 + 지금 실제로 쓰일 모델 |
| `GET /api/doctor` | 환경 점검 (`diagnose`) |
| `GET /api/settings/cloud` | 동의 상태·엔진 설정 조회 |
| `PUT /api/settings/cloud` | 동의 부여·철회 |

- **폴더 탐색 API가 필요한 이유**: 브라우저는 로컬 경로를 서버에 줄 수 없다.
  `<input type="file" webkitdirectory>`는 파일을 업로드할 뿐 경로를 주지 않는다. 따라서
  서버가 디렉터리 목록을 돌려주고 사용자가 화면에서 폴더를 고른다.
- **`--neighbors` 경로 해석**은 CLI가 하는 것과 같은 규칙을 GUI 어댑터가 진다 —
  위키 상대경로 → 원문 상대경로 → 절대경로 순으로 시도하고, `out_dir` 하위일 때만 위키로
  인정한다. 코어는 경로 해석 책임을 지지 않는다.
- 그래프 전체를 한 번에 돌려주는 것은 `--max`(기본 50) 규모에서 문제되지 않는다. v0.6이
  전 쌍 코사인에 대해 같은 근거로 별도 상한을 두지 않은 것과 같다.
- **옵션 저장은 부분 갱신이다** [사용자 결정 · 2026-09-01 추가]. 통째로 교체하면 설정
  화면이 모델 두 개만 보낼 때 `engine`·임계치 같은 다른 저장값이 함께 지워진다.
- **하위 경로가 있는 DELETE는 워크스페이스 삭제로 잡지 않는다** [2026-09-01 추가]. 경로
  마지막 조각만 보면 `DELETE .../{id}/index` 의 `index` 를 워크스페이스 id로 읽는다.
- **`POST …/reveal` 은 폴더를 열 뿐 파일을 실행하지 않는다** [사용자 결정 · 2026-09-02 추가].
  브라우저는 `http://` 페이지에서 `file://` 링크를 **오류도 없이 조용히 무시하므로**, 위키
  본문의 「원문」 링크는 처음부터 눌러도 아무 일이 없는 죽은 링크였다. 브라우저가 못 하는
  일이라 서버가 대신 연다.
  - **파일을 실행하지 않는다.** 요청 한 번이 매크로가 든 통합문서나 실행 파일을 띄우는
    통로가 되면 안 된다. 파일 탐색기에서 **그 파일을 고른 채 폴더를 열고**, 실제로 여는
    것은 사용자가 한다.
  - 경로는 **절대경로**여야 하고 **그 워크스페이스의 `source_dir`·`out_dir` 안**이어야
    한다. 그러지 않으면 토큰을 쥔 쪽이 컴퓨터의 아무 폴더나 열 수 있다.
  - 원본이 사라졌으면 상위 폴더를 열고 그 사실을 응답에 담는다 — 「어디에 있던 문서인가」를
    보여 주는 것이 목적이므로 실패로 만들지 않는다.
- **`GET /api/models` 는 Ollama 가 꺼져 있어도 오류가 아니다.** 목록이 비고 `available:
  false` 가 온다 — 데몬이 없다는 사실은 환경 점검이 이미 말해 주며, 여기서 400을 내면 설정
  화면이 통째로 실패한다. 「지금 실제로 쓰일 모델」(`resolved`)은 그때도 답한다. 그건 설정이지
  조회가 아니기 때문이다.

#### 4.7.1 스캔 옵션의 노출 [사용자 결정 · grill T1]
`POST /api/scan`의 요청 본문은 `ScanConfig`의 15필드 전부를 받을 수 있으나, **화면은 3단으로
나누어 낸다.** CLI 플래그 13개를 평면으로 늘어놓으면 §4.8의 「간결한 메뉴」 결정과 정면으로
부딪힌다.

| 단계 | 항목 |
|---|---|
| **항상 보임** | 엔진(`local`/`cloud`) |
| **「고급」 접기** | 강제 재생성 · 게이트 무시 · 스캔 상한 · 문서당 글자수 · 개별 파일 크기 · 총 토큰 예산 · 유사도 임계치 · 관련 문서 개수 |
| **설정 화면에만** | 요약 모델 · 임베딩 모델 |
| **노출하지 않음** | `folder`·`out_dir`(워크스페이스가 소유) · `ollama_url` |

**모델은 설정 화면 한 곳에서만 고른다** [사용자 결정 · 2026-09-01 정정]. 초판은 요약 모델을
「항상 보임」에, 임베딩 모델을 「고급」에 두었으나 둘 다 옮겼다.

- **임베딩 모델**은 한 번 실행의 옵션이 아니라 **인덱스 전체의 속성**이다. 스캔마다 바꾸면
  코어가 «다른 임베딩 모델로 생성된 인덱스»로 막으므로, 그 자리에 두면 «고르면 반드시
  실패하는 항목»이 된다.
- **요약 모델**을 스캔 화면에서 고르게 하면 엔진이 클라우드일 때 모순이 생긴다 —
  `ScanConfig`는 `model`(Ollama)과 `cloud_model`(Anthropic)을 따로 갖고 엔진에 따라 하나만
  쓰는데, Ollama 모델만 나열하는 드롭다운은 클라우드를 고른 순간 **아무 효과가 없는
  컨트롤**이 된다.
- 대신 스캔 화면은 **엔진이 실제로 쓸 모델을 읽기 전용으로 표시**하고, 그 옆에 설정으로
  데려가는 버튼을 둔다. 고르는 컨트롤이 아니라 결과를 보여 주는 자리다.
- 화면의 모델 선택은 **설치된 모델 목록에서 고르는 드롭다운**이며 자유 입력이 아니다.
  오타로 없는 모델을 적어 스캔이 실패하는 일을 없앤다. 비워 둘 수 없다 — 언제나 구체적인
  모델 하나가 선택돼 있다.

- 접기 영역은 `gui_preview/variants/minimalist`가 게이트 토글 3개를 `<details>`로 감춰 둔
  관용구를 그대로 계승한다. 새 패턴을 만들지 않는다.
- **「고급」을 없애지 않는다.** GPU 게이트나 토큰 예산에 막혔을 때 UI에서 풀 길이 없으면
  사용자가 터미널로 돌아가야 하고, 그러면 이 슬라이스의 목표(§1)가 그 지점에서 무너진다.
- 요청 본문에서 생략된 필드는 코어 기본값을 쓴다. 서버가 값을 지어내지 않는다.
- **저장된 옵션은 폼에 되돌린다** [사용자 결정 · 2026-09-02 추가]. 서버가 `last_options`를
  밑에 깔고 요청으로 덮으므로(§4.7 `POST /api/scan`), 입력칸이 비어 있어도 **저장된 값이
  그대로 쓰인다.** 채워 두지 않으면 자리 표시로 보이는 기본값과 실제로 도는 값이 어긋나고
  사용자가 알 길이 없다. 저장된 고급 값이 있으면 접기를 펴 둔다 — 접힌 채로는 채워 넣어도
  보이지 않는다. `force`·`force_gates`는 §4.5대로 저장하지 않으며 언제나 꺼진 채 시작한다.
- **각 항목에 「?」 도움말을 단다** [사용자 결정 · 2026-09-02 추가]. 기본값과 「올리면·내리면
  무엇이 달라지는가」를 한 문장으로 적는다. 8개 항목은 모두 `ScanConfig`의 실제 필드이며,
  화면에만 있는 항목이 섞이면 그 칸을 채우는 순간 러너가 «알 수 없는 설정 키»로 거절해
  스캔이 시작조차 되지 않는다 — 테스트가 이 집합을 대조한다.

### 4.8 화면 [사용자 결정]
- **`gui_preview/variants/minimalist`를 코드 베이스로 삼는다.** 인라인 SVG 아이콘, 키보드
  조작(`tabindex`·Enter·Space), 인앱 모달·토스트, WCAG 대비 보정이 이미 되어 있고 CDN을
  쓰지 않는다.
- **1축 레이아웃**이다. 프로토타입의 2축(좌측 프로젝트 + 상단 5탭)을 **되돌린다.**
  사용자가 기준으로 제시한 도구들(클로드·ChatGPT·제미나이)은 좌측 사이드바 하나에 컨텍스트
  목록을 두고 상단 탭을 두지 않는다. 프로토타입 CSS의 `Architecture: 2-Axis — UNCHANGED`
  주석은 이 결정으로 무효가 된다.
- 사이드바 구성: 워크스페이스 선택 → 메뉴 **3개** → 하단 설정.

  | 메뉴 | 담는 것 |
  |---|---|
  | **탐색** | 검색 · 위키 본문 · 그래프를 **한 화면**에서 전환 |
  | **스캔** | 견적(plan) · 실행 · 진행 상황 · 중지 |
  | **대시보드** | 워크스페이스 현황 |
  | 설정 | 환경 점검(doctor) · 클라우드 엔진 · 워크스페이스 관리 |

- **탐색 화면이 한 화면인 이유**: 검색 → 결과 클릭 → 본문 → 관련 문서로 이어지는 흐름에서
  화면이 바뀌면 검색어와 결과 목록이 사라진다. 화면마다 상태 보존 장치를 따로 만들지
  않으려면 흐름을 한 화면에 두는 편이 낫다.
- **검색 전 기본 화면은 전체 문서 목록이다** [사용자 결정 · 2026-09-01 추가]. 빈 화면은
  막다른 길이다 — 검색어를 모르면 아무것도 못 한다. 목록에는 파일 이름이 아니라 **위키의
  `# 제목`**을 보여 준다(`온보딩.md.md`만 늘어놓으면 무엇이 들었는지 알 수 없다). 검색어를
  비우고 검색하면 목록으로 돌아온다.
  - **목록은 폴더 트리다** [사용자 결정 · 2026-09-02 추가]. 평면 목록은 줄마다 같은
    접두사(`인사/`)를 반복해 읽을 것만 늘렸다. 폴더 이름을 한 번만 적고 그 아래 문서를
    모으며, 폴더 줄을 눌러 접고 편다. **접힘 상태는 변수가 들고 있다** — 화면에만 두면 다른
    메뉴에 갔다 오는 순간 전부 펼쳐진다. 기본은 모두 펼침이다.
  - **검색 결과는 평면 그대로다.** 폴더로 묶으면 관련도 순서가 깨진다.
  - **선택 표시도 변수에서 다시 만든다** [2026-09-02 추가]. 표시를 화면 요소에만 두면 목록을
    다시 그리는 순간(다른 화면에 갔다 오거나 검색을 다시 하면) 사라져, 본문은 열려 있는데
    왼쪽에는 아무것도 골라져 있지 않은 어긋난 상태가 된다. 목록은 위키 상대경로로, 검색
    결과는 원문 절대경로로 맞춘다.
- **그래프 탭은 워크스페이스 전체를 그린다** [2026-09-01 명시]. 검색 결과와 무관하며,
  「본문」 탭 옆에 있어 «고른 문서의 그래프»로 오해되기 쉬우므로 화면이 그 범위를 글자로
  밝힌다. 고른 문서는 색으로 강조한다. 워크스페이스를 바꾸면 이전 그래프를 버린다 —
  안 버리면 새 데이터가 오기 전 잠깐 이전 워크스페이스의 그림이 보인다.
  - **배치는 방사형이다** [사용자 결정 · 2026-09-02 추가]. 고른 문서(없으면 연결이 가장 많은
    문서)를 가운데 두고, 직접 이어진 문서를 안쪽 고리에, 나머지를 바깥 고리에 놓는다. 다각형
    한 겹으로 늘어놓던 배치는 어느 문서가 중심인지 그림이 말해 주지 않았다. **중심 선택도
    이웃 판정도 저장된 값(연결 수·엣지)을 읽기만 한다** — §4.11의 「조회는 저장값을 읽기만
    한다」를 지킨다. 선은 곡선으로 그린다(직선은 지름을 가로지를 때 막대처럼 보인다).
  - **점을 누르면 목록에서 고른 것과 같은 경로를 탄다.** 그림과 목록이 서로 다른 문서를
    가리키는 상태를 만들지 않는다.
  - **휠로 확대·축소하고 끌어서 옮긴다.** 확대는 **그리는 단계에서만** 적용한다 — 배율로
    좌표를 다시 계산하면 확대할 때마다 문서 자리가 달라지고 되돌려도 처음 그림이 돌아오지
    않는다. 클릭 판정은 화면 좌표를 그림 좌표로 되돌려 맞춘다.
- **「?」 도움말은 호버에만 의존하지 않는다** [사용자 결정 · 2026-09-02 추가]. 대시보드
  「엣지 종류」와 스캔 「고급 설정」이 같은 컴포넌트를 쓰며, 클릭·Enter·Space 로 여닫고
  Esc 로 닫는다 — 터치 기기에는 호버가 없다. 아이콘은 **인라인 SVG** 다(글자 `?` 는 글꼴
  지표 때문에 원 안에서 위로 쏠린다). 아이콘 라이브러리를 들이지 않는다 — §2의 「외부 CDN
  없음」·「의존성 0」이 그대로 유효하다.
- **환경 점검은 CLI 텍스트를 그대로 뿌리지 않는다** [2026-09-01 명시]. `DoctorReport`의
  구조화된 필드에서 항목 목록(`status`·`label`·`detail`·`action`·`blocking`)을 만들어 상태
  칩과 조치로 렌더한다. 문자열을 파싱하면 문구를 다듬을 때마다 화면이 조용히 깨진다.
  GPU 미탐지와 클라우드 미설정은 **경고**이지 `blocking`이 아니다 — 실패로 칠하면 로컬만
  쓰는 사용자에게 늘 빨간 화면이 보인다.
- 기능 6개(대시보드·스캔·검색·위키·그래프·설정)는 모두 제공된다. **메뉴가 3개인 것이지
  기능이 3개인 것이 아니다.**

#### 4.8.1 정적 자산 [사용자 결정 · grill T7]
- 자산은 **`corpbrain/gui/static/`** 에 둔다. `gui_preview/variants/minimalist`에서 **복사**해
  오며, `gui_preview/`는 참고 자료로 **그대로 남긴다** — 모든 goal 루프가 그 디렉터리를
  「수정 금지」로 지정해 두었고, 세 변형의 색채와 설계 의도를 나중에 되짚을 수 있어야 한다.
  두 사본 중 **정본은 `corpbrain/gui/static/`** 이며 `gui_preview/`는 갱신하지 않는다.
- **웹폰트를 쓰지 않는다. 시스템 폰트 스택만 쓴다** (한국어는 맑은 고딕·Apple SD Gothic Neo
  등 OS 기본). 폰트 파일을 커밋하면 v0.8이 세운 "바이너리를 커밋하지 않는다"와 부딪히고,
  커밋하지 않고 내려받으면 "빌드 없는 Vanilla"(§2)와 부딪힌다. 웹폰트를 쓰지 않으면 이
  충돌이 애초에 발생하지 않으며, §3 항목6(외부 URL 0건)이 자동으로 성립한다.
  - `gui_preview/variants/minimalist`는 이미 CDN 폰트를 쓰지 않는다. CDN을 링크하는 것은
    `brutalist`·`soft` 둘뿐이며, 이번 슬라이스는 그 둘을 베이스로 삼지 않는다.
- 아이콘은 minimalist가 이미 쓰는 **인라인 SVG**를 그대로 쓴다. 아이콘 폰트·이미지 파일을
  들이지 않는다.
- 그래프 캔버스는 minimalist의 **자체 구현 물리 엔진**을 쓴다. 라이브러리를 로드하지 않는다.
  - 복사 시 **알려진 버그를 함께 고친다** — `app.js`의 스프링 힘 계산에서 y축 부호가 x축과
    반대로 되어 있어(`b.vy += …`가 `-=`여야 한다) 레이아웃이 수직으로 왜곡된다. 루트·
    `brutalist`·`soft` 세 벌에 복제돼 있다.

### 4.9 마크다운 렌더링과 위키 편집 [제안 후 승인]
- 마크다운 렌더러를 **최소 구현으로 직접 작성**한다 — 헤딩·불릿·링크·인라인 코드·문단·
  front-matter 분리. 위키는 코드가 소유한 고정 템플릿이므로 이것으로 충분하고, 모르는
  문법은 평문으로 흘린다. 라이브러리를 쓰면 §4.2의 의존성 0이 깨진다.
- **렌더링 시 HTML을 반드시 이스케이프한다.** 위키 본문은 LLM이 만들고 사용자가 편집하는,
  신뢰할 수 없는 입력이다. 편집을 범위에 넣은 이상 XSS 방어가 필수다.
- 편집 저장 시 서버가 **`<!-- corpbrain:related:start -->` / `:end` 마커 블록의 보존을
  검증한다.** 마커가 사라지면 다음 스캔이 블록을 하나 더 추가해 「관련 문서」 섹션이
  중복된다. 마커가 없는 본문은 400으로 거절하고 파일을 쓰지 않는다.
- 편집한 문서를 나중에 `--force`로 재스캔하면 사람이 고친 내용이 덮인다. **이 사실을 편집
  화면에 명시한다.**
- **「원문」 섹션의 `file://` 링크는 §4.7의 `reveal`을 부르는 버튼으로 렌더한다**
  [사용자 결정 · 2026-09-02 추가]. 브라우저가 그 링크를 따라갈 수 없으므로 서버가 대신
  폴더를 연다.
  - **문구는 위키에 적힌 것을 그대로 쓴다**(「원본 파일 열기」). 경로를 덧붙이지 않는다 —
    이 화면이 보여 주는 것은 **위키 문서 자체**이므로, 화면이 위키의 글을 고쳐 쓰거나 없던
    글자를 지어내지 않는다. 같은 잣대로 문서 목록의 «원본 확장자 배지»도 두지 않는다.
  - 이 링크만 **대상에 공백을 허용하는 별도 패턴**으로 먼저 잡는다. 범용 링크 패턴은 대상에
    공백이 없다고 보는데(「관련 문서」의 상대경로가 그렇다), 원문 경로에는 공백이 흔해
    `02. 환경설정 가이드.docx` 같은 실제 문서명에서 **마크다운 원문이 글자 그대로 화면에
    남아 있었다.**
  - **위키 파일 자체는 바뀌지 않는다.** 마크다운에는 종전대로 `file://` 링크가 있고, 코어
    렌더러(`render.py`)를 고치지 않는다 — §2의 「코어 수정」 비목표를 지킨다.
- **저장 응답은 방금 쓴 내용의 렌더 결과를 함께 돌려준다** [사용자 결정 · 2026-09-02 추가].
  그러지 않으면 화면이 편집기를 닫고도 낡은 본문을 보여 주어 새로고침 전까지 저장이 안 된
  것처럼 보인다. 화면이 스스로 렌더하게 하면 마크다운 렌더러가 두 벌이 되고 그중 한쪽만
  이스케이프를 빠뜨리는 순간 위의 XSS 방어가 무너지므로, 렌더는 서버 한 곳에 두고 결과만
  돌려준다.

### 4.10 클라우드 엔진 설정 [사용자 결정]
- 설정 화면에서 동의 부여·철회와 엔진 선택을 제공한다. 코어의
  `grant_cloud_consent()`·`revoke_cloud_consent()`를 호출한다.
- 동의 다이얼로그에 **세 가지 고지를 반드시 표시한다** — ① 문서 내용이 외부(Anthropic)로
  전송된다 ② PII 7종은 자동 마스킹된다 ③ API 키는 파일에 저장되지 않는다. CLI가 지금
  `consent cloud --grant`에서 이 세 줄을 내고 있으며, 코어의 `grant_cloud_consent()`는
  아무 고지도 하지 않고 파일만 쓴다.
- **API 키는 어디에도 저장하지 않는다.** 서버 프로세스의 환경변수로만 다룬다 — 코어가
  호출 시점에 `ANTHROPIC_API_KEY`를 직접 읽으며 전달할 파라미터 통로 자체가 없다.

### 4.11 유지할 불변식 [사용자 결정]
- **코어/어댑터 이음새**: GUI는 코어의 공개 API만 호출한다. 비즈니스 로직을 GUI로 옮기지
  않고, 화면 요구 때문에 코어에 I/O를 들이지 않는다.
- **단일 외부호출 관문**: GUI는 나가는 네트워크 호출을 직접 하지 않는다. 로컬 서버를
  여는 것(인바운드)은 이 불변식의 대상이 아니다 — 관문은 나가는 호출만 다룬다.
- **기본 로컬**: 클라우드는 동의 + API 키 + 명시적 엔진 선택을 모두 통과할 때만 쓰인다.
- **조회는 저장값을 읽기만 한다**: 그래프 캔버스가 클라이언트에서 중심성·클러스터를 다시
  계산하지 않는다. 계산하면 화면이 DB·산출물과 어긋난다.
- **하위 호환**: 기존 CLI 동작을 바꾸지 않는다. `corpbrain gui`는 신규 서브커맨드다.

## 5. 엣지 케이스와 실패 시나리오

- **스캔 중 조회 요청** [사용자 결정 · grill T2]: 스캔이 잠그는 자원은 셋이고 성질이 서로
  다르다. **같은 잣대로 묶지 않는다** — 묶으면 멀쩡히 동작하는 기능을 수십 분간 막게 된다.

  | 자원 | 스캔이 하는 일 | 처리 |
  |---|---|---|
  | 벡터 인덱스 | 실행 내내 쓰기 락 점유 | **검색을 409로 차단** |
  | 그래프 DB | 패스2가 전량 재삽입을 단일 트랜잭션으로 커밋 | 조회 **허용**, 실패만 흡수 |
  | 위키 `.md` | 패스1이 생성, 패스3이 마커 블록 갱신 | 열람 **허용**, 변경 가능성 표시 |

  - **검색**: UI에서 비활성화한다. 그래도 타이밍 경합으로 요청이 들어오면 서버가 **409**로
    거절한다. 구조적으로 반드시 실패하기 때문이다 — 스캔이 벡터 인덱스 쓰기 락을 실행 내내
    점유하고(`upsert`가 커밋하지 않고 `close()`에서 한 번에 커밋), `search`는 조회인데도
    인덱스를 쓰기로 연다(개봉 시 `CREATE TABLE IF NOT EXISTS` + `commit()`). **이번
    슬라이스는 코어를 고치지 않으므로 GUI에서 막는 것으로 대응한다.**
  - **그래프 조회**: 허용한다. `read_only`로 열므로 대부분의 시간 동안 정상 동작하고,
    패스2가 커밋하는 순간에만 짧게 `SQLITE_BUSY`가 난다. 서버가 `sqlite3.Error`를 잡아
    「그래프를 다시 만드는 중입니다. 잠시 후 다시 시도하세요」로 바꾼다.
  - **위키 열람**: 허용한다. 파일 락은 없으나 패스1·패스3이 내용을 바꿀 수 있으므로,
    스캔 중에는 본문에 「스캔 중이라 내용이 바뀔 수 있습니다」를 표시한다. 스캔 중에는
    **편집 저장을 409로 막는다** — 패스3의 마커 블록 갱신과 충돌해 한쪽이 덮인다.
  - 어느 경우에도 `sqlite3.Error`가 응답에 원시 트레이스백으로 노출되지 않는다. 현재
    `search_index()`와 CLI 어느 쪽도 이 예외를 잡지 않아 웹에서는 500이 된다.
- **동시 스캔** [제안 후 승인]: 전체에서 **1개만** 허용한다. 이미 실행 중이면 **409**로
  거절한다. 같은 `out_dir`에 두 스캔이 붙는 것을 막는 장치가 코어에 없다.
- **서버 종료** [제안 후 승인]: 자식 프로세스를 함께 종료한다. 고아 프로세스가 인덱스 락을
  쥔 채 남으면 다음 실행이 이유 없이 막힌다.
- **스캔 중지** [사용자 결정]: 이미 생성된 위키는 남고, 커밋되지 않은 인덱스 변경은
  유실된다. 다음 스캔이 복구한다. **이 사실을 UI에 명시한다.**
- **포트 사용 중** [제안 후 승인]: 다음 빈 포트를 자동으로 잡는다. 기동 실패로 만들지
  않는다. 전부 실패하면 exit 1.
- **그래프 단계의 관측 공백** [제안 후 승인]: 코어의 패스2·패스3(그래프 빌드·「관련 문서」
  주입)은 이벤트를 하나도 내지 않는다. 마지막 `FileGenerated`와 `RunFinished` 사이에서
  진행바가 멈춘 것처럼 보이므로, UI가 "그래프 만드는 중"을 별도로 표시한다.
- **워크스페이스의 폴더가 사라짐** [제안 후 승인]: 목록에는 남기고 「폴더 없음」으로
  표시한다. 조용히 지우지 않는다.
- **그래프 DB 부재·손상** [제안 후 승인]: 코어 방침을 그대로 따른다 — 부재는 정상 응답
  (코사인 단독 검색 + 안내), 손상은 오류와 재생성 안내다. GUI가 자동 복구하지 않는다.
- **벡터 인덱스 부재**: 코어대로 선행 조건 실패다. 화면은 "먼저 스캔하세요"로 안내한다.
  [제안 후 승인]
- **개별 파일 실패**: 코어가 예외로 올리지 않고 `ScanResult.skipped`에 담는다. GUI는
  **"성공했지만 N건 스킵됨"을 반드시 렌더한다** — 스킵을 표시하지 않으면 사용자가 문서가
  누락된 사실을 모른다. [제안 후 승인]
- **상한 초과**: `ScanResult.limit_exceeded`는 예외가 아니라 결과 필드다. 놓치지 않고
  화면에 표시한다. [제안 후 승인]
- **동의 파일 쓰기 실패**: 코어가 `ConsentStoreError`(선행 조건 실패)로 올린다. GUI는 이를
  오류 메시지로 매핑한다. Windows에서는 다른 프로세스가 파일을 연 순간 `os.replace`가
  실패할 수 있다. [제안 후 승인]
- 기존 스펙들의 실패 방침(미지원·빈·추출 실패·권한 거부·긴 경로 스킵, 선행 조건 실패 시
  비-0 종료, 개별 파일 실패를 전체 실패로 위장하지 않음)은 그대로 유지된다.
