# 스펙: CorpBrain v0.8 — `.xlsx`/`.xlsm`/`.pptx` 텍스트 추출

- 상태: 확정
- 최종 갱신: 2026-08-27 (grill-it 토픽 7건 반영 · U1 확인 결과 2건 기록 — §2 `.pptm` · §4.2 숨긴 행
  · §4.2 T2 「내용 없음」 기준을 공백까지 확대 — spec-check 드리프트 D3 해소)

## 1. 목표
v0.2가 후속으로 예고해 둔 오피스 포맷 확장을 닫는다. `extract.py`의 기존 「확장자별 추출기」
패턴을 그대로 따라 `.xlsx`·`.xlsm`·`.pptx` 세 확장자의 **텍스트 레이어만** 추출해, 다른 지원
포맷과 동일하게 문서 1개당 위키 1개를 생성한다. 파이프라인·렌더러·저장 계층은 바뀌지 않으며,
추가 LLM 호출·추가 네트워크 연결도 없다. [사용자 결정]

## 2. 비목표
이번 슬라이스에서 다음은 하지 않는다.

- **`.xls`(BIFF 97-2003)·`.ppt`(OLE 97-2003) 지원.** 사용자 환경에 구형 파일이 없고, `.ppt`는
  순수 파이썬 경로 자체가 없어 LibreOffice 같은 **외부 변환기 프로세스 의존**을 들이게 된다 —
  100% 로컬 구동형 제품에 「특정 데스크톱 앱이 깔려 있어야만 동작하는 기능」을 처음 만드는 일이다.
  [사용자 결정]
- **`.xltx`/`.xltm`(엑셀 템플릿)·`.pptm`(매크로 포함 PPT) 지원.** 템플릿 2종은 실사용 빈도가 낮다.
  `.pptm`은 이 스펙 초판이 「`python-pptx`가 메인 파트 content type을 검사해 거부할 가능성이 크다」
  (`python-docx`가 `.docm`을 `ValueError`로 막는 것과 같은 구조)고 적었으나, **실측에서 그 추정은
  틀렸다** [2026-08-27 · U1 확인 · `python-pptx` 1.0.2]. 확장자만 `.pptm`으로 바꾼 파일도, 메인 파트
  content type을 `application/vnd.ms-powerpoint.presentation.macroEnabled.main+xml`로 바꾼 파일도
  `Presentation()`이 예외 없이 열었다 — `python-pptx`는 `python-docx`와 달리 메인 파트 타입을
  검사하지 않는다.
  - **그럼에도 지원 범위를 넓히지 않는다.** 비목표 목록은 사용자 결정이고, 「라이브러리가 거부한다」는
    그 결정의 근거가 아니라 근거를 보강하던 관찰이었다. 무너진 것은 보강 쪽뿐이므로 결정은 그대로
    두고, 틀린 문장만 실측 문장으로 바꾼다.
  - 남는 실질은 이것이다 — `.pptm`을 `SUPPORTED_EXTENSIONS`에 넣지 않으므로 스캐너가
    `unsupported_extension`으로 스킵한다(§5). 이 저장소는 이미 같은 이유로 `.docm`을 지원하지
    않는다. [사용자 결정]
- **OCR·이미지 텍스트·암호 해제.** v0.2가 `.pdf`에서 세운 "텍스트 레이어만" 원칙을 그대로 계승한다.
  [제안 후 승인]
- **확장자별 파일 크기 임계치.** 전역 `--max-file-size`(기본 20MB) 하나를 그대로 쓴다.
  [제안 후 승인]
- **수동 스모크.** 아래 §3 「검증 방식」의 근거로 이번 회차에 한해 요구하지 않는다. [사용자 결정]

### 2.1 선행 정정 — 로드맵의 라이브러리 매핑은 사실 오류다 [제안 후 승인]
`docs/ROADMAP.md` §4·§5와 v0.2 스펙 §2가 모두 **"xls(`openpyxl`)/ppt(`python-pptx`)"** 로 적어
두었으나, 이 매핑은 성립하지 않는다. 이번 슬라이스에서 문면을 정정한다.

| 확장자 | 가능 여부 | 수단 |
|---|---|---|
| `.xlsx` · `.xlsm` | 가능 | `openpyxl` |
| `.xls` (BIFF) | 가능하나 **다른 라이브러리** | `xlrd>=2` — `openpyxl`은 열지 못한다 |
| `.pptx` | 가능 | `python-pptx` |
| `.ppt` (OLE) | **순수 파이썬으로 불가** | 외부 변환기 필요 |

## 3. 완료의 정의
`tmp_path`에 `.xlsx`·`.xlsm`·`.pptx`·기존 지원 4종·암호화 파일·수식 전용 파일을 **인라인 생성**한
코퍼스로 코어 API(`run_scan()`·`plan_scan()`)를 직접 호출해 아래를 모두 만족한다. [제안 후 승인]

1. 신규 3종 각각에 `<원본이름.확장자>.md`가 1개씩 생성되고, 출력 트리가 기대 집합과 **정확히
   일치**한다.
   - 검증: 통합테스트에서 생성된 상대경로 집합을 기대 집합과 동등 비교.
2. 엑셀 추출 텍스트에 `[시트: <이름>]` 경계 줄이 **내용이 있는** 시트마다 정확히 1회 나타나고
   (내용이 없는 시트에는 나타나지 않으며), 행의 셀 값이 탭으로 구분되며, **숨긴 시트의 내용이
   없다**. 숨긴 **행**은 §4.2 T3의 확인 결과에 따른다 — 판별 가능하면 그 내용도 없어야 하고,
   불가하면 이 단언에서 제외한다.
   - 검증: 추출기 단위테스트에서 반환 문자열 단언.
3. 수식만 있고 캐시된 계산값이 없는 `.xlsx`는 `empty_document`로 스킵되고 위키가 생성되지 않으며
   종료 코드는 0이다(§4.2의 「내용 없는 시트에는 경계 줄도 내지 않는다」가 이 항목을 성립시킨다).
   - 검증: 단위테스트(스킵 사유) + 통합테스트(산출물 부재·종료 코드).
4. PPTX 추출 텍스트에 `[슬라이드 N]` 경계 줄, 표 셀 텍스트, 그룹 도형 내부 텍스트, `[노트]` 뒤의
   발표자 노트가 모두 포함된다.
   - 검증: 네 요소를 모두 담은 픽스처를 생성해 추출기 단위테스트에서 단언.
5. 암호화된 `.xlsx`/`.pptx`는 `extraction_failed` + §4.3.1의 detail로 스킵되고, 같은 실행의 나머지
   파일은 정상 처리되며 종료 코드는 0이다. OLE 시그니처를 가진 파일과 그렇지 않은 손상 파일이
   **서로 다른 detail**을 받는다.
   - 검증: 통합테스트에서 스킵 리포트와 나머지 산출물을 함께 단언. 암호화 픽스처는 OLE 시그니처
     8바이트로 시작하는 파일을 만들어 대신한다(실제 암호화 통합문서를 생성할 필요가 없다).
6. `SkipReason`의 원소 집합이 v0.7과 동일하다(증설 없음).
   - 검증: enum 원소 집합 동등 단언.
7. `SUPPORTED_EXTENSIONS == {".docx", ".txt", ".md", ".pdf", ".xlsx", ".xlsm", ".pptx"}`이고,
   §4.2 추출기 매핑의 **키 집합이 이 상수와 정확히 같다**.
   - 검증: `tests/test_scanner.py`의 기존 집합 동등 단언 갱신 + 매핑 키 집합 동등 단언 추가.
8. `plan_scan()`에서 신규 3종이 기본점수 40과 §4.4의 `CHARS_PER_BYTE` 값을 받는다 — 미등록
   fallback(0점·0.5)이 **아니다**.
   - 검증: `tests/unit/test_plan.py`에서 신규 확장자의 점수·토큰 추정치 단언.
9. `max_chars`를 초과하는 `.xlsx`/`.pptx`에서 추출 결과 길이가 `max_chars` 이하다.
   - 검증: 상한을 넘는 픽스처로 반환 길이 단언.
10. **네트워크 불변식** — 신규 3종을 포함한 코퍼스의 `scan` 실행에서 소켓 목적지가 localhost뿐이다.
    - 검증: `tests/security/test_network_invariant.py`에 케이스를 **추가**한다. 새 파일로 분리하지
      않는다 — 소켓 패치 관용구가 복제되고, 감시장치가 공허하게 통과하지 않음을 증명하는
      `test_watcher_flags_a_gateway_bypass`의 보호를 받지 못한다(v0.6·v0.7 결정 계승).
11. `uv run ruff check .`와 `uv run pytest`가 exit 0이다.
    - 검증: 두 명령의 종료 코드.
12. 지원 포맷을 나열한 문서 전 지점이 동기화되고, §4.6의 stale 부채가 해소된다.
    - 검증: `.pdf`·신규 3종이 §4.6 목록의 모든 지점에 나타나는지 확인.

**검증 방식(전반)** [사용자 결정]: 추출기는 단위테스트, 파이프라인 통합은 `gateway.request_json`을
스텁한 채 코어 API를 직접 호출하는 통합테스트로 검증한다. **수동 스모크는 요구하지 않는다** —
두 추출기는 LLM·네트워크가 개입하지 않는 결정적 순수 함수이므로, v0.6이 정한 「스텁이 원리적으로
증명할 수 없는 것만 수동으로 확인한다」 기준에 해당하는 영역이 없다. ROADMAP §6 품질 게이트의
이번 회차 예외이며 근거를 여기에 남긴다.

**픽스처 구성** [제안 후 승인]: 테스트 코퍼스는 `tmp_path`에 `openpyxl`·`python-pptx`로 인라인
생성한다(`.pdf`가 이미 쓰는 방식). `tests/fixtures/sample_corpus/`는 **확장하지 않는다** — 세 테스트
파일이 공유하고 있고, 2026-08-22에 스모크 산출물이 그 폴더를 오염시켜 통합테스트 3건을 깨뜨린
사고가 있었다. 바이너리를 커밋하지 않으므로 「이 픽스처가 왜 이런 내용인가」가 테스트 코드에
드러난다.

**헬퍼 배치** [사용자 결정 · T6]: 픽스처 생성 헬퍼는 단위·통합 테스트 파일에 **각각 둔다**(복제).
`tests/conftest.py`나 공유 헬퍼 모듈을 신설하지 않는다 — 이 저장소는 `.pdf`에서 이미 같은 선택을
했고 근거를 주석으로 남겨 두었다. 공유 인프라를 새로 들이면 `.pdf`는 복제, 오피스는 공유가 되어
관용구가 둘로 갈린다. 중복 제거가 필요해지면 `.pdf`까지 함께 옮기는 별도 정리로 한다.

## 4. 인터페이스 계약

### 4.1 지원 포맷 [사용자 결정]
- 정본은 `corpbrain/core/config.py`의 `SUPPORTED_EXTENSIONS` 하나이며, 다른 모든 목록은 파생이다.
- `.xlsx` · `.xlsm` · `.pptx` 세 값을 추가한다. `.xlsm`은 `openpyxl`이 공식 지원하므로 확장자 한 줄
  추가로 끝나고 실익이 크다.

### 4.2 추출기 [제안 후 승인]
기존 패턴을 그대로 따른다 — 시그니처 `(path: Path, max_chars: int) -> str`, 실패는
`ExtractionError`, 내용 없음은 빈 문자열.

**디스패치를 매핑으로 전환한다** [사용자 결정 · T5]. `extract_text()`의 if-체인을
`dict[str, Callable[[Path, int], str]]` 하나로 바꾸고, 흩어진 확장자 상수를 그 매핑으로 모은다.

- 지원 포맷 목록이 `config.SUPPORTED_EXTENSIONS`와 `extract.py`에 **따로 정의돼 어긋나도 아무도
  검증하지 않는** 기존 구멍을 닫는다 — **`매핑의 키 집합 == SUPPORTED_EXTENSIONS`를 단위테스트로
  단언**한다. 지금까지의 유일한 방어는 `tests/test_scanner.py`의 리터럴 단언이었다.
- 확장자가 4종 → 7종으로 늘어나는 이번이 그 값을 치를 시점이며, 이후 포맷 추가는 매핑 한 줄이 된다.
- 매핑에 없는 확장자는 종전대로 `ExtractionError`를 올린다(스캐너를 우회한 직접 호출용 방어선).

**엑셀 (`.xlsx`·`.xlsm`)**
- `openpyxl.load_workbook(read_only=True, data_only=True)`로 연다.
- **내용이 있는 시트에만** `[시트: <시트명>]` 경계 줄을 먼저 낸다. 시트명 자체가 요약에 유용한
  신호이며, 경계가 없으면 서로 다른 표의 행이 이어 붙어 한 표로 읽힌다.
- **내용이 없는 시트에는 경계 줄도 내지 않는다** [사용자 결정 · T1]. 경계 줄은 「뒤에 내용이
  온다」는 신호이므로 뒤가 비면 낼 것이 없다. 항상 내면 값이 전부 비는 파일(수식 캐시 없음, 빈
  통합문서)의 추출 결과가 경계 줄만 남아 `text.strip()` 검사를 통과해 버려 §3 항목3이 성립하지
  않고, 모델에 시트 이름만 든 입력이 간다. 빈 판정 책임은 호출자 한 곳에 그대로 둔다 — 추출기
  밖으로 포맷 문법 지식을 흘리지 않는다.
- 각 행은 셀 값을 **탭으로 이어 한 줄**로 만든다. **내용이 없는 행은 건너뛰고**(빈 줄이 쌓이지
  않게), **행 끝의 빈 셀은 탭을 남기지 않는다**(오른쪽 여백 탭 제거). [사용자 결정 · T2]
  - **「내용이 없다」는 공백만 남는 경우를 포함한다** [사용자 결정 · 2026-08-27 추가]. 판정은
    탭으로 이은 결과 문자열을 `strip()` 해서 한다. 초판은 이 기준을 `None`(빈 셀)로만 적었으나,
    그러면 T1이 막으려던 실패가 공백을 통해 그대로 재현된다 — 아래 「공백 셀」 항목에 실측이 있다.
  - **두 규칙의 기준이 다른 것은 의도적이다.** 「행 끝의 빈 셀」 제거는 종전대로 `None`(→ 빈
    문자열)만 대상으로 한다. 열 위치를 나타내는 탭을 어디까지 지울지는 표의 모양에 관한 문제이고,
    「이 행에 내용이 있는가」는 요약 입력으로 보낼지에 관한 문제라 같은 잣대를 쓸 이유가 없다.
    공백 셀은 열이 실재한다는 신호이므로 **다른 셀에 값이 있으면 탭과 함께 그대로 남는다.**
- **셀 값의 문자열화 규칙** [사용자 결정 · T2]: `openpyxl`이 돌려주는 것은 문자열이 아니라 파이썬
  객체이므로 변환 규칙을 못박는다. `120000.0`·`2026-03-31 00:00:00` 같은 표기는 LLM이 요약문에
  그대로 옮겨 적는 종류의 잡음이며, 아래 네 줄로 사라진다.

  | 값 | 표기 |
  |---|---|
  | `datetime`·`date` | `YYYY-MM-DD` — 시각이 0시가 아니면 `YYYY-MM-DD HH:MM` 까지 |
  | 정수값 `float` (`120000.0`) | 소수점을 떼어 `120000` — 그 외 실수는 `str()` 그대로 |
  | `bool` | `True` / `False` |
  | `None` (빈 셀) | 빈 문자열 |
  | 공백뿐인 문자열 (`" "`·`"\t"`) | 그대로 두되 **행의 내용 판정에서는 빈 것으로 센다** (아래) |

  - **공백 셀** [사용자 결정 · 2026-08-27 추가]: T1의 「내용 없음」 판정 기준은 `None` 하나가
    아니라 **행을 이은 결과가 공백뿐인 경우 전체**다. 초판은 이 기준을 `None`으로만 적었는데,
    문자열화 규칙이 공백 문자열을 그대로 통과시키고 「행 끝의 빈 셀」 제거도 빈 문자열만 떼어내므로
    공백 셀이 살아남아 **내용으로 세어졌다.**
    - 실측: 보이는 셀이 `" "`·`"  "`·`"\t"` 뿐인 통합문서의 추출 결과가
      `"[시트: 서식만]\n \t  \n\t"` 가 되어 호출자의 `text.strip()` 검사를 통과했고, **시트
      이름만 든 입력이 LLM 까지 갔다** [2026-08-27]. §3 항목3과 T1이 겨냥한 실패가 `None` 이
      아니라 공백을 통해 그대로 재현된 것이다.
    - 즉 초판에서는 T1의 **의도**와 T2 표의 **문면**이 충돌하고 있었다. 의도 쪽으로 문면을 넓힌다.
    - 이로써 PPTX 표 경로와 판정이 같아진다 — 그쪽은 처음부터 `strip()` 기준이었다. 같은 표를
      담은 `.xlsx` 와 `.pptx` 가 다른 판정을 받지 않는다.
    - 빈 판정 **책임**은 여전히 호출자(`prepare_summary_input`)에 있다. 추출기는 「이 행에 낼
      내용이 없다」를 판단해 줄을 만들지 않을 뿐이고, 문서 전체가 비었는지는 호출자가 정한다.

  엑셀 표시 형식(`number_format`)은 해석하지 않는다 — `read_only` 모드에서 제한적이고, 통화·
  백분율까지 다루면 이번 슬라이스의 「텍스트 레이어만」 원칙을 넘어선다.
- **숨겨진 시트는 제외한다** (`sheet_state`는 읽기 전용 모드에서도 판정된다).
- **숨겨진 행은 제외하지 않는다 — 판별할 수 없기 때문이다** [사용자 결정 · T3 · 2026-08-27 실측으로
  확정]. 초판은 `read_only=True` 워크시트가 `row_dimensions`를 채우지 않을 가능성이 크다고 적고
  (라이브러리 미설치로 미검증) 구현 첫 단계의 확인 결과에 따라 아래 표에서 갈리도록 두었다.

  | 확인 결과 | 처리 |
  |---|---|
  | 행 숨김 정보를 얻을 수 있다 | 시트·행 모두 제외한다 (스펙 문면 그대로) |
  | 얻을 수 없다 | **시트만 제외하고 행은 포함한다.** §3 항목2에서 「숨긴 행」 단언을 빼고, 확인 결과를 이 절에 기록한다 |

  **확인 결과: 얻을 수 없다 — 아래 표의 두 번째 행으로 확정한다** [2026-08-27 · U1 확인 ·
  `openpyxl` 3.1.5]. `read_only=True`로 연 워크시트는 `Worksheet`가 아니라 `ReadOnlyWorksheet`이고,
  이 클래스에는 `row_dimensions` 속성이 **아예 없다**(`hasattr(...) is False`). 값이 비어 있는
  것이 아니라 속성 자체가 없으므로 행을 순회한 뒤에도 채워질 여지가 없다. 따라서 **숨긴 행의
  내용은 추출 결과에 포함된다.** 같은 개봉에서 `sheet_state`는 정상 판정되므로 **시트 숨김 제외는
  그대로 성립한다.**
  - §3 항목2의 「숨긴 행」 단언은 이 결과에 따라 빠진다 — 그 항목이 조건부로 예고한 대로다.

  `read_only=False`로 바꾸는 선택지는 **택하지 않는다** — 통합문서 전체를 메모리에 올려 위의
  「파일을 통째로 메모리에 올리지 않는다」와 정면으로 부딪친다. 폴백을 미리 못박는 것은 구현자가
  그 자리에서 스펙을 임의 해석하지 않게 하기 위함이다.
- 수식 셀은 **캐시된 계산값**을 쓴다(`data_only=True`). 요약에 쓸모 있는 것은 `=SUM(B2:B10)`이
  아니라 그 결과값이다.

**PPTX**
- **내용이 있는 슬라이드에만** `[슬라이드 N]` 경계 줄을 먼저 낸다 — 위와 같은 규칙이다.
  이미지만 있는 슬라이드는 경계 줄도 내지 않으며, 전 슬라이드가 그러면 추출 결과가 빈
  문자열이 되어 `empty_document`로 처리된다. `N`은 **원본 슬라이드 번호**(1부터)이며 건너뛴
  슬라이드가 있어도 번호를 다시 매기지 않는다.
- 도형은 **파일에 적힌 순서 그대로** 읽는다. 좌표 기반 시각 순서 재정렬을 하지 않는다 — 같은 높이의
  도형에서 순서가 흔들려 tie-break를 또 정해야 하고, 결정성이 약해진다.
- 표(`GraphicFrame`) 셀 텍스트와 그룹 도형 내부 텍스트를 **재귀로** 훑는다. 표는 `text_frame`이
  없어 별도로 훑지 않으면 통째로 누락된다.
- 발표자 노트를 `[노트]` 줄 뒤에 덧붙인다. 슬라이드 본문이 키워드 나열뿐이고 실제 내용이 노트에
  있는 경우가 흔하다.
- **노트 접근은 `has_notes_slide`로 가드한다** [사용자 결정 · T7]. `slide.notes_slide`에 바로
  접근하면 노트 슬라이드가 없는 슬라이드에 객체가 새로 만들어진다(파일에 쓰이지는 않으나 읽기
  연산이 객체를 만드는 모양새다). 추출기는 전부 읽기 전용이며 그 성질이 코드에서 보이게 둔다.
- **노트가 있으나 공백뿐이면 `[노트]` 줄도 내지 않는다** — T1의 「내용이 있을 때만 경계 줄」과 같은
  규칙이다.

**공통** [제안 후 승인]
- 파일을 통째로 메모리에 올리지 않는다. 누적 문자수가 `max_chars`에 닿으면 즉시 중단한다 —
  `.pdf` 추출기가 페이지 루프에서 하는 것과 같은 방식이다.
- 호출자 `prepare_summary_input()`의 방어적 절단(`text[:max_chars]`)은 그대로 유지된다.

### 4.3 실패 매핑 [제안 후 승인]
**새 `SkipReason` 값을 만들지 않는다.** v0.2가 `.pdf`에서 세운 계약을 글자 그대로 계승한다.

| 상황 | 처리 |
|---|---|
| 손상·파싱 실패 | `ExtractionError` → `extraction_failed` + detail |
| 암호화 (zip이 아닌 OLE 컨테이너가 되어 열리지 않음) | `ExtractionError` → `extraction_failed` + detail (§4.3.1) |
| 내용 없음·공백뿐 (빈 통합문서, 이미지만 있는 슬라이드) | 예외가 아니라 **빈 문자열** → 호출자가 `empty_document`로 판정 |
| `--max-file-size` 초과 | 기존 전역 게이트대로 `file_too_large` |

#### 4.3.1 암호화 판정 [사용자 결정 · T4]
`.pdf`는 `reader.is_encrypted`라는 명시적 API가 있었으나, 암호화된 `.xlsx`/`.pptx`는 zip이 아니라
**OLE 복합문서**로 감싸져 라이브러리가 「zip을 열지 못했다」는 예외만 던진다 — 손상된 파일과 예외
종류가 같아 구분되지 않는다.

- **열기에 실패했을 때만** 파일 앞 8바이트를 읽어 OLE 시그니처(`D0 CF 11 E0 A1 B1 1A E1`)를
  확인한다. 표준 라이브러리만 쓰고 결정적이며, 정상 경로에는 비용이 없다.
- 시그니처가 맞으면 detail을 **「암호화되었거나 구형 이진 포맷입니다」**로 적는다. 이 시그니처는
  구형 `.xls`/`.ppt`를 확장자만 바꿔 놓은 파일과 구분되지 않으므로, 두 원인을 함께 적어 정직하게
  둔다 — 어느 쪽이든 사용자가 할 일(암호를 풀거나 최신 포맷으로 다시 저장)은 같다.
- 시그니처가 아니면 기존 문구(손상·파싱 실패)를 쓴다.
- 예외 메시지 문자열 매칭으로 판정하지 않는다 — 라이브러리 버전이 올라가면 조용히 깨진다.

`ExtractionError`를 올릴 때 원인 예외를 `from exc`로 보존한다 — `PermissionError`와
`extraction_failed`를 가르는 기존 판정이 `__cause__`에 의존한다.

### 4.4 pre-scan 상수 [사용자 결정]
`corpbrain/core/plan.py`의 두 dict에 신규 3종을 추가한다. 누락하면 fallback(0점·0.5)이 조용히
적용된다.

```python
BASE_EXT_SCORE  = {..., ".xlsx": 40, ".xlsm": 40, ".pptx": 40}
CHARS_PER_BYTE  = {..., ".xlsx": 0.06, ".xlsm": 0.06, ".pptx": 0.03}   # 잠정값 — §4.5
```

- 기본점수 40은 `.docx`/`.pdf`와 같은 「정식 산출물」 취급이다. 근거 없이 차등을 두지 않는다.
- `CHARS_PER_BYTE`를 방치해 fallback `0.5`가 적용되면 zip 압축 포맷의 토큰량을 10배 가까이
  과대추정해, `plan`의 소요시간 추정이 틀어지고 v0.3의 총 토큰 예산 게이트(기본 200,000)가
  엉뚱하게 발동할 수 있다.

### 4.5 `CHARS_PER_BYTE`는 잠정값이다 [사용자 결정]
위 세 값의 근거는 «OOXML zip 구조가 `.docx`와 닮았다»뿐이며 **실측이 아니다**(`.xlsx`/`.xlsm`은
`.docx`와 같은 0.06, `.pptx`는 이미지·레이아웃 XML이 바이트 대부분을 차지하므로 그 절반인 0.03).
실물 코퍼스가 없어 이번에는 측정하지 못했다.

- **잠정값임을 코드 주석에 명시한다.**
- 실물 `.xlsx`/`.pptx` 코퍼스로 `추출 문자수 ÷ 파일 바이트`를 재어 확정하는 것은 **후속 이슈**로
  남긴다 (issue #48).
- 이는 v0.7 스펙 §4.8이 정한 「잠정값인 채로 릴리스하지 않는다」와 어긋난다. 성격의 차이를 근거로
  이번 회차에 한해 허용한다 — α는 검색 **순위**를 바꾸는 계약이었고 이 값은 `plan`의 **추정
  표시값**이다. 다만 총 토큰 예산 게이트를 통해 간접 영향이 있으므로 완전히 무해하지는 않으며,
  fallback `0.5`를 두는 것보다 어느 쪽으로 보나 개선이다.

## 5. 엣지 케이스와 실패 시나리오
- **Excel이 저장하지 않은 `.xlsx`** (LibreOffice·스크립트 생성): `data_only=True`가 읽는 계산값
  캐시가 없어 수식 셀이 비어 읽힌다. **이 한계를 수용한다** — 값이 비면 수식 문자열로 대체하려고
  파일을 두 번 열지 않는다. 시트가 수식뿐이면 추출 결과가 빈 문자열이 되어 `empty_document`로
  스킵되며, 이는 v0.2가 스캔 이미지 PDF를 같은 사유로 흘려보낸 것과 같은 처리다. [제안 후 승인]
- **암호화된 통합문서·프레젠테이션**: zip이 아니라 OLE 컨테이너로 저장되어 열리지 않는다.
  `extraction_failed` + detail로 스킵하고 나머지 파일 처리를 계속한다(종료 코드 0). [제안 후 승인]
- **이미지만 있는 슬라이드 / 빈 통합문서**: 예외가 아니라 빈 문자열 → `empty_document`.
  [제안 후 승인]
- **텍스트량 대비 파일이 큰 경우**: 엑셀·PPT는 같은 글자 수에도 파일이 크지만 확장자별 임계치를
  두지 않는다. 전역 20MB를 넘으면 기존대로 `file_too_large` 스킵이며 `--max-file-size`로만
  조정한다. [제안 후 승인]
- **`max_chars` 이후의 시트·슬라이드**: 앞부분만 읽으므로 뒤쪽 시트·슬라이드는 요약 입력에 들어오지
  않는다. `.pdf`가 뒤쪽 페이지에 대해 갖는 것과 같은 알려진 한계로 수용한다. [제안 후 승인]
- **비목표 확장자를 만난 경우**(`.xls`·`.ppt`·`.pptm` 등): 스캐너가 기존대로
  `unsupported_extension`으로 스킵한다. 새 안내 문구를 만들지 않는다. [제안 후 승인]
- 기존 스펙들의 실패 방침(빈 문서·추출 실패·권한 거부·긴 경로 스킵, 상한 초과 중단, 선행 조건 실패
  시 비-0 종료, 개별 파일 실패를 전체 실패로 위장하지 않음)은 그대로 유지된다.
