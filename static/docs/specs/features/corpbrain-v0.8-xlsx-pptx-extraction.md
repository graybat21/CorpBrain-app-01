# 스펙: CorpBrain v0.8 — `.xlsx`/`.xlsm`/`.pptx` 텍스트 추출

- 상태: 확정
- 최종 갱신: 2026-08-27

## 1. 목표
v0.2가 후속으로 예고해 둔 오피스 포맷 확장을 닫는다. `extract.py`의 기존 「확장자별 추출기」
패턴을 그대로 따라 `.xlsx`·`.xlsm`·`.pptx` 세 확장자의 **텍스트 레이어만** 추출해, 다른 지원
포맷과 동일하게 문서 1개당 위키 1개를 생성한다. 파이프라인·렌더러·저장 계층은 바뀌지 않으며,
추가 LLM 호출·추가 네트워크 연결도 없다. [사용자 결정]

## 2. 비목표
이번 슬라이스에서 다음은 하지 않는다.

- **`.xls`(BIFF 97-2003)·`.ppt`(OLE 97-2003) 지원.** 사용자 환경에 구형 파일이 없고, `.ppt`는
  순수 파이썬 경로 자체가 없어 LibreOffice 같은 **외부 변환기 프로세스 의존**을 들이게 된다 —
  100% 로컬 구동형 제품에 「특정 데스크톱 앱이 깔려 있어야만 동작하는 기능」을 처음 만드는 일이다.
  [사용자 결정]
- **`.xltx`/`.xltm`(엑셀 템플릿)·`.pptm`(매크로 포함 PPT) 지원.** 템플릿 2종은 실사용 빈도가 낮다.
  `.pptm`은 `python-pptx`가 메인 파트 content type을 검사해 거부할 가능성이 크며(`python-docx`가
  `.docm`을 `ValueError`로 막는 것과 같은 구조), 구현 중 「확인해 보니 안 되더라」로 스펙이 흔들릴
  위험이 있다. 이 저장소는 이미 같은 이유로 `.docm`을 지원하지 않는다. [사용자 결정]
- **OCR·이미지 텍스트·암호 해제.** v0.2가 `.pdf`에서 세운 "텍스트 레이어만" 원칙을 그대로 계승한다.
  [제안 후 승인]
- **확장자별 파일 크기 임계치.** 전역 `--max-file-size`(기본 20MB) 하나를 그대로 쓴다.
  [제안 후 승인]
- **수동 스모크.** 아래 §3 「검증 방식」의 근거로 이번 회차에 한해 요구하지 않는다. [사용자 결정]

### 2.1 선행 정정 — 로드맵의 라이브러리 매핑은 사실 오류다 [제안 후 승인]
`docs/ROADMAP.md` §4·§5와 v0.2 스펙 §2가 모두 **"xls(`openpyxl`)/ppt(`python-pptx`)"** 로 적어
두었으나, 이 매핑은 성립하지 않는다. 이번 슬라이스에서 문면을 정정한다.

| 확장자 | 가능 여부 | 수단 |
|---|---|---|
| `.xlsx` · `.xlsm` | 가능 | `openpyxl` |
| `.xls` (BIFF) | 가능하나 **다른 라이브러리** | `xlrd>=2` — `openpyxl`은 열지 못한다 |
| `.pptx` | 가능 | `python-pptx` |
| `.ppt` (OLE) | **순수 파이썬으로 불가** | 외부 변환기 필요 |

## 3. 완료의 정의
`tmp_path`에 `.xlsx`·`.xlsm`·`.pptx`·기존 지원 4종·암호화 파일·수식 전용 파일을 **인라인 생성**한
코퍼스로 코어 API(`run_scan()`·`plan_scan()`)를 직접 호출해 아래를 모두 만족한다. [제안 후 승인]

1. 신규 3종 각각에 `<원본이름.확장자>.md`가 1개씩 생성되고, 출력 트리가 기대 집합과 **정확히
   일치**한다.
   - 검증: 통합테스트에서 생성된 상대경로 집합을 기대 집합과 동등 비교.
2. 엑셀 추출 텍스트에 `[시트: <이름>]` 경계 줄이 시트마다 정확히 1회 나타나고, 행의 셀 값이 탭으로
   구분되며, **숨긴 시트·숨긴 행의 내용이 없다**.
   - 검증: 추출기 단위테스트에서 반환 문자열 단언.
3. 수식만 있고 캐시된 계산값이 없는 `.xlsx`는 `empty_document`로 스킵되고 위키가 생성되지 않으며
   종료 코드는 0이다.
   - 검증: 단위테스트(스킵 사유) + 통합테스트(산출물 부재·종료 코드).
4. PPTX 추출 텍스트에 `[슬라이드 N]` 경계 줄, 표 셀 텍스트, 그룹 도형 내부 텍스트, `[노트]` 뒤의
   발표자 노트가 모두 포함된다.
   - 검증: 네 요소를 모두 담은 픽스처를 생성해 추출기 단위테스트에서 단언.
5. 암호화된 `.xlsx`/`.pptx`는 `extraction_failed` + detail로 스킵되고, 같은 실행의 나머지 파일은
   정상 처리되며 종료 코드는 0이다.
   - 검증: 통합테스트에서 스킵 리포트와 나머지 산출물을 함께 단언.
6. `SkipReason`의 원소 집합이 v0.7과 동일하다(증설 없음).
   - 검증: enum 원소 집합 동등 단언.
7. `SUPPORTED_EXTENSIONS == {".docx", ".txt", ".md", ".pdf", ".xlsx", ".xlsm", ".pptx"}`.
   - 검증: `tests/test_scanner.py`의 기존 집합 동등 단언을 갱신.
8. `plan_scan()`에서 신규 3종이 기본점수 40과 §4.4의 `CHARS_PER_BYTE` 값을 받는다 — 미등록
   fallback(0점·0.5)이 **아니다**.
   - 검증: `tests/unit/test_plan.py`에서 신규 확장자의 점수·토큰 추정치 단언.
9. `max_chars`를 초과하는 `.xlsx`/`.pptx`에서 추출 결과 길이가 `max_chars` 이하다.
   - 검증: 상한을 넘는 픽스처로 반환 길이 단언.
10. **네트워크 불변식** — 신규 3종을 포함한 코퍼스의 `scan` 실행에서 소켓 목적지가 localhost뿐이다.
    - 검증: `tests/security/test_network_invariant.py`에 케이스를 **추가**한다. 새 파일로 분리하지
      않는다 — 소켓 패치 관용구가 복제되고, 감시장치가 공허하게 통과하지 않음을 증명하는
      `test_watcher_flags_a_gateway_bypass`의 보호를 받지 못한다(v0.6·v0.7 결정 계승).
11. `uv run ruff check .`와 `uv run pytest`가 exit 0이다.
    - 검증: 두 명령의 종료 코드.
12. 지원 포맷을 나열한 문서 전 지점이 동기화되고, §4.6의 stale 부채가 해소된다.
    - 검증: `.pdf`·신규 3종이 §4.6 목록의 모든 지점에 나타나는지 확인.

**검증 방식(전반)** [사용자 결정]: 추출기는 단위테스트, 파이프라인 통합은 `gateway.request_json`을
스텁한 채 코어 API를 직접 호출하는 통합테스트로 검증한다. **수동 스모크는 요구하지 않는다** —
두 추출기는 LLM·네트워크가 개입하지 않는 결정적 순수 함수이므로, v0.6이 정한 「스텁이 원리적으로
증명할 수 없는 것만 수동으로 확인한다」 기준에 해당하는 영역이 없다. ROADMAP §6 품질 게이트의
이번 회차 예외이며 근거를 여기에 남긴다.

**픽스처 구성** [제안 후 승인]: 테스트 코퍼스는 `tmp_path`에 `openpyxl`·`python-pptx`로 인라인
생성한다(`.pdf`가 이미 쓰는 방식). `tests/fixtures/sample_corpus/`는 **확장하지 않는다** — 세 테스트
파일이 공유하고 있고, 2026-08-22에 스모크 산출물이 그 폴더를 오염시켜 통합테스트 3건을 깨뜨린
사고가 있었다. 바이너리를 커밋하지 않으므로 「이 픽스처가 왜 이런 내용인가」가 테스트 코드에
드러난다.

## 4. 인터페이스 계약

### 4.1 지원 포맷 [사용자 결정]
- 정본은 `corpbrain/core/config.py`의 `SUPPORTED_EXTENSIONS` 하나이며, 다른 모든 목록은 파생이다.
- `.xlsx` · `.xlsm` · `.pptx` 세 값을 추가한다. `.xlsm`은 `openpyxl`이 공식 지원하므로 확장자 한 줄
  추가로 끝나고 실익이 크다.

### 4.2 추출기 [제안 후 승인]
기존 패턴을 그대로 따른다 — 시그니처 `(path: Path, max_chars: int) -> str`, 실패는
`ExtractionError`, 내용 없음은 빈 문자열. `extract_text()`의 확장자 디스패치에 분기를 더한다.

**엑셀 (`.xlsx`·`.xlsm`)**
- `openpyxl.load_workbook(read_only=True, data_only=True)`로 연다.
- 시트마다 `[시트: <시트명>]` 경계 줄을 먼저 낸다. 시트명 자체가 요약에 유용한 신호이며, 경계가
  없으면 서로 다른 표의 행이 이어 붙어 한 표로 읽힌다.
- 각 행은 셀 값을 **탭으로 이어 한 줄**로 만든다.
- **숨겨진 시트·행은 제외한다.**
- 수식 셀은 **캐시된 계산값**을 쓴다(`data_only=True`). 요약에 쓸모 있는 것은 `=SUM(B2:B10)`이
  아니라 그 결과값이다.

**PPTX**
- 슬라이드마다 `[슬라이드 N]` 경계 줄을 먼저 낸다.
- 도형은 **파일에 적힌 순서 그대로** 읽는다. 좌표 기반 시각 순서 재정렬을 하지 않는다 — 같은 높이의
  도형에서 순서가 흔들려 tie-break를 또 정해야 하고, 결정성이 약해진다.
- 표(`GraphicFrame`) 셀 텍스트와 그룹 도형 내부 텍스트를 **재귀로** 훑는다. 표는 `text_frame`이
  없어 별도로 훑지 않으면 통째로 누락된다.
- 발표자 노트를 `[노트]` 줄 뒤에 덧붙인다. 슬라이드 본문이 키워드 나열뿐이고 실제 내용이 노트에
  있는 경우가 흔하다.

**공통** [제안 후 승인]
- 파일을 통째로 메모리에 올리지 않는다. 누적 문자수가 `max_chars`에 닿으면 즉시 중단한다 —
  `.pdf` 추출기가 페이지 루프에서 하는 것과 같은 방식이다.
- 호출자 `prepare_summary_input()`의 방어적 절단(`text[:max_chars]`)은 그대로 유지된다.

### 4.3 실패 매핑 [제안 후 승인]
**새 `SkipReason` 값을 만들지 않는다.** v0.2가 `.pdf`에서 세운 계약을 글자 그대로 계승한다.

| 상황 | 처리 |
|---|---|
| 손상·파싱 실패 | `ExtractionError` → `extraction_failed` + detail |
| 암호화 (zip이 아닌 OLE 컨테이너가 되어 열리지 않음) | `ExtractionError` → `extraction_failed` + detail `"암호화된 …"` |
| 내용 없음·공백뿐 (빈 통합문서, 이미지만 있는 슬라이드) | 예외가 아니라 **빈 문자열** → 호출자가 `empty_document`로 판정 |
| `--max-file-size` 초과 | 기존 전역 게이트대로 `file_too_large` |

`ExtractionError`를 올릴 때 원인 예외를 `from exc`로 보존한다 — `PermissionError`와
`extraction_failed`를 가르는 기존 판정이 `__cause__`에 의존한다.

### 4.4 pre-scan 상수 [사용자 결정]
`corpbrain/core/plan.py`의 두 dict에 신규 3종을 추가한다. 누락하면 fallback(0점·0.5)이 조용히
적용된다.

```python
BASE_EXT_SCORE  = {..., ".xlsx": 40, ".xlsm": 40, ".pptx": 40}
CHARS_PER_BYTE  = {..., ".xlsx": 0.06, ".xlsm": 0.06, ".pptx": 0.03}   # 잠정값 — §4.5
```

- 기본점수 40은 `.docx`/`.pdf`와 같은 「정식 산출물」 취급이다. 근거 없이 차등을 두지 않는다.
- `CHARS_PER_BYTE`를 방치해 fallback `0.5`가 적용되면 zip 압축 포맷의 토큰량을 10배 가까이
  과대추정해, `plan`의 소요시간 추정이 틀어지고 v0.3의 총 토큰 예산 게이트(기본 200,000)가
  엉뚱하게 발동할 수 있다.

### 4.5 `CHARS_PER_BYTE`는 잠정값이다 [사용자 결정]
위 세 값의 근거는 «OOXML zip 구조가 `.docx`와 닮았다»뿐이며 **실측이 아니다**(`.xlsx`/`.xlsm`은
`.docx`와 같은 0.06, `.pptx`는 이미지·레이아웃 XML이 바이트 대부분을 차지하므로 그 절반인 0.03).
실물 코퍼스가 없어 이번에는 측정하지 못했다.

- **잠정값임을 코드 주석에 명시한다.**
- 실물 `.xlsx`/`.pptx` 코퍼스로 `추출 문자수 ÷ 파일 바이트`를 재어 확정하는 것은 **후속 이슈**로
  남긴다 (issue #48).
- 이는 v0.7 스펙 §4.8이 정한 「잠정값인 채로 릴리스하지 않는다」와 어긋난다. 성격의 차이를 근거로
  이번 회차에 한해 허용한다 — α는 검색 **순위**를 바꾸는 계약이었고 이 값은 `plan`의 **추정
  표시값**이다. 다만 총 토큰 예산 게이트를 통해 간접 영향이 있으므로 완전히 무해하지는 않으며,
  fallback `0.5`를 두는 것보다 어느 쪽으로 보나 개선이다.

### 4.6 의존성과 문서 [사용자 결정]
- `openpyxl`·`python-pptx`를 **필수 런타임 의존성**으로 `pyproject.toml`에 추가한다(전이 의존성
  `et-xmlfile`·`Pillow`·`XlsxWriter` 포함, `lxml`은 이미 있다).
- `[project.optional-dependencies]` extras 분리와 지연 import 가드를 **도입하지 않는다.** 그러면
  「미설치 = 미지원 확장자인가, 추출 실패인가」라는 판정이 하나 늘고, 같은 폴더가 설치 상태에 따라
  다른 개수의 위키를 내게 된다 — v0.6이 엔진별로 위키 개수가 갈리는 것을 막으려 한 것과 같은
  종류의 문제다. 기존 `python-docx`·`pypdf`가 모듈 최상단에서 무조건 import되는 관행을 그대로
  따른다.
- **문서 동기화 지점**: `docs/USAGE.md`(버전 매트릭스 행, §8 지원 포맷과 스킵 규칙, 「지원 4종」
  하드코딩, §15 "범위 밖: xls/ppt 추출" 항목), `docs/ROADMAP.md`(§2.1의 매핑 정정 + §3 v0.7 행
  이월 표기), `corpbrain/core/extract.py` 모듈 docstring.
- **stale 부채를 함께 해소한다** [사용자 결정]: `README.md`의 세 지점과
  `corpbrain/core/scanner.py`의 docstring 두 지점은 v0.2 이후 `.pdf`가 빠진 채로 남아 있다. 지원
  포맷 목록이 이번 슬라이스의 주제 그 자체이므로, 같은 문장을 고치러 들어가 틀린 것을 알고도 두고
  나오지 않는다.

### 4.7 릴리스 [사용자 결정]
- 이 슬라이스는 **`v0.8.0`** 으로 낸다. 신규 기능·신규 의존성·지원 포맷 확대라는 실질을 번호가
  반영하게 한다.
- `docs/ROADMAP.md` §3의 v0.7 행은 "검색 두 항목만 완료, 포맷 확장은 v0.8로 이월"로 정정한다.
- v0.8 자리를 이 슬라이스가 쓰므로, §7이 v0.8 후보로 남겨 둔 GUI·`RELATES_TO`는 그다음 버전
  후보가 된다.

## 5. 엣지 케이스와 실패 시나리오
- **Excel이 저장하지 않은 `.xlsx`** (LibreOffice·스크립트 생성): `data_only=True`가 읽는 계산값
  캐시가 없어 수식 셀이 비어 읽힌다. **이 한계를 수용한다** — 값이 비면 수식 문자열로 대체하려고
  파일을 두 번 열지 않는다. 시트가 수식뿐이면 추출 결과가 빈 문자열이 되어 `empty_document`로
  스킵되며, 이는 v0.2가 스캔 이미지 PDF를 같은 사유로 흘려보낸 것과 같은 처리다. [제안 후 승인]
- **암호화된 통합문서·프레젠테이션**: zip이 아니라 OLE 컨테이너로 저장되어 열리지 않는다.
  `extraction_failed` + detail로 스킵하고 나머지 파일 처리를 계속한다(종료 코드 0). [제안 후 승인]
- **이미지만 있는 슬라이드 / 빈 통합문서**: 예외가 아니라 빈 문자열 → `empty_document`.
  [제안 후 승인]
- **텍스트량 대비 파일이 큰 경우**: 엑셀·PPT는 같은 글자 수에도 파일이 크지만 확장자별 임계치를
  두지 않는다. 전역 20MB를 넘으면 기존대로 `file_too_large` 스킵이며 `--max-file-size`로만
  조정한다. [제안 후 승인]
- **`max_chars` 이후의 시트·슬라이드**: 앞부분만 읽으므로 뒤쪽 시트·슬라이드는 요약 입력에 들어오지
  않는다. `.pdf`가 뒤쪽 페이지에 대해 갖는 것과 같은 알려진 한계로 수용한다. [제안 후 승인]
- **비목표 확장자를 만난 경우**(`.xls`·`.ppt`·`.pptm` 등): 스캐너가 기존대로
  `unsupported_extension`으로 스킵한다. 새 안내 문구를 만들지 않는다. [제안 후 승인]
- 기존 스펙들의 실패 방침(빈 문서·추출 실패·권한 거부·긴 경로 스킵, 상한 초과 중단, 선행 조건 실패
  시 비-0 종료, 개별 파일 실패를 전체 실패로 위장하지 않음)은 그대로 유지된다.

## 미결정 사항
없음. `CHARS_PER_BYTE` 세 값은 §4.5가 잠정값으로 확정하고 실측을 후속 이슈로 분리했다.
