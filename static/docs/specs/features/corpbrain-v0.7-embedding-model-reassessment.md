# 스펙: CorpBrain v0.7 — 임베딩 모델 재판단 (issue #42)

- 상태: 확정
- 최종 갱신: 2026-08-25

## 1. 목표
지식그래프의 `SEMANTICALLY_SIMILAR` 엣지가 의존하는 기본 임베딩 모델(`nomic-embed-text`)이
한국어 코퍼스에서 유사도 순서 자체를 틀리는 문제(issue #42 실측: 관련 문서를 1순위로 꼽은
비율 1/4, `bge-m3`는 4/4)를 더 큰 한국어 코퍼스로 재검증하고, 실측 근거를 바탕으로 기본
임베딩 모델과 유사도 임계치 기본값을 재확정한다. `TAGGED_WITH`·`CONTAINS_ENTITY`·
`REFERENCES` 등 나머지 3종 엣지는 임베딩과 무관하게 정상 동작해 이번 범위에서 다루지
않는다. [사용자 결정]

## 2. 비목표
- 하이브리드 검색(코사인 유사도 + 그래프 가중치 결합) 구현 — 별도 issue #43. [사용자 결정]
- 임베딩 모델의 값 자체 드리프트 감지(동일 모델명이 재-pull 등으로 가중치만 바뀌는 경우) —
  현재 정책(모델 *이름* 문자열만 기록·비교)의 범위 밖이며 이번에 확장하지 않는다. [사용자 결정]
- 벡터 인덱스 자동 마이그레이션 — v0.4·v0.6이 정한 "자동 마이그레이션하지 않고 에러 +
  `--force` 재생성 안내" 방침을 그대로 유지하며 새 코드를 추가하지 않는다. [사용자 결정]
- 재사용 가능한 모델 비교 CLI 서브커맨드/스크립트 구축 — 이번엔 기존 스모크 절차와 동일한
  방식의 일회성 수동 측정으로 끝낸다. [사용자 결정]
- 구현 세션이 직접 5종 모델을 pull·측정하지 않는다 — 측정은 사용자가 로컬 환경에서 수행한다
  (§4.4). [사용자 결정 · grill-it T1]

## 3. 완료의 정의
1. `docs/smoke/corpus/`가 기존 구조(하위 폴더별 분류, 의도된 참조 쌍·고립 문서 설계)를
   유지한 채 **정확히 24개 문서·6개 하위폴더·주제 클러스터 4개(클러스터당 최소 2개 상호참조
   문서)·고립 문서 2개**로 확장된다(기존 6문서 구조를 4배로 스케일). 확장 문서는 구현 세션이
   기존 6문서와 동일한 합성 설계 원칙으로 작성한다(실제 업무 문서를 쓰지 않는다).
   [사용자 결정 · grill-it T2·T5]
   - 검증: 코퍼스 문서 수가 정확히 24개, 하위폴더가 6개, 고립 문서가 2개인지 세어 확인하고,
     4개 클러스터 각각 최소 1쌍 이상의 의도된 참조/유사 관계가 `docs/smoke/README.md`(기존
     6문서 설계 기록에 이어서 확장분도 같은 파일에 기록)에 명시되어 있는지 확인한다.
     [사용자 결정 · grill-it T3]
2. 후보 5종 모델(`nomic-embed-text`, `bge-m3`, `qwen3-embedding`(4b), `bona/bge-m3-korean`,
   `hf.co/mykor/KURE-v1-gguf`)에 대해 확장된 코퍼스의 전체 쌍별 코사인 유사도 행렬과 모델별
   "관련 문서를 1순위로 꼽은 비율(top-1 적중률)"이 `docs/SMOKE.md`의 새 "실행 I" 섹션에
   기록된다. 실측 자체는 §4.4의 결정적 측정 스크립트를 **사용자가 로컬 환경에서 실행**해
   산출하고, 그 결과(원시 출력)를 구현 세션에 전달한다 — 구현 세션은 모델을 직접 pull하거나
   측정을 실행하지 않는다. [사용자 결정 · grill-it T1]
   - 검증: `docs/SMOKE.md`에서 "실행 I" 섹션을 찾아 5개 모델명 전부와 모델별 top-1 적중률
     수치가 존재하는지 확인하고, 그 수치가 사용자가 전달한 스크립트 원시 출력과 일치하는지
     대조한다.
3. §4의 채택 규칙에 따라 채택 모델과 새 유사도 임계치 기본값이 결정되어
   `corpbrain/core/config.py`의 `DEFAULT_EMBED_MODEL`·`DEFAULT_SIMILARITY_THRESHOLD`
   상수에 반영되고, 그 근거(실측 수치·채택 규칙 적용 결과)가 `docs/SMOKE.md` 실행 I 및 본
   스펙(구현 후 갱신)에 기록된다.
   - 검증: `config.py`의 두 상수 값이 실행 I에 기록된 채택 모델·임계치와 일치하는지 코드
     리뷰로 확인한다.
4. 새 임계치·모델을 전제로 한 관련 단위 테스트(`tests/unit/test_related_ranking.py` 등
   `DEFAULT_SIMILARITY_THRESHOLD`·`DEFAULT_EMBED_MODEL`을 참조하거나 하드코딩된 구 값을
   가정하는 테스트)가 갱신되어 통과한다.
   - 검증: `uv run pytest tests/unit/test_related_ranking.py tests/unit/test_vectorstore.py
     tests/unit/test_graph_builder.py`가 green.
5. 기존 인덱스를 가진 사용자가 새 기본 모델로 넘어올 때의 안내가 `docs/USAGE.md` §13.5(기존
   임베딩 모델 한계·우회법 섹션)에 명시된다 — 기존 `PreconditionError` 메커니즘이 이미 모델
   불일치를 감지해 "인덱스를 지우고 `--force`로 재생성"을 안내하므로 코드 변경은 없지만, 어떤
   기본값이 바뀌었는지 사용자에게 사전 고지하는 문구가 추가된다. 별도 릴리스 노트 문구는 두지
   않는다(릴리스 노트는 PR 목록 기반 자동 생성 관행을 유지). [사용자 결정 · grill-it T4]
   - 검증: `docs/USAGE.md` §13.5에서 기본 임베딩 모델 변경 안내 문구를 확인한다.

## 4. 인터페이스 계약

### 4.1 채택 규칙 (결정 함수) [사용자 결정]
5종 모델을 확장된 코퍼스로 각각 인덱싱해 전체 쌍별 코사인 유사도를 측정한 뒤:
- **1순위**: 모델별 "관련 문서를 1순위로 꼽은 비율(top-1 적중률)"이 가장 높은 모델을 채택한다.
- **동점 타이브레이크**: 다운로드 용량이 작은 쪽 → 그래도 동점이면 출처 신뢰도(Ollama 공식
  라이브러리 > 커뮤니티/개인 네임스페이스)가 높은 쪽을 채택한다.
- **전원 실패(간극 없음)**: 5종 모두 "의도된 관련 쌍의 최저 점수 > 무관 쌍의 최고 점수"인
  깨끗한 간극을 보이지 않으면, 그래도 top-1 적중률이 가장 높은 모델을 채택하고(현재
  `nomic-embed-text`의 1/4보다 개선되는 한), 간극이 없다는 한계를 스펙·`docs/SMOKE.md`에
  명시한다.

### 4.2 임계치 산출 (결정 함수) [사용자 결정]
채택된 모델의 실측 분포에서 **"의도된 관련 쌍들의 최저 유사도 점수"와 "무관 쌍들의 최고 유사도
점수" 사이의 중간값**을 새 `DEFAULT_SIMILARITY_THRESHOLD`로 삼는다. 간극이 없는 경우(§4.1
전원 실패 케이스)에는 전체 분포의 중앙값 등 합리적 대체 기준을 적용하고 그 근거를 문서화한다.

### 4.3 변경되는 상수 [제안 후 승인]
- `corpbrain/core/config.py`: `DEFAULT_EMBED_MODEL`, `DEFAULT_SIMILARITY_THRESHOLD` 값을
  §4.1·§4.2의 결과로 갱신한다. 정확한 값은 실측 후 확정되며 이 스펙은 산출 규칙만 고정한다.
- CLI 플래그(`--embed-model`, `--similarity-threshold`, `--related-top-k`)는 기존 그대로
  유지한다 — 시그니처 변경 없음.
- 벡터 인덱스 모델 불일치 감지(`pipeline.py`의 `_open_index()`, `search.py`의
  `search_index()`가 저장된 `model_name`과 대조해 `PreconditionError`를 내는 기존 메커니즘)는
  변경하지 않는다 — 기본값이 바뀌어도 이 메커니즘이 그대로 마이그레이션 안내를 담당한다.

### 4.4 측정 스크립트 계약 (사용자 로컬 실행) [사용자 결정 · grill-it T1]
구현 세션은 실측을 직접 수행하지 않고, 사용자가 로컬에서 실행할 결정적 측정 스크립트를
`docs/smoke/`(예: `docs/smoke/embedding_reassessment.py` 또는 동등한 절차 문서)에 작성해
제공한다. 스크립트는:
- 입력: 확장된 코퍼스 경로(`docs/smoke/corpus/`), 후보 모델 목록(5종 하드코딩 또는 인자),
  로컬 Ollama URL.
- 동작: 각 모델을 대상으로 코퍼스 전체 쌍의 코사인 유사도를 계산하고, 문서별로 "의도된 관련
  문서가 1순위로 나왔는지"를 판정한다. 모델 pull은 스크립트가 자동으로 시도하지 않는다 —
  사용자가 `ollama pull <model>`을 사전에 실행해 둔다(README/절차 문서에 명시).
- 출력: 모델별 top-1 적중률과 전체 쌍별 코사인 값 원시 데이터(재현·대조 가능한 형식 — 예:
  CSV 또는 JSON, 사람이 읽을 수 있는 표 요약 포함).
- 사용자는 스크립트 실행 결과(원시 출력 전체)를 구현 세션에 그대로 전달한다. 구현 세션은 그
  결과를 `docs/SMOKE.md` 실행 I에 옮겨 적고 §4.1·§4.2 규칙을 적용해 상수를 확정한다.

## 5. 엣지 케이스와 실패 시나리오
- **5종 모두 깨끗한 간극을 못 보임**: §4.1 "전원 실패" 규칙에 따라 그래도 상대적으로 가장 나은
  모델을 채택하고 한계를 명시한다(기본값 교체를 보류하지 않는다). [사용자 결정]
- **모델 pull 실패(디스크·네트워크 등 로컬 환경 문제)**: 해당 모델은 측정 대상에서 제외하고
  `docs/SMOKE.md`에 제외 사유를 기록한다. 나머지 모델로 채택 규칙을 계속 적용한다.
- **기존 인덱스를 가진 사용자의 다음 `scan` 실행**: 새 기본 모델이 저장된 `model_name`과
  달라 기존 `PreconditionError` 메커니즘이 발동해 exit 1로 멈추고 "인덱스를 지우고 `--force`로
  재생성" 안내를 낸다 — 새 코드 없이 기존 동작 그대로.
- **코퍼스 확장 중 참조 쌍 설계 실수**(예: 의도한 관련 쌍이 실제로는 무관하거나 그 반대) —
  기존 6문서 스모크에서 실제로 있었던 실수 유형(§ SMOKE.md 실행 1 기록)이므로, 확장 문서 작성
  후 설계 의도(관련/고립 여부)를 사람이 한 번 더 확인한다.
