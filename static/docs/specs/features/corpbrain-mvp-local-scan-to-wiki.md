# 스펙: CorpBrain MVP 첫 슬라이스 — 로컬 스캔→요약→마크다운 위키 (코어/CLI)

- 상태: 확정
- 최종 갱신: 2026-08-12

## 1. 목표
흩어진 로컬 문서를 100% 로컬 환경에서 자동 구조화된 마크다운 위키로 변환하는
CorpBrain의 핵심 파이프라인을, UI 없이 코어/CLI 형태로 먼저 구현·검증한다.
지정한 폴더를 재귀 스캔하여 지원 포맷 문서를 텍스트 추출하고, 로컬 Ollama LLM으로
요약·구조화한 뒤, 문서 1개당 위키 마크다운 1개를 생성한다. 외부로 나가는 통신은
로컬 Ollama 호출 외 전무하다. [사용자 결정]

## 2. 비목표
이번 슬라이스에서 다음은 하지 않는다. [사용자 결정·파생]
- 클라우드 LLM(Option A) 경로 및 PII 마스킹 인프라(NetworkGuard, 정규식 7종, 동의 게이트)
- UI(pywebview·React) — 코어/CLI만 구현
- `.pdf`, `.doc` 등 까다로운 포맷 파싱
- 폴더 융합 심층 위키, 벡터DB·임베딩
- 실시간 감지 Watcher, 일괄 Rename/Undo, `os.startfile` 딥링크 브릿지
- Ollama 설치·프로비저닝 (탐지만 한다)
- PRD v1.1의 결정 사항은 참고 자료일 뿐이며, 이 스펙의 확정 근거로 삼지 않는다. [사용자 결정]

## 3. 완료의 정의
픽스처 폴더(정상 `.docx/.txt/.md`, 하위폴더, 빈 파일, 미지원 확장자, 12,000자 초과
파일 포함)에 대해 `corpbrain scan <fixture> --out <tmp>` 실행 시 아래를 모두 만족한다.

1. 지원 파일마다 입력 하위구조를 미러링한 `<원본이름.확장자>.md`가 `<out>`에 생성된다
   (§4.4의 파일명 규칙 — 예: `report.docx` → `report.docx.md`).
   - 검증: 통합테스트에서 출력 트리와 기대 트리를 비교.
2. 생성된 각 `.md`가 필수 섹션을 전부 포함한다 — front-matter 키(`source_path`,
   `generated_at`, `model`, `source_bytes`) + `제목`/`한 줄 요약`/`핵심 포인트`/`요약`/
   `태그·키워드`/`원문` 링크.
   - 검증: 생성물 파싱으로 front-matter 키·섹션 헤더 존재 확인.
3. 미지원·빈·추출 실패·권한 거부·긴 경로(>260자) 파일은 산출물이 아니라 종료 요약의
   스킵 리포트에 사유와 함께 나타난다.
   - 검증: 스킵 리포트(문자열/구조)에 각 사유가 있고 해당 `.md`가 없음을 확인.
4. 스캔 대상이 상한(기본 50)을 초과하면 처리를 중단하고 사용자에게 알린다.
   - 검증: 51개 이상 픽스처로 중단+알림 동작 확인.
5. 종료 코드: 개별 파일의 부분 실패는 0(스킵 목록 보고), Ollama 미탐지·입력 폴더 없음
   등 선행 조건 실패는 비-0.
   - 검증: mock으로 Ollama 미탐지 상황을 만들어 비-0 종료 확인.
6. 실행 중 `--ollama-url`(기본 localhost) 외 네트워크 연결이 발생하지 않는다.
   - 검증: 테스트에서 localhost 외 소켓 연결 없음을 확인.

검증 방식(전반): 추출기·템플릿 렌더러는 단위테스트, 파이프라인은 Ollama HTTP를
mock으로 스텁한 통합테스트로 검증하고, 마무리로 실제 모델 1회 수동 스모크 실행한다.
[제안 후 승인]

## 4. 인터페이스 계약

### 4.1 CLI [제안 후 승인]
```
corpbrain scan <folder>
  --out DIR           기본 ./corpbrain_wiki
  --model NAME        기본 qwen2.5:7b-instruct (환경변수 CORPBRAIN_MODEL로도 지정)
  --max N             기본 50 (스캔 대상 상한; 초과 시 중단+알림)
  --max-chars N       기본 12000 (문서당 요약 입력 상한)
  --ollama-url URL    기본 http://127.0.0.1:11434
  --force             mtime 무관 강제 재생성
```
- 진행 로그는 stderr. 종료 시 요약 출력: 처리 N건 / 스킵 M건(+사유) / 출력 경로.
- 런타임: Python **3.12**. `pyproject.toml`에 `requires-python = ">=3.12,<3.13"`으로 고정하고 `.python-version`에도 명시한다. [사용자 결정]

### 4.2 처리 규칙 [사용자 결정·제안 승인]
- 탐색: 폴더 인자를 재귀 순회.
- 지원 포맷: `.docx`, `.txt`, `.md` 3종. 그 외 확장자는 스킵+로그.
- 처리 단위: 입력 파일 1개 → 위키 마크다운 1개.
- 텍스트는 앞부분 `--max-chars`(기본 12,000)자까지만 읽어 요약 입력으로 사용(파일을
  통째로 메모리에 올리지 않는다).
- 재실행: 원문 mtime이 기존 위키보다 최신일 때만 재생성. 아니면 스킵. `--force`로 강제.

### 4.3 LLM 연동 [제안 후 승인]
- 백엔드: Ollama 로컬 HTTP(`--ollama-url`). 구동 중인 인스턴스를 탐지만 하며, 없으면
  설치를 시도하지 않고 비정상 종료한다.
- 모델은 고정 필드 JSON을 반환하도록 요청한다. 필드: `title`, `one_line_summary`,
  `key_points`(배열), `summary`, `tags`(배열).
- 코드가 이 JSON을 결정적으로 마크다운 템플릿에 렌더링한다(섹션 누락 불가).
- 출력 언어: 항상 한국어. [사용자 결정]

### 4.4 출력 마크다운 템플릿 [제안 후 승인]
```markdown
---
source_path: "<원문 절대경로>"
generated_at: "<ISO8601>"
model: "<사용 모델>"
source_bytes: <숫자>
---

# <제목>

## 한 줄 요약
<한 문장>

## 핵심 포인트
- <불릿 3~7개>

## 요약
<문단 요약>

## 태그·키워드
<태그 목록>

## 원문
[원본 파일 열기](file://<원문 절대경로>)
```
- 위치: `--out` 하위에 입력 폴더 구조를 미러링.
- 파일명: 원본 파일명 뒤에 **확장자를 유지한 채** `.md`를 덧붙인 `<원본이름.확장자>.md`.
  예: `report.docx` → `report.docx.md`, `a.txt` → `a.txt.md`, `a.md` → `a.md.md`.
  원본 확장자를 `.md`로 **대체하지 않는다** — 같은 폴더의 `a.txt`와 `a.md`가 동일한 출력
  경로로 충돌해 "입력 1개당 위키 1개"가 깨지는 것을 원천 차단하기 위함이다.
  [사용자 결정 · 2026-08-12 추가]

### 4.5 구조 제약 (후속 확장을 위한 이음새) [제안 후 승인]
후속 슬라이스(UI, 클라우드 엔진, 저장 계층 등)를 재설계 없이 증분으로 얹기 위해 다음 두
이음새를 이번 슬라이스에서 확보한다.

- **코어 라이브러리화:** 스캔·텍스트 추출·요약·마크다운 렌더의 비즈니스 로직은 CLI에서
  분리된 재사용 가능한 코어 모듈에 둔다. CLI는 이 코어를 호출하는 얇은 어댑터일 뿐이며,
  인자 파싱·로그 출력·종료 코드 매핑 외의 로직을 포함하지 않는다. 이로써 이후 UI(pywebview
  ·React)는 같은 코어를 호출하는 또 다른 어댑터로 붙는다.
  - 검증: 코어 모듈이 CLI 없이 함수 호출만으로 end-to-end 실행 가능하며, 통합테스트가
    CLI가 아닌 코어 API를 직접 호출해 통과한다.
- **단일 외부호출 관문:** 프로세스의 모든 외부 네트워크 호출(현재는 Ollama 로컬 호출뿐)은
  단일 함수/모듈을 통해서만 이루어진다. 코어의 다른 부분은 네트워크 라이브러리를 직접
  호출하지 않는다. 이로써 이후 클라우드 엔진과 `NetworkGuard`·PII 마스킹 게이트를 이 관문
  한 곳에 도입할 수 있다.
  - 검증: 완료의 정의 6번(‘localhost 외 연결 없음’) 테스트가 이 단일 관문을 스텁·감시하는
    형태로 성립한다.

## 5. 엣지 케이스와 실패 시나리오 [사용자 결정·제안 승인]
- 미지원 확장자: 스킵+로그.
- 빈 문서 / 텍스트 추출 실패 / 권한 거부 / 경로 길이 >260자: 중단 없이 스킵+로그.
- 12,000자 초과 문서: 앞부분 12,000자만 요약 입력으로 사용.
- LLM JSON 파싱 실패: 해당 파일만 실패로 스킵+로그, 나머지는 계속 처리.
- Ollama 미탐지/미구동: 선행 조건 실패로 비-0 종료(설치 시도 없음).
- 입력 폴더 없음/접근 불가: 비-0 종료.
- 스캔 대상 상한(50) 초과: 처리 중단+알림.
- 개별 파일 실패는 전체 실패로 위장하지 않는다(부분 성공 보고).
