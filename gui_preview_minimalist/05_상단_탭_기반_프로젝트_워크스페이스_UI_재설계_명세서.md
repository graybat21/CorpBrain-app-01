- **문서 번호**: 05

- **상태**: 확정 및 프로토타입 반영 완료
- **목적**: 회비서님의 제안에 따라 프로젝트 내부 5개 기능 메뉴를 상단 수평 탭(Top Tabs)으로 재배치하여, GitHub/Linear와 같은 표준적인 상하 계층 위상 관계를 확립하고 좌측 사이드바의 프로젝트 탐색성을 극대화함.

## 1. UI/UX 전문가 관점의 타당성 분석

회비서님의 **"5개 메뉴를 상단 탭으로 이동시키는 제안"**은 매우 탁월한 UX 개선 방향입니다. 다음과 같은 3대 핵심 이점이 있습니다:

1. **표준 멘탈 모델과의 일치 (GitHub / Linear / GitLab 패턴)**:
   - 개발자와 지식 관리자에게 가장 익숙한 구조는 **[좌측: 저장소/프로젝트 선택] → [상단: 해당 프로젝트의 탭 메뉴 (Code, Wiki, Graph, Issues)] → [중앙: 본문 작업]**입니다.
   - 인지 부하(Cognitive Load)가 현저히 감소합니다.

2. **완벽한 위상 관계(Hierarchy) 시각화**:
   - **좌측 사이드바**: "어떤 프로젝트(Workspace)에서 일할 것인가?"
   - **상단 수평 탭**: "그 프로젝트 안에서 무엇을 볼 것인가? (대시보드 / 플랜&스캔 / 지식그래프 / 위키 / 검색)"
   - 상하좌우의 역할이 명확히 분리됩니다.

3. **좌측 사이드바의 슬림화 및 탐색성 개선**:
   - 사이드바에서 메뉴들이 빠지고 **프로젝트/폴더 목록(Projects Explorer)**에만 온전히 집중할 수 있어, 10개 이상의 프로젝트가 생기더라도 한눈에 탐색하고 전환하기가 훨씬 수월해집니다.
